# 创建项目与首次启动

## 本节目录与路线

1. 创建一个 Maven + Java 17 项目。
2. 配置依赖、包名、端口和开发环境。
3. 手写统一响应、业务异常和健康接口。
4. 测试、打包并确认交付物。

前置：[01-真实开发流程手把手教学](01-真实开发流程手把手教学.md)。本节暂不添加 MyBatis/MySQL 依赖，避免数据源尚未配置就无法启动。

## 一、先看完成后的效果

请求：

```http
GET http://localhost:8081/health
```

响应 HTTP 200：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { "status": "UP" }
}
```

此时请求链路只有 `HTTP → HealthController → ApiResponse`。健康接口无需查询数据库，本节先验证 Web 应用本身。

## 二、创建项目

打开 [Spring Initializr](https://start.spring.io/)，填写：

| 选项 | 值 |
| --- | --- |
| Project | Maven |
| Language | Java |
| Spring Boot | 选择可用的 3.5.x 正式版；生成后按下面 POM 对齐到教程基线 |
| Group | `com.example` |
| Artifact / Name | `pulse-admin-server` |
| Package name | `com.example.admin` |
| Packaging | Jar |
| Java | 17 |
| Dependencies | Spring Web、Validation、Lombok |

点击 Generate，解压到 `E:\JAVA\projects\pulse-admin-server`，保证该目录下直接有 `pom.xml`，而不是再嵌套一层同名目录。

若生成器已不提供 3.5.x，使用它生成 Maven 目录和 Wrapper 后，**首次运行前替换为本节完整 POM**，并按本节代码创建启动类和测试类。生成器的默认版本不等于教程指定版本。

用 VS Code 的“打开文件夹”打开新项目。在 PowerShell 中执行：

```powershell
Set-Location 'E:\JAVA\projects\pulse-admin-server'
$env:JAVA_HOME
java -version
.\mvnw.cmd -version
```

预期 Maven 使用 Java 17。Wrapper 首次执行会下载 Maven，自带的 `.mvn`、`mvnw`、`mvnw.cmd` 应保留并进入版本管理。

## 三、基础文件

文中的文件路径都相对于新项目根目录。每个 Java 代码块包含完整 `package` 和 `import`。

### 2. 启动类

文件：`src/main/java/com/example/admin/AdminApplication.java`

```java
package com.example.admin;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class AdminApplication {
    public static void main(String[] args) {
        SpringApplication.run(AdminApplication.class, args);
    }
}
```

把生成器原来的启动类重命名为 `AdminApplication`，同步文件名，不保留两个启动类。所有业务包放在 `com.example.admin` 下，才能默认被组件扫描发现。

### 3. 配置文件

文件：`src/main/resources/application.yml`

```yaml
spring:
  application:
    name: pulse-admin-server
  profiles:
    default: dev
server:
  port: ${SERVER_PORT:8081}
```

文件：`src/main/resources/application-dev.yml`

```yaml
server:
  address: 127.0.0.1
```

本地开发先仅监听本机。没有指定 active profile 时使用 `dev`；以后设置 `SPRING_PROFILES_ACTIVE=prod` 就会选择生产配置。若生成器有 `application.properties`，将内容迁移后只保留一份主配置，避免两种格式互相覆盖。

### 4. 统一响应

文件：`src/main/java/com/example/admin/common/response/ApiResponse.java`

```java
package com.example.admin.common.response;

import lombok.AllArgsConstructor;
import lombok.Getter;

@Getter
@AllArgsConstructor
public class ApiResponse<T> {
    private final int code;
    private final String message;
    private final T data;

    public static <T> ApiResponse<T> success(T data) {
        return new ApiResponse<>(200, "操作成功", data);
    }

    public static ApiResponse<Void> success() {
        return new ApiResponse<>(200, "操作成功", null);
    }

    public static <T> ApiResponse<T> fail(int code, String message) {
        return new ApiResponse<>(code, message, null);
    }
}
```

删除接口先调用返回 `void` 的 Service，再调用无参 `success()`。不能把 `void` 当作一个数据值传给泛型方法。

文件：`src/main/java/com/example/admin/common/response/PageResponse.java`

```java
package com.example.admin.common.response;

import java.util.List;
import lombok.AllArgsConstructor;
import lombok.Getter;

@Getter
@AllArgsConstructor
public class PageResponse<T> {
    private final long total;
    private final int pageNum;
    private final int pageSize;
    private final List<T> records;
}
```

### 5. 业务异常

文件：`src/main/java/com/example/admin/common/exception/BusinessException.java`

```java
package com.example.admin.common.exception;

import lombok.Getter;
import org.springframework.http.HttpStatus;

@Getter
public class BusinessException extends RuntimeException {
    private final HttpStatus status;

    public BusinessException(HttpStatus status, String message) {
        super(message);
        this.status = status;
    }
}
```

它表示“参数格式正确，但业务不允许”，例如用户不存在或用户名已占用。继承 `RuntimeException` 后，事务中的业务异常默认触发回滚。

文件：`src/main/java/com/example/admin/framework/exception/GlobalExceptionHandler.java`

```java
package com.example.admin.framework.exception;

import com.example.admin.common.exception.BusinessException;
import com.example.admin.common.response.ApiResponse;
import lombok.extern.slf4j.Slf4j;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.http.converter.HttpMessageNotReadableException;
import org.springframework.validation.BindException;
import org.springframework.validation.FieldError;
import org.springframework.web.ErrorResponse;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.method.annotation.HandlerMethodValidationException;
import org.springframework.web.method.annotation.MethodArgumentTypeMismatchException;

@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<ApiResponse<Void>> handleBusiness(BusinessException e) {
        return ResponseEntity.status(e.getStatus())
                .body(ApiResponse.fail(e.getStatus().value(), e.getMessage()));
    }

    @ExceptionHandler(BindException.class)
    public ResponseEntity<ApiResponse<Void>> handleBinding(BindException e) {
        FieldError error = e.getFieldError();
        String message = error == null ? "请求参数不正确" : error.getDefaultMessage();
        return ResponseEntity.badRequest().body(ApiResponse.fail(400, message));
    }

    @ExceptionHandler({HttpMessageNotReadableException.class,
            MethodArgumentTypeMismatchException.class})
    public ResponseEntity<ApiResponse<Void>> handleInput(Exception e) {
        return ResponseEntity.badRequest()
                .body(ApiResponse.fail(400, "参数类型或 JSON 格式不正确"));
    }

    @ExceptionHandler(HandlerMethodValidationException.class)
    public ResponseEntity<ApiResponse<Void>> handleMethodValidation(
            HandlerMethodValidationException e) {
        int status = e.getStatusCode().value();
        return ResponseEntity.status(status).body(ApiResponse.fail(status,
                status == 400 ? "请求参数超出允许范围" : "服务器处理异常"));
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiResponse<Void>> handleUnexpected(Exception e) {
        if (e instanceof ErrorResponse error) {
            int status = error.getStatusCode().value();
            return ResponseEntity.status(status)
                    .body(ApiResponse.fail(status, "HTTP 请求处理失败"));
        }
        log.error("Unexpected server error", e);
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
                .body(ApiResponse.fail(500, "服务器处理异常"));
    }
}
```

`MethodArgumentNotValidException` 继承 `BindException`，因此请求体校验失败也会进入 `handleBinding`。查询 DTO 校验和参数类型错误同样需要处理。

**响应 JSON 的 code 不会自动修改 HTTP 状态。** 所以异常使用 `ResponseEntity` 明确返回 400、404 等。Spring 自带的 404/405 等错误保留原 HTTP 状态，不统一误报成 500。

### 6. 健康接口

文件：`src/main/java/com/example/admin/framework/web/HealthController.java`

```java
package com.example.admin.framework.web;

import com.example.admin.common.response.ApiResponse;
import java.util.Map;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HealthController {
    @GetMapping("/health")
    public ApiResponse<Map<String, String>> health() {
        return ApiResponse.success(Map.of("status", "UP"));
    }
}
```

`Map.of` 创建一个小型只读 Map，序列化后就是 JSON 对象。后续 `/health` 只表示 Web 进程可用，不能据此断言数据库、Redis 也健康。

## 四、启动与测试

在项目根目录执行：

```powershell
.\mvnw.cmd spring-boot:run
```

出现 `Started AdminApplication` 后，打开另一个终端测试：

```powershell
Invoke-RestMethod 'http://localhost:8081/health' | ConvertTo-Json -Depth 5
```

也可以在 Apifox 新建 GET 请求；打开 [Swagger UI](http://localhost:8081/swagger-ui/index.html) 应能找到 `/health`。此时没有自定义 `SwaggerConfig` 也可以工作，Bearer 配置在登录阶段添加。

### 一个有意义的自动化测试

将生成器默认的全量 `@SpringBootTest` 测试替换为下面的 Web 测试。以后添加数据源时，它也不依赖本机 MySQL。

文件：`src/test/java/com/example/admin/AdminApplicationTests.java`

```java
package com.example.admin;

import com.example.admin.framework.web.HealthController;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest;
import org.springframework.test.web.servlet.MockMvc;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

@WebMvcTest(HealthController.class)
class AdminApplicationTests {
    @Autowired
    private MockMvc mvc;

    @Test
    void healthReturnsUnifiedResponse() throws Exception {
        mvc.perform(get("/health"))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.code").value(200))
                .andExpect(jsonPath("$.data.status").value("UP"));
    }
}
```

执行：

```powershell
.\mvnw.cmd clean verify
```

预期 `BUILD SUCCESS`，生成 `target/pulse-admin-server.jar`。这个测试验证响应契约，不能替代后面的数据库或权限测试。

## 五、验收与定位

- [ ] Maven 使用 Java 17。
- [ ] 启动类和所有包名一致，项目只有一个启动入口。
- [ ] `/health` 为 HTTP 200，JSON 与本节示例一致。
- [ ] Swagger 可打开；`clean verify` 通过。
- [ ] 能解释请求如何到达 Controller，返回对象如何变成 JSON。

| 现象 | 优先检查 |
| --- | --- |
| 8081 被占用 | 停止自己启动的旧进程，或统一修改端口和请求地址 |
| 找不到启动类 | 文件名、包名、POM 是否一致 |
| 一启动就要数据库地址 | 是否提前加了数据源依赖；在下一篇完整配置后再运行 |
| getter 爆红但编译通过 | Java 扩展索引或 Lombok 注解处理状态 |
| 中文乱码 | 保存为 UTF-8，检查编辑器编码和 Maven 源码编码 |

## 六、知识沉淀与面试小题

1. **为什么先做健康接口？** 它把 JDK、依赖、组件扫描、端口、HTTP 和 JSON 的链路独立验证出来，后续错误更容易定位。
2. **为什么还没写业务就定义异常？** 后续模块都使用相同的返回契约，避免每个 Controller 重复 try/catch。
3. **为什么测试不用完整启动数据库？** Web 切片测试专门验证 HTTP 层；数据库 SQL 需要另做集成验证。
