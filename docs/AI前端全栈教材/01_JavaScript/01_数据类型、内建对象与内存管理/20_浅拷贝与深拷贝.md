## 二、知识讲解

<a id="k01"></a>

### 1. 浅拷贝

**口述总结：** 浅拷贝会创建一个新的外层对象或数组，复制其中的属性值或元素。原始值按值复制，嵌套对象复制的是引用值，所以外层独立，内层仍然共享。它适合只需要独立修改外层的场景，常用对象展开、Object.assign 和数组 slice 等方法。直接赋值没有创建新对象，不属于浅拷贝。

**快速记忆：新建外层，内层共享；改外层独立，改共享内层联动。**

#### 1.1. 是什么：创建新外层，只复制一层

以 `{ name: 'Alice', profile: { age: 18 } }` 为例，外层有两个属性：name 和 profile。浅拷贝复制这两个属性的值，不会再创建一个新的 profile 对象。

先分清直接赋值与浅拷贝。

**直接赋值：两个变量访问同一个对象。**

<!-- example: d17-assignment -->
```js
const source = { name: 'Alice', profile: { age: 18 } };
const copy = source;

copy.name = 'Bob';
console.log(copy === source); // true
console.log(source.name); // Bob
```

source 和 copy 只是两个名字，访问同一个对象。直接赋值不属于浅拷贝。

**浅拷贝：两个外层对象，仍共用同一个 profile。**

<!-- example: d17-shallow-sharing -->
```js
const source = { name: 'Alice', profile: { age: 18 } };
const copy = { ...source };

console.log(copy === source); // false
console.log(copy.profile === source.profile); // true
copy.name = 'Bob';
console.log(source.name, copy.name); // Alice Bob
copy.profile.age = 20;
console.log(source.profile.age, copy.profile.age); // 20 20
```

name 保存字符串；给 copy.name 换值，修改的是副本的外层属性。profile 保存对象引用；两边访问同一个内层对象，修改其中的 age，双方都能看到。

```text
source -> 外层对象 A --profile--+
                              +--> 内层对象 { age: 20 }
copy   -> 外层对象 B --profile--+
```

#### 1.2. 为什么：让外层修改独立，同时理解内层共享

**为什么需要浅拷贝？** 有时我们需要基于原数据生成一个新对象，修改它的外层字段，同时保留原数据。例如给副本修改 name 或新增 selected 字段；数组则可能需要独立地排序、增删元素。浅拷贝可以提供一个新的外层容器。

在上面的例子中，`copy.name = 'Bob'` 不影响 source.name，正是因为两个外层对象已经分开。

**为什么内层仍然共享？** 复制 profile 属性时，复制的是对象引用值，不是 profile 对象本身。浅拷贝不继续往里复制，因此两个 profile 仍然访问同一个对象。

这也解释了为什么要区分“修改嵌套对象”与“替换外层属性”：

如果执行的是 `copy.profile = { age: 30 }`，就只更换 copy 的 profile 属性，source.profile 不会被替换：

<!-- example: d17-nested-reassignment -->
```js
const source = { profile: { age: 18 } };
const copy = { ...source };
copy.profile = { age: 30 };

console.log(source.profile.age, copy.profile.age); // 18 30
console.log(copy.profile === source.profile); // false
```

**改 copy.profile.age，是修改内层对象；改 copy.profile，是给副本的外层属性换值。**

如果需求是“副本修改 profile.age，也不能影响原数据”，单独复制外层就不够，需要继续复制 profile。这就是下一节深拷贝要解决的问题。

<a id="k06"></a>

#### 1.3. 怎么做：常用 API 与一层循环

对象常用 `{ ...source }` 或 `Object.assign({}, source)`；普通数组常用 `slice()`、`concat()` 或 `[...source]`。这些写法都不会自动复制嵌套对象。

##### 方法一：对象展开

`{ ...source }` 创建新对象，把源对象的自有可枚举属性值放进去，包含字符串键和 Symbol 键。对象值仍访问原来的对象，不会自动递归。

<!-- example: d17-spread -->
```js
const source = { name: 'Alice', profile: { age: 18 } };
const copy = { ...source };

copy.profile.age = 20;
console.log(copy !== source); // true
console.log(source.profile.age); // 20
```

##### 方法二：Object.assign

`Object.assign(target, ...sources)` 把源属性写入 target，返回的也是 target。第一个参数不是“待复制的源”，而是写入目标。

<!-- example: d17-assign-target -->
```js
const source = { name: 'Alice', profile: { age: 18 } };
const copy = Object.assign({}, source);

console.log(copy === source); // false
console.log(copy.profile === source.profile); // true
const result = Object.assign(source, { name: 'Bob' });
console.log(result === source, source.name); // true Bob
```

需要新外层时写 `Object.assign({}, source)`。写 `Object.assign(source, extra)` 会直接修改 source。多个源从左到右写入，同名属性的后续值通常覆盖前面的值。

<a id="k07"></a>

##### 方法三：数组的 slice、concat 和展开

对普通数组，下面三种写法都创建新数组：

<!-- example: d17-array-sharing -->
```js
const source = [{ age: 18 }];
const sliced = source.slice();
const concatenated = source.concat();
const spread = [...source];

console.log(sliced !== source, concatenated !== source, spread !== source);
// true true true
sliced[0].age = 20;
console.log(source[0].age, concatenated[0].age, spread[0].age); // 20 20 20
```

数组外层独立，但第 0 项仍是同一个对象。这里只讨论普通数组；空位与自定义迭代行为见附录。

##### 手写思路：创建新容器，再复制一层属性值

下面只演示对象的自身可枚举字符串键，不递归。输入应是已确认的普通数据对象；数组使用前面的 API。副本用无原型对象作为数据容器，避免把特殊键当作原型赋值。

<!-- example: d17-shallow-manual -->
```js
function shallowCopy(source) {
  if (source === null || typeof source !== 'object' || Array.isArray(source)) {
    throw new TypeError('data object required');
  }
  const copy = Object.create(null);
  for (const key of Object.keys(source)) {
    copy[key] = source[key];
  }
  return copy;
}

const source = { name: 'Alice', profile: { age: 18 } };
const copy = shallowCopy(source);
console.log(copy !== source, copy.profile === source.profile); // true true
copy.profile.age = 20;
console.log(source.profile.age); // 20
```

它复制的是属性值，不是原型和属性描述符；不包含 Symbol 键或不可枚举键，读取属性也可能执行 getter。这个例子用于理解“一层循环”，不是 Object.assign 的完整替代。更多属性保留要求见附录。

### 2. 深拷贝

**口述总结：** 深拷贝在支持的数据范围内，不只创建新外层，还继续复制嵌套对象，让副本中的这些对象与原数据分开。它适合需要独立修改嵌套数据的场景，比如编辑表单草稿。常见方案有 structuredClone、JSON 序列化后重建和递归实现，但每种方案都有支持范围，不能默认完整复制任何 JavaScript 对象。

**快速记忆：不只复制外层，嵌套对象也复制；先看数据类型，再选实现方式。**

#### 2.1. 是什么：继续复制内层，形成独立的数据副本

仍然使用同一个例子。这次不仅外层不同，profile 也变成了两个对象：

<!-- example: d17-deep-basic -->
```js
const source = { name: 'Alice', profile: { age: 18 } };
const copy = structuredClone(source);

console.log(copy === source); // false
console.log(copy.profile === source.profile); // false
copy.profile.age = 20;
console.log(source.profile.age, copy.profile.age); // 18 20
```

这次 profile 也是两个对象，修改副本中的 age 不会影响源对象。深拷贝只在实现支持的数据范围内成立，不代表函数、类实例和所有资源都能完整复制。

```text
source -> 外层对象 A -> profile 对象 A：{ age: 18 }
copy   -> 外层对象 B -> profile 对象 B：{ age: 20 }
```

这里的“深”指继续处理嵌套数据，并不是简单多写一层展开。数据可以嵌套多层，具体实现需要按约定处理每一层。

#### 2.2. 为什么：隔离嵌套修改，避免污染原数据

**为什么需要深拷贝？** 例如把用户资料复制成表单草稿，编辑时会修改 profile.age。我们希望保存前原数据保持不变，取消编辑时直接丢弃草稿。

如果只用浅拷贝，草稿与原数据仍共享 profile，修改年龄就会提前影响原数据。需要把这个嵌套对象也复制出来，编辑才会独立。

**为什么深拷贝能够隔离这些修改？** 它为需要复制的嵌套对象建立新对象，并把属性值继续复制进去。上例中 copy.profile 和 source.profile 不再是同一个对象，修改 copy.profile.age 就只影响副本。

深拷贝解决的是数据共享问题；具体复制哪些字段、支持哪些类型，需要结合业务和实现约定。提交时的校验与冲突处理仍需单独设计。

#### 2.3. 怎么做：选择现成 API，理解递归原理

先看输入包含哪些数据，以及副本需要保留什么，再选方案。普通嵌套数据可以评估 structuredClone；明确符合 JSON 格式的数据可以使用 JSON 方案；面试手写则重点解释递归和对象映射。

##### 方法一：structuredClone，复制受支持的数据

structuredClone 是现代运行时提供的结构化克隆 API，支持普通对象、数组、Date、Map、Set、BigInt 等常见数据，也支持循环和共享关系。

<!-- example: d17-structured-types -->
```js
const source = {
  profile: { age: 18 },
  date: new Date('2026-01-01T00:00:00Z'),
  scores: new Map([['math', 90]])
};
const copy = structuredClone(source);
copy.profile.age = 20;

console.log(source.profile.age, copy.profile.age); // 18 20
console.log(copy.date instanceof Date); // true
console.log(copy.scores instanceof Map, copy.scores.get('math')); // true 90
```

不要把它理解成任意对象的复制器：函数、Symbol 值、WeakMap 等不受支持，自定义类的方法与原型也不能默认保留。目标运行时必须支持这个 API；进阶边界见附录。

##### 方法二：JSON 序列化后重建，适用于 JSON 数据

这个过程先把数据转为 JSON 文本，再解析为新值，对普通嵌套数据可以得到独立副本。

<!-- example: d17-json-basic -->
```js
const source = { name: 'Alice', profile: { age: 18 } };
const copy = JSON.parse(JSON.stringify(source));
copy.profile.age = 20;

console.log(source.profile.age, copy.profile.age); // 18 20
```

它的限制来自 JSON 协议，默认情况下：

- 对象属性中的 undefined、函数、Symbol 值被省略；数组中的这些值变成 null。
- 顶层这些值可能使 stringify 返回 undefined，再 parse 会失败。
- Date 通常变成字符串，RegExp、Map、Set 通常变成空对象。
- NaN、Infinity、-Infinity 变成 null；BigInt 和循环引用会报错。
- 原型、属性描述符和内部共享关系不会完整保留。

<!-- example: d17-json-limits -->
```js
console.log(JSON.stringify({ value: undefined, keep: 1 })); // {"keep":1}
console.log(JSON.stringify([undefined, () => {}, Symbol('id')])); // [null,null,null]
console.log(JSON.stringify([NaN, Infinity, -Infinity])); // [null,null,null]
try {
  JSON.stringify({ amount: 1n });
} catch (error) {
  console.log(error.name); // TypeError
}
```

所以 JSON 方案可以用于明确的 JSON 数据，不应作为任意对象的通用深拷贝。

<a id="k04"></a>

##### 方法三：手写递归，遇到嵌套对象就继续复制

浅拷贝只循环一层；深拷贝把同样的复制过程继续用于子对象。核心步骤是：

1. 原始值直接返回。
2. 如果当前对象已经复制过，返回之前记录的副本。
3. 为对象或数组创建新容器。
4. 先记录“源对象 → 副本”的对应关系。
5. 遍历属性，对每个属性值递归复制，再放入新容器。

第 5 步是“深”的来源：遇到嵌套对象时，又进入同样的复制过程。第 2、4 步则处理下面的循环和共享关系。

[完整递归示例](#deep-code)放在进阶附录，限定为普通数据对象、普通数组及原始值；不把特殊类型、原型和属性信息都混入基础复制过程。

<a id="k03"></a>

###### 为什么递归还需要 WeakMap？

循环引用会再次遇到自己；多个属性也可能访问同一个对象。映射保存“源对象 → 副本”，再次遇到时直接复用副本。

<!-- example: d17-graph-mapping -->
```js
const shared = { age: 18 };
const source = { left: shared, right: shared };
source.self = source;
const copy = structuredClone(source);

console.log(copy.self === copy); // true：循环指向副本
console.log(copy.left === copy.right); // true：副本内部仍共享一个节点
console.log(copy.left === shared); // false：与源节点分开
```

手写函数必须在递归前登记副本，否则处理 self 时仍会无限递归。WeakMap 只是映射工具；只记录“访问过”的 Set 无法告诉你对应副本是谁。

深拷贝不等于把副本内所有共享节点都拆开。深度过大的无环递归仍可能栈溢出，输入规模需另行约定。

<a id="k08"></a>

##### 方法四：项目已有 lodash 时使用 cloneDeep

项目已经使用 lodash，可以按现有导入方式调用：

```text
const copy = _.cloneDeep(source);
```

它覆盖许多常见类型，但函数闭包、特殊实例行为和属性元信息仍要按版本验证。不要为了简单纯数据默认新增依赖，也不要仅凭名字就认定它能完整复制任何对象。jQuery 的深合并放在附录比较。

<a id="k09"></a>

##### 怎样选择：按需要独立的范围复制

只需独立修改外层，选择浅拷贝；需要独立修改嵌套数据，选择符合输入范围的深拷贝。如果只修改一条已知路径，也可以对这条路径逐层浅拷贝，不必复制所有分支。

###### 表单草稿：取消编辑不能污染原数据

草稿涉及哪些字段，就为这些字段建立独立数据。纯数据可以使用 structuredClone；带方法、订阅或外部资源的完整运行时对象，优先提取要编辑的字段。

提交时还需确定覆盖或合并、版本冲突和校验规则。拷贝解决引用共享，不自动解决并发或权限。

###### 状态更新：复制变化路径

<!-- example: d17-path-copy -->
```js
const state = { profile: { age: 18 }, settings: { theme: 'light' } };
const next = { ...state, profile: { ...state.profile, age: 20 } };

console.log(next !== state, next.profile !== state.profile); // true true
console.log(next.settings === state.settings); // true
console.log(state.profile.age, next.profile.age); // 18 20
```

只新建外层和 profile，未变的 settings 继续共享。前提是共享分支遵守不可变更新约定，不能再直接修改 next.settings.theme。

完整深拷贝通常增加遍历、对象分配和源/副本同时存在的内存开销。先验证复制是否正确，再按真实数据规模测成本，不用小对象的一次结果下结论。

<a id="summary"></a>

## 三、知识小结

两节使用同一条主线：**是什么 → 为什么 → 怎么做。**

> 浅拷贝创建新外层、复制一层值，用于隔离外层修改；嵌套对象仍共享，常用展开、assign 和数组 API。深拷贝继续复制支持的嵌套对象，用于隔离嵌套修改；常用 structuredClone、JSON 方案或递归实现。选择时看修改范围和数据类型，不是拷贝越深越好。

第一轮先能解释直接赋值、浅拷贝和深拷贝的结果，再使用常用 API。手写时掌握“创建 → 登记 → 递归”；特殊属性与资源问题留到进阶追问。

## 四、进阶附录：按追问查阅

这些内容解释主线方法的边界，首次阅读可以跳过。

### A. 属性范围、getter 与 setter

展开和 assign 主要复制自身可枚举字符串键及 Symbol 键，不完整保留原型、不可枚举属性和描述符。读取源 getter 会执行代码；assign 向目标赋值可能触发 setter，展开通常建立自身数据属性。

<!-- example: d17-assign-spread-setter -->
```js
let writes = 0;
const prototype = { set count(value) { writes += value; } };
const source = { count: 2 };
const target = Object.create(prototype);
Object.assign(target, source);
const copy = { __proto__: prototype, ...source };

console.log(writes, Object.hasOwn(target, 'count')); // 2 false
console.log(Object.hasOwn(copy, 'count'), copy.count); // true 2
```

需要 Symbol、不可枚举键或描述符时，可以使用 Reflect.ownKeys 和 Object.defineProperty，并明确访问器策略。基础手写浅拷贝读取可枚举字符串键的属性值，可能执行 getter；深拷贝版本进一步限定为数据属性并拒绝访问器。两者都不承诺完整属性保留。

### B. 数组空位

对普通数组和标准行为，slice、concat 通常保留空位，展开通过迭代把空位读成实际 undefined 元素。

<!-- example: d17-array-holes -->
```js
const source = new Array(2);
console.log(Object.hasOwn(source.slice(), 0)); // false
console.log(Object.hasOwn(source.concat(), 0)); // false
console.log(Object.hasOwn([...source], 0)); // true
```

空位是没有自身索引属性，不等于属性值为 undefined。子类、继承索引、访问器或自定义迭代器可能改变行为，不能把普通示例推广到所有数组。

### C. 深拷贝的保留范围

structuredClone 不保证自定义原型、私有字段、描述符、Symbol 键或不可枚举属性保真；可枚举 getter 可能被读取。RegExp 的 lastIndex 通常重置；支持 SharedArrayBuffer 的环境中，克隆后底层内存仍共享。

JSON 对普通对象按可枚举自身字符串键序列化，数组则按索引读取，规则不同；getter 和 toJSON 也可能执行。循环默认报错，共享节点通常被重建为多份，不能据文本相同证明对象关系相同。

手写基础版本也有明确取舍：不保留原型与描述符，不支持特殊容器，不保证任意 Proxy 无副作用。增加一种支持类型前，先定义它要保留的状态和关系。

<a id="deep-code"></a>

#### 手写深拷贝：限定数据范围的完整示例

先明确这个基础版本的契约：只处理已确认的普通数据对象、普通数组及原始值，复制自身可枚举字符串键。对象副本统一用无原型容器；不保留描述符，不处理函数、Date、Map、Set、类实例或访问器。它不是任意对象的类型验证器。

<!-- example: d17-deep-manual -->
```js
function deepCloneData(value, seen = new WeakMap()) {
  if (typeof value === 'function') throw new TypeError('function unsupported');
  if (value === null || typeof value !== 'object') return value;
  if (seen.has(value)) return seen.get(value);

  const isArray = Array.isArray(value);
  const prototype = Object.getPrototypeOf(value);
  if (isArray ? prototype !== Array.prototype :
      prototype !== Object.prototype && prototype !== null) {
    throw new TypeError('plain data only');
  }
  const copy = isArray ? new Array(value.length) : Object.create(null);
  seen.set(value, copy);

  for (const key of Object.keys(value)) {
    const descriptor = Object.getOwnPropertyDescriptor(value, key);
    if (!descriptor || !Object.hasOwn(descriptor, 'value')) {
      throw new TypeError('data property required');
    }
    Object.defineProperty(copy, key, {
      value: deepCloneData(descriptor.value, seen),
      enumerable: true, writable: true, configurable: true
    });
  }
  return copy;
}

const source = { profile: { age: 18 }, list: [1, 2] };
const copy = deepCloneData(source);
copy.profile.age = 20;
console.log(source.profile.age, copy.profile.age); // 18 20
console.log(copy.list !== source.list); // true
```

核心步骤只有四个：

1. 原始值直接返回。
2. 对象或数组创建新容器。
3. 先记录源对象对应的副本。
4. 遍历属性，对子值递归，然后放入副本。

代码中的描述符查询用于拒绝普通访问器，不去执行 getter；defineProperty 把键写成自身数据属性，避免特殊键触发原型 setter。这里的属性配置是统一的新配置，不是保留源描述符。Proxy 仍可能拦截查询，原型筛选也不能识别所有伪装对象，调用方必须遵守输入契约。

### D. jQuery.extend：深合并不是通用深拷贝

```text
$.extend({}, source);       // 浅合并到新目标
$.extend(true, {}, source); // 按库规则递归合并
```

它修改并返回目标；多个源、数组索引、循环和特殊类型的语义需要按库版本确认。递归合并与复制单个对象图不是相同契约，旧项目还应核对实际版本和修复情况。

<a id="k05"></a>

### E. transfer：转移资源所有权

以 ArrayBuffer 为例，transfer 让接收方取得资源，源缓冲区被分离。这是所有权变化，不能当成两边都能继续使用的普通复制。

<!-- example: d17-transfer -->
```js
const buffer = new ArrayBuffer(4);
new Uint8Array(buffer).set([1, 2, 3, 4]);
const moved = structuredClone({ buffer }, { transfer: [buffer] });

console.log(buffer.byteLength, moved.buffer.byteLength); // 0 4
console.log(JSON.stringify([...new Uint8Array(moved.buffer)])); // [1,2,3,4]
```

Worker 通信中，按发送后源侧是否仍需要数据来决定复制或转移，同时定义失败、取消后的所有权。

## 五、面试题与答案

**主线题先练 D17-01、02、03、06、09；其余作为进阶追问。** 题号保留，方便从已有索引继续查阅。

<a id="d17-01"></a>

### D17-01 [P0·原理] 浅拷贝到底复制了什么？

**口述回答：** 创建新外层，复制属性或元素的值；嵌套对象仍可能共享。直接赋值没有新外层，不属于浅拷贝。

**追问：外层不同为什么仍影响源数据？** 两边的 profile 都指向同一个内层对象，改 profile.age 修改的是共享节点。

对应讲解：[浅拷贝：是什么与为什么](#k01)、[浅拷贝：怎么做](#k06)。

<a id="d17-02"></a>

### D17-02 [P0·原理] JSON为什么不是通用深拷贝？

**口述回答：** 它按 JSON 协议序列化后重建，会丢失或改变部分值，不保留原型、描述符和内部共享关系，循环与 BigInt 默认报错。

**追问：undefined 都会消失吗？** 对象属性通常省略，数组元素变 null，顶层可能返回 undefined，再 parse 会失败。

对应讲解：[深拷贝](#k02)。

<a id="d17-03"></a>

### D17-03 [P0·编码] 深拷贝为什么必须先登记副本再递归？

**口述回答：** 子路径可能再次遇到同一源对象。提前登记后返回已有副本，可以终止循环，并保留多条路径共用一个节点的关系。

**追问：Set 够不够？** 不够，还要知道对应副本是谁；WeakMap 或 Map 可以保存映射。它不能消除深层无环递归的栈限制。

对应讲解：[手写实现](#k04)、[循环与映射](#k03)。

<a id="d17-04"></a>

### D17-04 [P1·工程取舍] structuredClone能代替任何手写拷贝吗？

**口述回答：** 不能，要核对类型、原型和属性信息等保留要求。纯数据常适合，函数和完整类行为不能默认保留。

**追问：表单收到带方法的实例怎么办？** 提取编辑字段构建纯数据草稿，提交时通过领域方法处理；验证字段与行为，不只比较序列化文本。

对应讲解：[深拷贝](#k02)、[选择复制范围](#k09)、[保留范围](#advanced)。

<a id="d17-05"></a>

### D17-05 [P1·原理] transfer之后源数据为何不能再用？

**口述回答：** ArrayBuffer 转移后源侧被分离，目标取得资源。减少复制成本伴随源侧失效，不能按普通复制使用。

**追问：怎样选择？** 源侧还需要数据就复制或另留一份；接收方独占才评估转移，检查目标字节、源侧访问和失败路径。

对应讲解：[transfer](#k05)。

<a id="d17-06"></a>

### D17-06 [P0·原理] 修改浅拷贝的嵌套属性与给它重新赋值，为什么结果不同？

**口述回答：** copy.profile.age 修改共享内层；copy.profile = 新对象只更换副本的外层属性，源对象的 profile 没换。

**追问：copy 自己重新赋值呢？** let 变量只改变自己的绑定，const 变量不允许重赋；两者都不会替换 source。

对应讲解：[浅拷贝：是什么与为什么](#k01)。

<a id="d17-07"></a>

### D17-07 [P1·原理] Object.assign 与对象展开有哪些共同点和行为差异？

**口述回答：** 都主要复制自有可枚举属性值，内层仍共享。assign 修改并返回目标，展开建立新外层；两者不完整保留描述符和原型。

**追问：副作用一样吗？** 都可能读源 getter；assign 的目标赋值可能触发 setter，展开通常建立数据属性。验证目标身份、覆盖顺序和访问次数。

对应讲解：[浅拷贝：怎么做](#k06)、[属性行为附录](#advanced)。

<a id="d17-08"></a>

### D17-08 [P1·原理] 数组 slice、concat 与展开复制，对嵌套对象和空位有什么影响？

**口述回答：** 普通数组的新外层不等于新元素对象，内层仍共享。slice、concat 通常保留空位；展开通常将空位读成实际 undefined 元素。

**追问：怎么验证？** 用 Object.hasOwn 检查索引存在，用身份比较检查对象共享，并确认是否有自定义数组行为。

对应讲解：[数组浅拷贝](#k07)、[空位附录](#advanced)。

<a id="d17-09"></a>

### D17-09 [P1·工程取舍] 表单草稿或状态更新应该选择路径复制还是完整深拷贝？

**口述回答：** 根据修改范围选择。状态更新可复制变化路径，未变分支按不可变约定共享；纯数据草稿需要独立编辑时评估深拷贝或字段转换。

**追问：共享安全吗？** 要限制共享分支的直接修改。深拷贝也不解决并发冲突；还需提交、合并和版本规则。

**验证依据：** 编辑和取消不污染源，变化路径更新身份，共享分支符合约定，再测实际数据下的交互与分配。

对应讲解：[选择复制范围](#k09)。

<a id="d17-10"></a>

### D17-10 [P1·工程取舍] lodash.cloneDeep 或 jQuery.extend 能作为任意对象的通用拷贝吗？

**口述回答：** 不能。cloneDeep 按库版本和类型契约工作；extend 主要递归合并，修改目标，不保证任意对象图和行为完整保留。

**追问：已有工具怎么迁移？** 按实际输入分类，验证源是否变化、嵌套身份、循环、特殊值与失败策略，优先复用满足契约的工具。

对应讲解：[lodash](#k08)、[深合并附录](#advanced)。

<a id="d17-11"></a>

### D17-11 [P1·编码] 手写拷贝如何处理自身属性、Symbol、空位、循环和共享引用？

**口述回答：** 先声明范围。基础版本用 Object.keys 复制可枚举字符串数据属性，数组先建立长度，深拷贝先登记映射再递归。需要 Symbol、不可枚举键和描述符时，再使用 Reflect.ownKeys 与描述符 API。

**追问：本章基础实现保留全部属性吗？** 不保留，不能当任意对象克隆器。需要扩展时分别验证 getter、只读 length、继承字段、特殊键、循环与共享，不能只增加递归。

对应讲解：[手写完整示例](#deep-code)、[属性范围附录](#advanced)。

<a id="d17-12"></a>

### D17-12 [P1·工程取舍] 如何验证一个拷贝方案的行为、数据边界和性能成本？

**口述回答：** 先用同一组输入验证复制契约，再比较成本：源是否变化、预期节点是否独立、共享关系是否保留、特殊值如何处理，以及失败是否明确。

**追问：性能测什么？** 实际规模下的总耗时、对象分配、GC 和交互延迟。先排除“快但复制错”，再评估少复制字段、路径复制和降低重复频率。

**验证依据：** 同条件复测编辑、取消、提交和异常行为，不用单个小对象或 JSON 文本相同证明方案正确。

对应讲解：[选择复制范围](#k09)、[资源转移](#k05)。
