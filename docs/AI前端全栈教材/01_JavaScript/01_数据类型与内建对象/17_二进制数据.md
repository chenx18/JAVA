# 17 二进制数据

网络和文件提供字节，文本与数字需要约定编码才能解释这些字节。ArrayBuffer负责存储，视图负责解释，传输则涉及复制或所有权转移。

## 二、知识讲解

<a id="k01"></a>

### 1. ArrayBuffer 与 TypedArray

ArrayBuffer是一块字节存储，byteLength是字节数，不能直接按数值元素访问。TypedArray建立带元素类型的视图，包括Int8/Uint8/Uint8Clamped、Int16/Uint16、Int32/Uint32、Float32/Float64、BigInt64/BigUint64，以及需检查支持的Float16Array。

构造可接长度、元素源，或(buffer,byteOffset?,length?)共享已有存储。TypedArray.length按元素计，byteLength按字节计，BYTES_PER_ELEMENT表明元素宽度；buffer和byteOffset描述底层关联。

```js
const buffer = new ArrayBuffer(4);
const view = new Uint8Array(buffer);
view.set([1, 2, 3, 4]);
const shared = view.subarray(0, 2);
const copied = view.slice(0, 2);
shared[0] = 9;
console.log(view[0], copied[0]); // 9 1
```

subarray返回共享存储的视图，slice复制内容。set(source,offset=0)批量写入；copyWithin/fill等会修改视图对应数据。TypedArray不是普通Array，不能任意push改变长度，数值写入按元素类型转换。较新的可调整ArrayBuffer和长度追踪视图另需目标支持。

<a id="k02"></a>

### 2. DataView 与字节序

DataView用于在同一缓冲中按明确偏移和字节序读写混合字段。常用get/setInt8、Uint8、Int16、Uint16、Int32、Uint32、Float32、Float64、BigInt64、BigUint64，现代环境还可能有Float16方法。

多字节方法通常形如getUint16(byteOffset,littleEndian=false)、setUint16(byteOffset,value,littleEndian=false)。默认大端；TypedArray多字节解释则依宿主字节序，不能直接当通用网络协议解析。

```js
const buffer = new ArrayBuffer(2);
const view = new DataView(buffer);
view.setUint16(0, 0x1234, false);
console.log([...new Uint8Array(buffer)]); // [18,52]
console.log(view.getUint16(0, true)); // 13330，即0x3412
```

偏移按字节计，越界会抛错。协议解析先验证长度，再读字段；不是get出来一个数字就证明报文完整或可信。

<a id="k03"></a>

### 3. 文本、Blob 与文件

TextEncoder把字符串编码为UTF-8字节，encode返回Uint8Array，encodeInto可写入已有缓冲。TextDecoder按编码把字节变文本；流式解码用decode(chunk,{stream:true})保留半个字符的状态，结束时decode()刷新。

```js
const bytes = new TextEncoder().encode('中');
const decoder = new TextDecoder('utf-8', { fatal: true });
const first = decoder.decode(bytes.slice(0, 1), { stream: true });
const last = decoder.decode(bytes.slice(1), { stream: true }) + decoder.decode();
console.log(first, last); // '' '中'
```

Blob表示不可变文件样数据，支持size/type、slice、text、arrayBuffer、stream；File扩展了name、lastModified等文件信息。它们属于Web/宿主API，不等同ECMAScript内建。Object URL应在不再需要时revoke；String.length也不是文件字节数。

<a id="k04"></a>

### 4. 复制、transfer 与共享内存

postMessage常按结构化克隆传数据，可能有复制成本；transfer可转移ArrayBuffer所有权，使原缓冲失效；SharedArrayBuffer让参与方共享内存，需要同步协议。

共享不等于安全：并发读写要考虑Atomics的操作与允许的TypedArray，等待机制还有线程/宿主限制；浏览器共享内存通常需要满足跨源隔离等环境要求。普通业务先量通信成本，再决定是否需要共享内存，不能因为“零拷贝”名字就增加复杂度。

ArrayBuffer新近的resize/transfer/transferToFixedLength、resizable/maxByteLength等接口需按运行时查阅；它们改变存储和视图生命周期，不能与固定长度示例无条件互换。

<a id="summary"></a>

## 三、知识小结

二进制按“存储→视图→编码→协议→所有权”分层理解。字节数、元素数、字符数是不同维度；共享视图与复制、转移与共享内存也是不同操作。

参考：[MDN Typed arrays](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Typed_arrays)。较新 API 按目标运行时核对支持，示例各自独立。

## 四、面试题与答案

<a id="d17-01"></a>

### D17-01 [P1·基础] ArrayBuffer、TypedArray、DataView分别负责什么？

**回答：** ArrayBuffer提供字节存储；TypedArray用固定元素类型解释数据，适合同类数值序列；DataView按字节偏移和显式字节序读取混合字段，适合二进制协议。

对应讲解：[ArrayBuffer 与 TypedArray](#k01)。

<a id="d17-02"></a>

### D17-02 [P1·原理] subarray与slice有何区别？

**回答：** TypedArray的subarray创建共享同一缓冲的视图，修改能相互观察；slice复制指定范围形成独立数据。要同时看视图本身是否新建以及底层存储是否共享。

对应讲解：[ArrayBuffer 与 TypedArray](#k01)。

<a id="d17-03"></a>

### D17-03 [P1·原理] 为什么不能对每个网络chunk独立decode？

**回答：** 一个UTF-8字符可能跨块，独立解码会丢失前一块的半字符状态。复用TextDecoder并设置stream，结束再刷新；得到文本后仍要按业务协议分帧。

对应讲解：[文本、Blob 与文件](#k03)。

<a id="d17-04"></a>

### D17-04 [P1·工程取舍] Worker大数据传输何时用transfer？

**回答：** 资源可以交由另一方独占且复制成本明显时可转移；原侧失效是代价。若双方都需访问，应选择复制或有同步设计的共享内存，不能误用已分离缓冲。

对应讲解：[复制、transfer 与共享内存](#k04)。
