## 二、知识讲解

<a id="types"></a>

### 1. 八种语言类型与七种原始类型

JavaScript 是动态类型语言：**变量可以先保存一种类型的值，再保存另一种；类型是值的属性。**

<!-- example: dynamic-types -->
```js
let value = 10;
console.log(typeof value); // 'number'

value = '10';
console.log(typeof value); // 'string'
```

ECMAScript 的语言类型共有八种：

| 类型 | 常见值 | 分类 | typeof 结果 |
| --- | --- | --- | --- |
| Undefined | undefined | 原始类型 | 'undefined' |
| Null | null | 原始类型 | 'object'，历史特殊情况 |
| Boolean | true、false | 原始类型 | 'boolean' |
| Number | 1、1.5、NaN、Infinity | 原始类型 | 'number' |
| BigInt | 1n、9007199254740993n | 原始类型 | 'bigint' |
| String | 'hello'、'' | 原始类型 | 'string' |
| Symbol | Symbol('id') | 原始类型 | 'symbol' |
| Object | {}、[]、函数、Date、Map 等 | 对象类型 | 通常 'object'；函数为 'function' |

前三列描述语言分类，最后一列描述某个运算符的返回值，两者不能混为一谈。函数属于 Object，但 typeof 特别返回 'function'；null 有自己的 Null 类型，却返回 'object'。

Array、Function、Date、RegExp、Map、Set、Promise 都属于对象体系，不是在上述八种类型之外再各加一种语言类型。日常说的“引用类型”“复杂类型”通常是在讨论对象及其共享引用行为。

Number 和 BigInt 也要分开：Number 用双精度浮点数语义，BigInt 用于整数，不表示小数。Symbol() 每次创建独立的符号；Symbol.for() 则按注册键复用符号。具体计算与 API 分别在相应章节讲解。

### 2. undefined、null、Boolean 与空数据

undefined 常出现在“还没有提供值”的位置，null 常被接口或业务代码约定为“明确为空”。它们的业务含义最终由契约决定，语言不会自动规定哪个表示加载中。

<!-- example: empty-values -->
```js
let selected;
const user = {};
function noReturn() {}

console.log(selected === undefined); // true
console.log(user.nickname === undefined); // true
console.log(noReturn() === undefined); // true

const chosenUser = null;
console.log(chosenUser === null); // true
```

下面四种数据状态应当区分：

| 数据 | 可能的业务含义 | 注意 |
| --- | --- | --- |
| 对象没有 nickname 字段 | 没有提供这个字段 | 读取结果是 undefined |
| { nickname: undefined } | 字段存在，但值未指定 | 与“字段不存在”不是同一件事 |
| { nickname: null } | 明确清空昵称 | 是否允许取决于接口 |
| { items: [] } | 已得到列表，当前无记录 | 空数组仍然为真值 |

判断字段是否存在，用 `Object.hasOwn(object, key)`；判断值是否为 null，用严格比较。仅看属性读取结果，分不清“没有该属性”和“属性值为 undefined”。

<!-- example: property-presence -->
```js
const a = {};
const b = { nickname: undefined };

console.log(a.nickname === b.nickname); // true
console.log(Object.hasOwn(a, 'nickname')); // false
console.log(Object.hasOwn(b, 'nickname')); // true
console.log(Boolean([]), Boolean({})); // true true
```

Boolean 类型本身只有 true 和 false。if、! 等会把其他值转换为布尔判断，不能把“真值”当成“Boolean 类型”。

一般 ECMAScript 值中，假值包括：**false、0、-0、0n、NaN、空字符串、null、undefined**。其他普通值，包括 'false'、'0'、空数组和空对象，都是真值。浏览器的历史对象 document.all 是兼容性例外，普通业务不依赖它。

<a id="primitive"></a>

### 3. 原始值不可变与包装对象

“原始值不可变”说的是值本身不能被原地修改，**不是变量不能换成另一个值**。

<!-- example: primitive-immutability -->
```js
let name = 'alice';
const upper = name.toUpperCase();

console.log(name, upper); // alice ALICE
name = 'bob';
console.log(name); // bob
```

toUpperCase 创建结果，原来的字符串没有变。后来给 name 重新赋值，只是让变量保存另一个字符串。

字符串能调用方法，并不意味着字符串原始值就是对象。对适合的原始值访问属性时，语言提供相应的对象包装语义，从对应原型获得方法。这不等于程序应主动创建包装对象，也不要求引擎每次真的分配一个可观察的临时对象。

<!-- example: primitive-and-wrapper -->
```js
const text = 'hello';
const boxed = new String('hello');

console.log(typeof text, typeof boxed); // string object
console.log(text === boxed); // false
console.log(boxed.valueOf() === text); // true

const flag = new Boolean(false);
console.log(Boolean(flag)); // true
console.log(flag.valueOf()); // false
```

new Boolean(false) 产生的是对象，条件判断先看到对象，因此为真；内部包装的 false 不会改变这个结论。业务中的字符串、数字和布尔值通常使用字面量或 String()/Number()/Boolean() 转换函数。

String、Number、Boolean 可以用 new 创建包装对象；Symbol 和 BigInt 不能作为构造器 new，但 Object(symbol) 和 Object(bigint) 可以包装对应值。null 和 undefined 没有可供直接访问属性的对应包装对象。

<a id="reference"></a>

### 4. 对象引用、赋值与参数传递

对象具有身份。两个内容一样的对象也可以是不同对象；两个不同变量也可以指向同一个对象。

<!-- example: object-identity -->
```js
const first = { score: 1 };
const second = first;
const third = { score: 1 };

console.log(first === second); // true
console.log(first === third); // false

second.score = 2;
console.log(first.score); // 2
```

first 与 second 共享同一个对象；third 指向另一个对象。“内容相同”与“对象身份相同”是两个问题。

理解赋值时可以使用下面的引用示意图。它表达程序语义，不是引擎物理内存布局：

```text
first  ──┐
         ├──> 对象 A：{ score: 2 }
second ──┘

third ──────> 对象 B：{ score: 1 }
```

**函数参数按值传递。传对象时，传递的是对象引用值的副本。** 所以形参和外部变量最初能访问同一个对象，但重新给形参赋值，只会改变形参自己的绑定。

<!-- example: argument-value -->
```js
function update(user) {
  user.name = 'Bob';
  user = { name: 'Carol' };
  return user;
}

const original = { name: 'Alice' };
const returned = update(original);

console.log(original.name); // Bob
console.log(returned.name); // Carol
console.log(original === returned); // false
```

分三步推导：

1. 调用 update 时，形参 user 和 original 都访问对象 A。
2. user.name = 'Bob' 修改对象 A，所以 original 看到 Bob。
3. user = {...} 让局部形参改为访问新对象 B；original 仍访问对象 A。

如果是“形参代表调用方变量本身”的传引用语义，第三步应当能替换 original 的绑定，而这个例子表明它没有。因此“对象可以被函数修改”不足以证明参数按引用传递。

<a id="memory"></a>

### 5. 堆、栈与 const 的准确理解

学习时常用“栈保存局部状态，堆保存动态对象”帮助理解运行过程，但不能把它简化成规范承诺：**所有原始值必在栈中，所有引用必在栈中，对象永远按一种方式放在堆里。**

引擎可以把值放在寄存器、栈或堆中，进行字符串共享、逃逸分析与其他优化。ECMAScript 规定可观察行为，不规定每个变量的物理地址。闭包所需的环境也可能在函数调用结束后继续存活。

回答相关问题，优先讲可靠的语义：

- 原始值不可原地修改。
- 对象可被多个变量共享，通过引用修改同一个对象。
- 参数重新赋值不替换调用方的变量绑定。
- 对象能否回收与可达性有关，离开某个作用域不等于立刻回收。

const 约束的也是变量绑定，不是它指向的整个对象。

<!-- example: const-and-freeze -->
```js
'use strict';

const config = { nested: { enabled: true } };
config.nested.enabled = false;
console.log(config.nested.enabled); // false

Object.freeze(config);
config.nested.enabled = true;
console.log(config.nested.enabled); // true

try {
  config = {};
} catch (error) {
  console.log(error.name); // TypeError
}
```

这里 Object.freeze 只冻结 config 的自身属性，不能自动深度冻结 nested。const、浅冻结、深度不可变，是三个不同层次的问题。

<a id="typeof"></a>

### 6. typeof：判断基础类型

typeof 是运算符，返回字符串。语法可以写 `typeof value` 或 `typeof(value)`，后面的括号不表示它是普通函数。

<!-- example: typeof-values -->
```js
console.log(typeof undefined); // 'undefined'
console.log(typeof null); // 'object'
console.log(typeof NaN); // 'number'
console.log(typeof 1n); // 'bigint'
console.log(typeof Symbol('id')); // 'symbol'
console.log(typeof []); // 'object'
console.log(typeof function () {}); // 'function'
```

typeof 适合区分多数原始值，以及通常意义上的函数值，但不能细分数组、日期、正则等对象。

typeof null 的结果来自早期实现留下的历史行为；因兼容性保留至今。它不是把 null 重新划入对象类型，也不能据此推断现代所有引擎仍使用同一套历史编码。

typeof 对“完全未声明的名字”有特殊处理，但对暂时性死区中的绑定仍会报错：

<!-- example: typeof-tdz -->
```js
console.log(typeof definitelyMissingName); // 'undefined'

{
  try {
    console.log(typeof value);
  } catch (error) {
    console.log(error.name); // ReferenceError
  }
  let value = 1;
}
```

两个情况的区别是：前者没有该绑定，后者已有块级绑定但尚未初始化。不能背成“typeof 永远不报错”。

还有一个边界：`typeof SomeClass === 'function'`，不代表能直接 `SomeClass()`。class 必须用符合其规则的构造调用；typeof 不是“业务回调可以安全执行”的完整验证器。

<a id="instanceof"></a>

### 7. instanceof：判断原型关系

在通常的函数构造器、没有自定义协议的情况下，`value instanceof Constructor` 检查 **Constructor.prototype 是否出现在 value 的原型链中**。

<!-- example: instanceof-chain -->
```js
function User(name) {
  this.name = name;
}
const user = new User('Alice');

console.log(user instanceof User); // true
console.log(user instanceof Object); // true
console.log(Object.getPrototypeOf(user) === User.prototype); // true
```

查找的是下面这条链：

```text
user → User.prototype → Object.prototype → null
```

它判断的是原型关系，不是重新查看“这个对象最早由哪一行 new 创建”。改变原型关系，结果也可能改变。

<!-- example: array-prototype-imitation -->
```js
const imitation = Object.create(Array.prototype);

console.log(imitation instanceof Array); // true
console.log(Array.isArray(imitation)); // false
```

imitation 的原型链包含 Array.prototype，但它不是数组。反过来，在另一个 iframe 中创建的真实数组，其原型指向那个 iframe 的 Array.prototype，与当前窗口的 Array.prototype 不同，使用当前窗口的 `instanceof Array` 可能得到 false。

原始值通常不满足对应包装构造器的 instanceof：

<!-- example: instanceof-boxing -->
```js
console.log('hello' instanceof String); // false
console.log(new String('hello') instanceof String); // true
console.log(1 instanceof Number); // false
```

最后，instanceof 还可以通过右侧对象的 Symbol.hasInstance 自定义。下面刻意展示它不一定验证构造来源：

<!-- example: custom-has-instance -->
```js
class NonEmptyString {
  static [Symbol.hasInstance](value) {
    return typeof value === 'string' && value.length > 0;
  }
}
console.log('hello' instanceof NonEmptyString); // true
console.log('' instanceof NonEmptyString); // false
```

因此“instanceof 沿原型链查找”应限定为默认机制。右侧传入不合适的值还可能抛 TypeError，不能把它当成对任意输入都安全的通用类型函数。

<a id="constructor"></a>

### 8. constructor：普通属性的局限

许多对象通过原型继承 constructor 属性，因此下面的常见例子成立：

<!-- example: constructor-usual -->
```js
console.log([].constructor === Array); // true
console.log(new Date().constructor === Date); // true
```

但 constructor 只是可读取、可遮蔽、可能被改写的属性，不是不可伪造的类型标签。

<!-- example: constructor-limit -->
```js
const fake = { constructor: Array };
console.log(fake.constructor === Array); // true
console.log(Array.isArray(fake)); // false

const dict = Object.create(null);
console.log(dict.constructor); // undefined

console.log(null?.constructor); // undefined
```

最后一行的可选链只避免对 null 直接访问属性时报错，并没有提高 constructor 判断的可信度。跨 realm 的构造函数身份也不同。

老式继承代码中修复 Child.prototype.constructor，主要恢复一个便于阅读和反射的普通属性；它不会自动建立原型链，也不是 new 查找构造目标的开关。

<a id="tag"></a>

### 9. Object.prototype.toString.call：类型标签

直接调用某个值自己的 toString，可能得到的是该类型重写后的业务文本。例如数组的 toString 通常连接元素。

<!-- example: object-type-tag -->
```js
console.log([1, 2].toString()); // '1,2'
console.log(Object.prototype.toString.call([1, 2])); // '[object Array]'
console.log(Object.prototype.toString.call(null)); // '[object Null]'
console.log(Object.prototype.toString.call(undefined)); // '[object Undefined]'
console.log(Object.prototype.toString.call(new Date())); // '[object Date]'
```

这段写法可以拆开理解：

1. Object.prototype.toString 取得通用的标签方法。
2. call(value) 让这个方法以 value 作为接收者。
3. 方法按自身规则生成 `[object Type]` 形式的字符串。

它能细分很多内建对象，但**类型标签可受 Symbol.toStringTag 影响**。

<!-- example: spoofed-tag -->
```js
const fake = { [Symbol.toStringTag]: 'Array' };

console.log(Object.prototype.toString.call(fake)); // '[object Array]'
console.log(Array.isArray(fake)); // false
```

这个方法适合受控数据的分类、日志与调试，不应被宣传成“任何情况下都最准的类型判断”。它也不会验证对象字段结构，遇到 getter 或 Proxy 等对象时还可能触发额外行为。

<a id="choose"></a>

### 10. Array.isArray 与实际选型

Array.isArray 使用数组身份相关的内部机制，能区分“原型像数组”和“真正数组”，也能识别其他 realm 的数组。

常用选择如下：

| 实际目标 | 首选方式 | 仍需注意 |
| --- | --- | --- |
| 判断 null | value === null | 不用 typeof |
| 判断 undefined 值 | value === undefined | 标识符自身需已声明 |
| 判断字符串、布尔值、BigInt、Symbol | typeof | 包装对象不是原始值 |
| 判断数组 | Array.isArray(value) | 不校验元素内容 |
| 判断真正的 NaN | Number.isNaN(value) | 不先转换字符串 |
| 判断有限 Number | Number.isFinite(value) | 还需按业务限制范围或整数 |
| 判断自定义类实例关系 | instanceof | 原型、realm、自定义协议影响结果 |
| 调试内建对象标签 | Object.prototype.toString.call(value) | toStringTag 可改变结果 |
| 判断接口对象是否符合业务要求 | 字段结构与取值校验 | 不能只看 typeof 'object' |

“是数组”与“是用户数组”不同。“是数字”与“是合法页码”也不同：

<!-- example: business-validation -->
```js
function isPageNumber(value) {
  return Number.isSafeInteger(value) && value >= 1;
}

function isStringList(value) {
  return Array.isArray(value) &&
    Array.from(value).every(item => typeof item === 'string');
}

console.log(isPageNumber(2), isPageNumber(2.5)); // true false
console.log(isStringList(['a', 'b'])); // true
console.log(isStringList(['a', 1])); // false
console.log(isStringList(new Array(2))); // false
```

这里 Array.from 将稀疏数组的空位表现为 undefined，再逐项校验；直接 every 会跳过空位。外部 JSON 不表示数组空位，但函数接收普通 JavaScript 值时仍可能遇到。

数据已经在解析阶段丢失精度，也不能靠类型判断恢复。例如某些超大整数从 JSON number 转成 Number 后被舍入，再 String(id) 或 BigInt(id) 只是转换已经不准确的值。标识符应在接口契约中约定为字符串。

## 三、知识小结

把本章压缩成下面四组关系即可，不必记一串互不相关的结论：

| 主线 | 要能解释的关系 |
| --- | --- |
| 类型分类 | 七种原始类型 + Object；typeof 返回值不等于语言分类 |
| 数据行为 | 原始值不可变；对象可以共享；参数按值传递 |
| 判断依据 | typeof 看基础分类；instanceof 看默认原型关系；toString 看标签；Array.isArray 识别数组 |
| 业务校验 | 类型正确只是起点，还要检查结构、范围与协议 |

面试回答一个判断方法时，按 **判断依据 → 适用对象 → 一个反例 → 实际选择** 展开。例如解释 instanceof，要能同时说出原型查找和跨 realm 的边界。

## 四、面试题与答案

P0 表示优先掌握，P1 表示常见进阶，P2 表示按岗位深入；这是学习优先级，不代表某题保证必考。深度分为基础、原理、编码和工程取舍。

<a id="d01-01"></a>

### D01-01 [P0·基础] JavaScript 有哪些数据类型？数组和函数算独立类型吗？

**回答：** ECMAScript 定义八种语言类型，其中 Undefined、Null、Boolean、Number、BigInt、String、Symbol 是原始类型，另一种是 Object。数组和函数都属于对象体系，函数具有调用相关的特殊能力。typeof function 返回 'function' 是运算符的分类结果，不是在八种类型之外增加了第九种类型。

**追问：typeof null 为什么是 'object'？** 这是早期实现遗留并为兼容性保留的行为；null 仍然属于 Null 类型。判断 null 应使用严格比较。

对应讲解：[类型分类](#types)、[typeof](#typeof)。

<a id="d01-02"></a>

### D01-02 [P0·原理] 原始类型和对象类型最主要的区别是什么？

**回答：** 原始值不可原地修改，操作通常产生新值；对象具有身份，多个变量可以共享同一个对象，通过其中一个引用修改属性，其他引用能观察到变化。比较两个对象时，严格相等判断身份而非内容。不要把区别只背成“一个在栈、一个在堆”，物理存储与引擎实现和优化有关。

**追问：字符串可以调用方法，为什么还不是对象？** 因为属性访问有包装语义，能从对应原型取得方法；typeof 'abc' 仍是 'string'，与 new String('abc') 的对象值不同。

对应讲解：[原始值](#primitive)、[对象引用](#reference)。

<a id="d01-03"></a>

### D01-03 [P0·原理] JavaScript 参数是值传递还是引用传递？

**回答：** 参数按值传递。对象参数传递的是对象引用值的副本，因此形参和调用方最初可以修改同一个对象；但重新给形参赋值，只改变局部绑定，不会替换调用方变量。证明时要同时演示“修改属性”和“重新赋值”，只展示前者容易误判成按引用传递。

**读码：**

<!-- example: interview-parameter -->
```js
function change(data) {
  data.count++;
  data = { count: 100 };
}
const data = { count: 1 };
change(data);
console.log(data.count); // 2
```

**推导：** 自增发生在共享对象上，所以变成 2；新对象只赋给局部形参，没有替换外部 data。

对应讲解：[参数传递](#reference)。

<a id="d01-04"></a>

### D01-04 [P0·基础] null、undefined、字段不存在和空数组怎么区分？

**回答：** undefined 常见于未赋值、缺少参数、无显式返回和不存在的属性；null 常由业务主动表示空值。字段不存在与值为 undefined，读取结果可能相同，但 Object.hasOwn 能区分。空数组是一个真实数组对象，只是没有元素，在条件判断中仍为真。接口状态的含义由契约约定，不应把这些值都直接当作“加载失败”。

**追问：如何判断列表为空？** 先判断请求是否成功及数据是否符合数组契约，再看 length === 0；不能只用 if (!list)。

对应讲解：[空数据](#empty)。

<a id="d01-05"></a>

### D01-05 [P0·基础] const 对象为什么还能修改？Object.freeze 能彻底解决吗？

**回答：** const 禁止重新赋值变量绑定，不禁止修改对象属性。Object.freeze 限制对象自身属性的修改、增删等操作，但它是浅层的，不自动冻结嵌套对象。需要深度不可变时，还必须明确嵌套结构、共享引用和支持对象类型；不应把 const、浅冻结和深冻结当成一回事。

对应讲解：[const 与冻结](#memory)。

<a id="d01-06"></a>

### D01-06 [P0·基础] typeof 能判断什么，不能判断什么？

**回答：** typeof 返回类型分类字符串，适合判断字符串、数字、布尔值、undefined、BigInt、Symbol，以及通常的函数值。它不能细分数组、日期、Map 等对象，null 又会得到 'object'。因此判断 null 用 === null，判断数组用 Array.isArray；判断数字业务合法性还要结合 Number.isFinite、Number.isSafeInteger 等条件。

**追问：typeof NaN 是什么？** 是 'number'。NaN 属于 Number 类型，判断它用 Number.isNaN，而不是与 NaN 做 === 比较。

对应讲解：[typeof](#typeof)、[实际选型](#choose)。

<a id="d01-07"></a>

### D01-07 [P1·原理] typeof 未声明变量不报错，为什么 typeof 某个 let 变量会报错？

**回答：** typeof 对不可解析的名字有特殊处理，会返回 'undefined'；但作用域中的 let/const 绑定在初始化前处于暂时性死区。此时名字已经命中该绑定，问题是绑定尚不可访问，所以仍抛 ReferenceError。typeof 不能绕过 TDZ，也不能由“未声明时安全”推广成“所有情况下安全”。

对应讲解：[typeof 与 TDZ](#typeof)。

<a id="d01-08"></a>

### D01-08 [P0·原理] instanceof 的原理是什么？有哪些不适用场景？

**回答：** 默认机制下，instanceof 检查右侧构造器的 prototype 是否在左侧对象的原型链上。它适合判断自定义类的实例关系，但原型可以被改变，不同 realm 的构造器身份不同，所以它不等于不可伪造的对象类型鉴定。原始字符串也不会因为能调用字符串方法就 instanceof String。另有 Symbol.hasInstance 可以定制行为，回答默认机制时要说明这个边界。

对应讲解：[instanceof](#instanceof)。

<a id="d01-09"></a>

### D01-09 [P1·原理] 为什么判断数组优先用 Array.isArray？

**回答：** Array.isArray 识别数组身份，而 instanceof Array 默认比较原型链是否包含当前 Array.prototype。一个普通对象可通过 Object.create(Array.prototype) 获得相应原型关系，却仍不是数组；另一个 iframe 创建的真实数组也可能不满足当前窗口的 instanceof Array。Array.isArray 能处理这两类常见误判。

**追问：类数组是数组吗？** 不一定。具有数字索引和 length 只说明它像数组；也不保证可迭代，具体行为要看它实现的协议。

对应讲解：[原型反例](#instanceof)、[数组判断](#choose)。

<a id="d01-10"></a>

### D01-10 [P1·原理] 为什么 constructor 不适合通用类型判断？

**回答：** constructor 是普通属性，可以被自身属性遮蔽、被修改，某些对象甚至不继承它。{ constructor: Array } 就能让判断为真，但这个对象不是数组。跨 realm 的构造函数身份也可能不同。可选链只能避免 null/undefined 的属性访问错误，不能消除这些误判。

对应讲解：[constructor](#constructor)。

<a id="d01-11"></a>

### D01-11 [P1·原理] Object.prototype.toString.call 为什么比直接 toString 信息更多？它绝对可靠吗？

**回答：** 对象自己的 toString 可能被类型重写，例如数组会连接元素。显式取 Object.prototype.toString，再通过 call 指定接收者，使用的是通用标签方法，能得到 [object Array]、[object Date] 等结果。但 Symbol.toStringTag 可以影响标签，普通对象也能伪装成某些名称，所以它适合受控数据分类和调试，不是安全边界，更不能替代字段结构校验。

对应讲解：[类型标签](#tag)。

<a id="d01-12"></a>

### D01-12 [P0·基础] new Boolean(false) 为什么会进入 if 分支？

**回答：** new Boolean(false) 创建包装对象，条件转换看到的是对象，对象为真值。内部保存的原始 false 可以通过 valueOf 取得，但不会自动把这个对象本身变成假值。需要布尔转换时通常使用 Boolean(value)，需要布尔常量时直接写 true 或 false。

对应讲解：[包装对象](#primitive)。

<a id="d01-13"></a>

### D01-13 [P1·原理] “原始类型在栈，对象在堆”能作为完整答案吗？

**回答：** 不能。这是教学中的简化模型，不是 ECMAScript 对物理存储的固定要求。引擎会使用不同表示和优化，闭包环境也可能在函数返回后继续存活。更稳定的回答是先解释原始值不可变、对象身份与共享引用、按值传参，再把堆栈作为理解实现的辅助模型，而不是用它预测所有行为。

对应讲解：[内存模型](#memory)。

<a id="d01-14"></a>

### D01-14 [P0·编码] 判断一个值是否为字符串数组，需要检查哪些内容？

**回答：** 先用 Array.isArray 检查容器，再逐项检查 typeof item === 'string'。如果函数接受一般 JavaScript 数组，还要决定是否允许空位：every 会跳过空位，直接判断可能误把稀疏数组当成全部字符串。以下契约允许空数组，但不允许空位和非字符串元素。

<!-- example: interview-string-list -->
```js
function isStringArray(value) {
  if (!Array.isArray(value)) return false;
  for (const item of value) {
    if (typeof item !== 'string') return false;
  }
  return true;
}
console.log(isStringArray([])); // true
console.log(isStringArray(['x'])); // true
console.log(isStringArray([1])); // false
console.log(isStringArray(new Array(1))); // false
```

**追问：这就完成接口校验了吗？** 还没有。如果业务限制数量、单项长度、重复值或取值范围，仍需继续校验。类型只是契约的一部分。

对应讲解：[实际选型](#choose)。

<a id="d01-15"></a>

### D01-15 [P1·工程取舍] 后端 ID 超过 Number 安全整数范围，前端再转字符串能修复吗？

**回答：** 如果在 JSON 解析为 Number 时已经舍入，后续 String(id) 只是把不准确的数转成字符串，无法恢复原值。Number 的安全整数范围是 ±(2^53 - 1)，超出后并非每个整数都能被精确区分。标识符通常约定由后端直接返回字符串；需要大整数运算时可用 BigInt，但必须统一序列化协议，不能拿它恢复已丢失的精度。

对应讲解：[类型边界与业务契约](#choose)。
