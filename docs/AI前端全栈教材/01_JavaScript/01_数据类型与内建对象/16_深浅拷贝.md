# 16 深浅拷贝

拷贝不是单一操作：可能只复制引用、复制一层属性、复制对象图，或转移资源所有权。先写清需要保留什么，再选择API或实现。

## 二、知识讲解

<a id="k01"></a>

### 1. 赋值、浅拷贝和深拷贝

```js
const source = { nested: { count: 1 } };
const assigned = source;
const shallow = { ...source };
console.log(assigned === source, shallow === source); // true false
shallow.nested.count = 2;
console.log(source.nested.count); // 2
```

赋值复制引用值，两变量访问同一对象。浅拷贝创建新外层，但嵌套值如果是对象仍共享。深拷贝则在声明支持范围内复制对象图，需要决定原型、描述符、Symbol、函数、特殊容器与循环的处理，不能只定义为“递归遍历”。

状态更新通常只复制发生变化路径上的对象，结构共享可降低成本；为了“安全”每次深拷贝整份大状态未必合理。

<a id="k02"></a>

### 2. JSON 与 structuredClone 的选择

| 方案 | 常见能力 | 主要限制 |
| --- | --- | --- |
| spread/assign/slice | 外层浅复制 | 嵌套引用共享 |
| JSON stringify/parse | JSON可表达的数据树 | 类型丢失、特殊值改变、循环报错 |
| structuredClone(value,options?) | 支持的结构化可克隆对象图、循环、Date/Map/Set等 | 函数、Symbol值、WeakMap、DOM节点等通常不支持；自定义原型/描述符/private不能当完整保留 |
| 领域专用转换 | 只复制业务需要字段 | 需维护明确schema |

```js
const source = { date: new Date('2026-01-01T00:00:00Z') };
source.self = source;
const copy = structuredClone(source);
console.log(copy !== source, copy.self === copy, copy.date instanceof Date); // true true true
```

structuredClone是宿主提供的API，不是所有环境都具备相同支持范围。自定义类对象经克隆不应假定仍有原方法；getter可能被读取成值，属性元信息也不是保真目标。

<a id="k03"></a>

### 3. 循环和共享引用：对象图

需要同时处理两种结构：a.self=a形成环；a.left与a.right共同引用一个child形成共享节点。若每遇到引用就创建新对象，共享节点会被拆成两份，语义改变；若完全不记忆访问，会在环中无限递归。

正确思路是维护“源对象→副本”的映射，创建副本后立即登记，再递归子值。发现已登记对象时直接返回同一副本。普通Map在一次同步拷贝结束后会随局部状态释放，WeakMap常用于表达只按对象身份关联。

<a id="k04"></a>

### 4. 限定范围的手写实现

下例支持数组、普通对象/无原型对象及其自有数据属性，保留共享引用、循环、空位和描述符。显式拒绝访问器、函数、Date/Map等特殊对象，避免给出“通用深拷贝”的错误承诺。

```js
function clonePlain(value, seen = new WeakMap()) {
  if (typeof value === 'function') throw new TypeError('function unsupported');
  if (value === null || typeof value !== 'object') return value;
  if (seen.has(value)) return seen.get(value);
  const proto = Object.getPrototypeOf(value);
  if (!Array.isArray(value) && proto !== Object.prototype && proto !== null) {
    throw new TypeError('plain data only');
  }
  const copy = Array.isArray(value) ? new Array(value.length) : Object.create(proto);
  seen.set(value, copy);
  for (const key of Reflect.ownKeys(value)) {
    if (Array.isArray(value) && key === 'length') continue;
    const descriptor = Object.getOwnPropertyDescriptor(value, key);
    if (!('value' in descriptor)) throw new TypeError('accessor unsupported');
    descriptor.value = clonePlain(descriptor.value, seen);
    Object.defineProperty(copy, key, descriptor);
  }
  if (Array.isArray(value)) {
    Object.defineProperty(copy, 'length', Object.getOwnPropertyDescriptor(value, 'length'));
  }
  return copy;
}
const shared = { n: 1 };
const source = { left: shared, right: shared };
source.self = source;
const copy = clonePlain(source);
console.log(copy.self === copy, copy.left === copy.right, copy.left !== shared);
// true true true
```

Reflect.ownKeys包含Symbol和不可枚举键，defineProperty避免把__proto__当普通赋值入口。这个实现不保留对象整体的不可扩展状态，也不负责跨realm普通对象、Proxy行为和超深图的栈限制；按需求另行定义。

<a id="k05"></a>

### 5. transfer：复制与转移

```js
const buffer = new ArrayBuffer(4);
const moved = structuredClone(buffer, { transfer: [buffer] });
console.log(buffer.byteLength, moved.byteLength); // 0 4
```

transfer转移可转移资源的所有权，原侧ArrayBuffer通常被分离，不能继续按原数据访问。它能减少大资源复制成本，但会改变源对象可用性；不是一种“更快且无代价的深拷贝”。跨Worker传输同样要明确谁在何时拥有数据。

<a id="summary"></a>

## 三、知识小结

拷贝先写契约，再选工具。图结构要记忆“源→副本”，避免环和共享关系错误；资源转移需要所有权意识；状态管理未必需要全量深拷贝。

参考：[MDN structuredClone](https://developer.mozilla.org/en-US/docs/Web/API/Window/structuredClone)。较新 API 按目标运行时核对支持，示例各自独立。

## 四、面试题与答案

<a id="d16-01"></a>

### D16-01 [P0·原理] 浅拷贝到底复制了什么？

**回答：** 创建新外层容器并复制属性或元素的值；嵌套对象的值是引用，因此仍共享。它不是完全没复制，也不是所有层都独立。直接赋值则连外层对象都相同。

对应讲解：[赋值、浅拷贝和深拷贝](#k01)。

<a id="d16-02"></a>

### D16-02 [P0·原理] JSON为什么不是通用深拷贝？

**回答：** 它走JSON序列化契约，会丢失或改变undefined、函数、Symbol、Date、Map等信息，默认不能处理BigInt与循环，也不保留原型和描述符。适合JSON数据协议，不适合任意运行时对象。

对应讲解：[JSON 与 structuredClone 的选择](#k02)。

<a id="d16-03"></a>

### D16-03 [P0·编码] 深拷贝为什么必须先登记副本再递归？

**回答：** 源对象可能在子路径再次出现。提前登记后再遇到源对象便返回已创建副本，既终止循环，又让多个引用仍指向同一个副本。只用访问过集合而不保存对应副本，会丢失共享关系。

对应讲解：[循环和共享引用：对象图](#k03)。

<a id="d16-04"></a>

### D16-04 [P1·工程取舍] structuredClone能代替任何手写拷贝吗？

**回答：** 不能，要看支持类型、原型/描述符保留要求和环境。它能处理许多结构化数据和循环，但函数、DOM等不受支持，自定义类行为也不能假定保留。领域数据转换有时更可控。

对应讲解：[JSON 与 structuredClone 的选择](#k02)。

<a id="d16-05"></a>

### D16-05 [P1·原理] transfer之后源数据为何不能再用？

**回答：** transfer表达资源所有权转移，源ArrayBuffer被分离，目标取得资源；省掉复制伴随着源侧失效。设计时必须约定生命周期，不把它当普通共享引用。

对应讲解：[transfer：复制与转移](#k05)。
