# 02 类型转换与比较

类型转换不是一组需要死记的奇怪输出。先确定运算符需要什么类型，再按转换规则逐步执行，就能解释字符串拼接、宽松相等和默认值中的大部分问题。先修：数据类型与类型判断。

## 二、知识讲解

<a id="k01"></a>

### 1. 显式转换与隐式转换

显式转换是主动调用 Number、String、Boolean 等函数；隐式转换由运算符或语言结构触发。它们可能使用相同的底层规则，但入口并非完全等价，例如 Number(1n) 可转换，+1n 却抛错。

| 目标 | 常见转换结果 | 需要保留的边界 |
| --- | --- | --- |
| Boolean | null、undefined、0、-0、0n、NaN、'' 为假；普通对象为真 | 不调用对象的 valueOf 来决定真假；document.all 为浏览器历史例外 |
| Number | undefined→NaN；null→0；true→1；false→0；空白字符串→0 | 非完整数字文本→NaN；Symbol 抛错；大数可能舍入 |
| String | null→'null'；undefined→'undefined'；布尔和数字转文本 | String(Symbol()) 可用，隐式拼接 Symbol 通常抛错 |

```js
console.log(Number('  '), Number('12px')); // 0 NaN
console.log(Boolean('false'), Boolean([])); // true true
console.log(String(null), String(undefined)); // 'null' 'undefined'
```

转换成功不代表数据合法。Number('') 得到 0，但表单中的空输入可能应该报“必填”。应先按业务识别缺失值，再转换，最后验证范围和整数约束。

<a id="k02"></a>

### 2. 对象转换：ToPrimitive 与 hint

对象参与需要原始值的运算时，语言先尝试 ToPrimitive。它表达转换步骤，不是业务代码能直接调用的全局函数。

1. 若存在可调用的 Symbol.toPrimitive，传入 hint：'string'、'number' 或 'default'；结果必须是原始值，否则抛 TypeError。
2. 没有该方法时，通常在 number/default 意图下先 valueOf 后 toString，在 string 意图下反过来。
3. 普通对象的 valueOf 往往返回自身，仍是对象，于是继续尝试 toString。两次都没产生原始值就抛错。

Date 对默认转换有特殊处理，通常偏字符串；不能把普通对象的顺序无条件套用所有内建对象。

```js
const price = {
  [Symbol.toPrimitive](hint) {
    return hint === 'string' ? '￥10' : 10;
  }
};
console.log(String(price)); // ￥10
console.log(price + 2); // 12
console.log(price > 8); // true
```

Boolean(price) 不需要上述过程，因为普通对象本身就为真值。自定义转换方法可能有副作用，比较对象并不一定是纯读取。

<a id="k03"></a>

### 3. 加号、数值运算与关系比较

二元 + 先把两边转成原始值；只要其中一边为字符串，就进行字符串拼接，否则进行数值加法。减、乘、除等要求数值，不走字符串拼接分支。

```js
console.log('1' + 2); // '12'
console.log('1' - 2); // -1
console.log([] + 1); // '1'
console.log([1, 2] + 3); // '1,23'
```

[] 的 valueOf 仍是数组，toString 得到空串，所以 [] + 1 是 '' + 1，而不是“数组加数字”。[1,2] 转成 '1,2' 后拼接 3。

<、> 等也先处理原始值；两个原始值都是字符串时按 UTF-16 码元顺序比较，否则通常进入数值比较。'10' < '2' 为 true，10 < '2' 为 false。NaN 与任何值的这些数值关系比较通常为 false，不能据此推出相等。Number/BigInt 的混合比较有规则，但混合算术通常抛错。

<a id="k04"></a>

### 4. 四种相等关系

| 关系 | '1' 与 1 | NaN 与 NaN | +0 与 -0 | 两个不同对象 |
| --- | --- | --- | --- | --- |
| == | true，允许转换 | false | true | false |
| === | false，不跨类型转换 | false | true | false |
| Object.is | false | true | false | false |
| SameValueZero | false | true | true | false |

SameValueZero 是 Set/Map 键比较、Array.includes 等使用的规则，不是一个可直接调用的全局函数。indexOf 使用的相等行为使它找不到 NaN。

宽松相等不是“全都转 Number”：null 和 undefined 可彼此相等但不与 0 相等；布尔值会转数值；对象与合适的原始值比较会先转原始值；两个对象仍比较身份。Symbol、BigInt 还各有分支。

```js
console.log(null == undefined, null == 0); // true false
console.log([] == false); // true
console.log([NaN].includes(NaN), [NaN].indexOf(NaN)); // true -1
console.log(Object.is(0, -0), Object.is(NaN, NaN)); // false true
```

[] == false：false→0；[]→''；''→0；最后 0==0。整个过程中没有要求 Boolean([]) 为 false，因此与空数组为真值不矛盾。业务通常优先 ===；使用 value == null 同时匹配 null/undefined 时应明确这是有意的策略。

<a id="k05"></a>

### 5. Number、parseInt 与 parseFloat

| API | 读取方式 | 示例 |
| --- | --- | --- |
| Number(value) | 要求文本整体能表示数字，可含空白和支持的进制形式 | Number('12px') 为 NaN |
| parseInt(text, radix) | 按进制从可解析前缀读整数，遇非法字符停止 | parseInt('12px',10) 为 12 |
| parseFloat(text) | 按十进制浮点前缀读取 | parseFloat('1.5px') 为 1.5 |
| 一元 +value | 常作数值转换 | BigInt 和 Symbol 会抛错 |

parseInt 不是可靠的“数字取整”函数：它先转文本，指数记法可能改变结果。取整数部分用 Math.trunc，并先检查有限性。文本解析要按协议指定 radix，不能忽略 callback 多余参数。

```js
console.log(['10', '10', '10'].map(parseInt)); // [10, NaN, 2]
console.log(['10', '10', '10'].map(x => parseInt(x, 10))); // [10,10,10]
```

map 传入 value、index、array；parseInt 把 index 当 radix，三次分别使用 0、1、2。问题来自函数签名不匹配。

<a id="k06"></a>

### 6. 默认值与输入校验

|| 根据真假选择值，?? 只根据 null/undefined 选择值；二者返回操作数本身，不保证返回 Boolean。解构和参数默认值仅处理 undefined，不处理 null。

```js
const count = 0;
console.log(count || 10, count ?? 10); // 10 0
const { name = 'guest' } = { name: null };
console.log(name); // null
```

校验外部数据时按“是否提供→类型是否接受→转换是否成功→范围是否合法”的顺序执行。不要用一连串默认值把错误类型悄悄变成合法结果。可选链只防空值访问，不能验证数据结构。

## 三、知识小结

转换题按“运算符 → 是否先取原始值 → 目标类型 → 比较规则”推导。对象为真值与对象参与数值转换是不同规则；解析前缀与验证完整数字文本也不同。复述时选一个具体例子走完步骤，比罗列转换结果更稳。

参考：[MDN 类型转换](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Data_structures)；[MDN 相等比较](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Equality_comparisons_and_sameness)。较新 API 按目标运行时核对支持，示例各自独立。

## 四、面试题与答案

<a id="d02-01"></a>

### D02-01 [P0·原理] 为什么 '1'+2 与 '1'-2 不同？

**回答：** + 在两侧转原始值后，只要一侧是字符串就拼接；- 则要求数值。所以前者得到 '12'，后者先把 '1' 转成 1，再计算得到 -1。不能概括为所有运算都把字符串变成数字。

对应讲解：[加号、数值运算与关系比较](#k03)。

<a id="d02-02"></a>

### D02-02 [P0·原理] [] == false 为什么成立，空数组不是为真吗？

**回答：** Boolean([]) 为 true，但 == 不先对数组做布尔转换。false 转成 0，数组转原始值得到空串，空串再转 0，最后比较 0 与 0。条件判断与宽松相等使用不同路径。

对应讲解：[四种相等关系](#k04)。

<a id="d02-03"></a>

### D02-03 [P0·基础] ===、Object.is、SameValueZero 有什么区别？

**回答：** 它们不靠跨类型转换判断相等；主要数值边界是 NaN 和正负零：=== 不认为 NaN 等于自身，却认为正负零相等；Object.is 恰好对这两个边界相反；SameValueZero 同时认为 NaN 相等、正负零相等。对象都按身份比较。

对应讲解：[四种相等关系](#k04)。

<a id="d02-04"></a>

### D02-04 [P1·原理] 自定义对象转换时，valueOf 一定先于 toString 吗？

**回答：** 不一定。Symbol.toPrimitive 优先；不存在时还要看转换意图。普通对象偏 number/default 时通常先 valueOf，string 意图先 toString；Date 对 default 有特殊规则。转换方法必须最终给出原始值，否则失败。

对应讲解：[对象转换：ToPrimitive 与 hint](#k02)。

<a id="d02-05"></a>

### D02-05 [P0·编码] map(parseInt) 为什么出错？

**回答：** map 回调的第二个参数是索引，parseInt 的第二个参数是进制，所以索引意外成为 radix。用 x => parseInt(x,10) 固定签名，或按需求用 Number 解析完整文本。修复前要确认想要的是前缀解析还是输入校验。

对应讲解：[Number、parseInt 与 parseFloat](#k05)。

<a id="d02-06"></a>

### D02-06 [P0·工程取舍] 表单数字用 Number(value)||0 是否合适？

**回答：** 这会把空串转换成 0，也把 NaN 等假值合并为 0，可能掩盖未填或输入错误。应分别识别缺失、转换和合法范围。默认值保留合法 0 时可用 ??，但 ?? 本身不会校验字符串或 NaN。

对应讲解：[默认值与输入校验](#k06)。
