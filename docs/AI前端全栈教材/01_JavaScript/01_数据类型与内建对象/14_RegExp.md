## 二、知识讲解

<a id="k01"></a>

### 1. 字面量、构造器与转义层次

```js
const literal = /\d+/;
const dynamic = new RegExp('\\d+');
console.log(literal.test('a12'), dynamic.test('a12')); // true true
```

字面量由正则语法直接解释；构造器先经历JavaScript字符串解析，再经历正则解析，因此通常要多一层反斜杠。动态用户文本若作为“字面字符”插入模式，必须按正则上下文转义。

RegExp.escape(text)是较新的标准转义入口，需检查环境支持；完整安全转义涉及首字符与不同语法上下文，不宜把只替换几个标点的片段称为通用实现。若只想查字面子串，includes往往更直接。

<a id="k02"></a>

### 2. 基础模式、分组与断言

| 语法 | 含义 |
| --- | --- |
| . | 除特定换行外的单字符；s可改变换行行为 |
| [abc]、[^abc]、[a-z] | 字符集合、取反、范围 |
| \d / \w / \s 及大写反向类 | 数字/单词字符/空白；\w并不等于所有语言文字 |
| ^、$ | 起止；m影响行边界 |
| *、+、?、{m,n} | 重复次数；后缀?使量词懒惰 |
| (...)、(?:...)、(?<name>...) | 捕获、非捕获、命名捕获 |
| a\|b | 分支选择 |
| (?=...)、(?!...) | 正/负前瞻 |
| (?<=...)、(?<!...) | 正/负后顾，按兼容性使用 |
| \1、\k<name> | 数字/命名反向引用 |

贪婪量词倾向在可成功匹配的条件下多取字符，懒惰量词倾向少取，但仍可能回溯。断言检查位置条件，本身不消费对应字符；不能把“零宽”理解成没有计算成本。

```js
console.log('<a><b>'.match(/<.*>/)[0]); // <a><b>
console.log('<a><b>'.match(/<.*?>/g)); // ['<a>','<b>']
console.log('id=12'.match(/(?<key>\w+)=(?<value>\d+)/).groups.value); // '12'
```

<a id="k03"></a>

### 3. flags、属性与 lastIndex

flags包括g全局、i忽略大小写、m多行锚点、s点匹配换行、u Unicode模式、v Unicode集合扩展、y粘连、d匹配索引。u/v互斥；具体语法需检查目标支持。

实例source返回模式文本，flags返回标志字符串；global、ignoreCase、multiline、dotAll、unicode、unicodeSets、sticky、hasIndices等反映各标志。lastIndex是可变匹配位置，尤其影响g/y的test和exec。

```js
const re = /a/g;
console.log(re.test('a'), re.lastIndex); // true 1
console.log(re.test('a'), re.lastIndex); // false 0
```

g可从lastIndex开始继续向后搜索；y要求恰好从该位置开始，失败重置。复用带状态正则做独立校验时要避免旧lastIndex影响结果。

<a id="k04"></a>

### 4. test、exec 与字符串方法

| 调用 | 返回 |
| --- | --- |
| re.test(text) | Boolean，但g/y会更新状态 |
| re.exec(text) | 一次匹配及捕获数组，或null；可含index/input/groups/indices |
| text.search(re) | 首个位置或-1 |
| text.match(re) | 无g时详细一次匹配；有g时完整匹配文本数组 |
| text.matchAll(re) | 各次详细匹配的迭代器；正则需要g |
| text.replace/replaceAll | 替换后的字符串，注意g与替换模式 |
| text.split(re) | 拆分结果，捕获组也可能进入数组 |

exec循环遇到可匹配空串的模式时，不能假定lastIndex会自动前进。手工推进还须按Unicode模式处理代理对；只需要完整迭代时优先考虑matchAll。

旧的RegExp.$1等全局静态匹配状态，以及compile等历史接口不适合作为现代逻辑基础，可能因其他匹配调用而受干扰。

<a id="k05"></a>

### 5. 输入校验、动态模式与 ReDoS

校验必须明确是否要整串匹配、是否允许换行、是否要Unicode字符集，以及业务长度上限。简单“邮箱正则”不能代替邮箱所有权验证；身份证等格式也不等于业务真实性。

某些嵌套量词与模糊分支在接近匹配但最终失败的长输入上可能发生大量回溯，阻塞主线程或服务器事件循环。防护包括限制输入长度、避免高风险模式、选择线性时间方案、隔离耗时处理和实际测试。

把外部字符串拼进正则时先区分“用户允许提供模式”还是“只查文本”。前者需要资源和语义限制，后者转义或使用字符串API。

<a id="summary"></a>

## 三、知识小结

正则推导顺序：字符串有没有先转义 → 模式匹配什么 → flags怎样改变规则 → lastIndex是否留下状态 → API返回哪种结构。性能与安全必须结合输入长度及失败路径。

参考：[MDN RegExp](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp)。较新 API 按目标运行时核对支持，示例各自独立。

## 四、面试题与答案

<a id="d14-01"></a>

### D14-01 [P0·原理] /a/g重复test为何一真一假？

**回答：** g让test使用并修改lastIndex。第一次成功后位置到1，第二次从末尾继续找不到，返回false并重置为0。独立校验避免复用状态或显式管理位置，不能误以为结果随机。

对应讲解：[flags、属性与 lastIndex](#k03)。

<a id="d14-02"></a>

### D14-02 [P1·基础] m与s分别解决什么问题？

**回答：** m改变^/$对多行边界的解释，s改变点号是否匹配换行；两者不是同一个“多行模式”。u/v则影响Unicode相关语法和匹配语义，d提供索引信息。

对应讲解：[flags、属性与 lastIndex](#k03)。

<a id="d14-03"></a>

### D14-03 [P1·原理] 构造器正则为什么要写双反斜杠？

**回答：** 传给构造器的是JS字符串，先由字符串语法处理转义，再由正则语法解析；字面量少了前一层。动态模板还可能额外涉及用户文本转义，不能靠猜反斜杠数量。

对应讲解：[字面量、构造器与转义层次](#k01)。

<a id="d14-04"></a>

### D14-04 [P0·基础] exec与matchAll怎么选择？

**回答：** exec适合逐次控制状态，返回一次匹配并可能更新lastIndex；matchAll提供每次详细结果的迭代器，适合收集全部捕获和位置。exec的空匹配推进、g/y状态必须自行处理。

对应讲解：[test、exec 与字符串方法](#k04)。

<a id="d14-05"></a>

### D14-05 [P1·工程取舍] 正则是否有性能或安全风险？

**回答：** 有。某些模式对长的失败输入会大量回溯，阻塞执行；动态拼接还可能改变匹配含义。限制长度、使用合适算法或可信转义，并测试失败路径，而不是只看正常示例能匹配。

对应讲解：[输入校验、动态模式与 ReDoS](#k05)。
