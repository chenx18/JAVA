## 二、各知识点详细解释

### 1. 类型转换为什么是 JavaScript 核心

JavaScript 很多语法允许不同类型共同参与运算。例如：

```js
'1' + 2
'1' - 2
if (value) {}
```

这些语法背后并不是“浏览器随便转换”，而是 ECMAScript 为每种运算定义了抽象转换过程。

### 2. ToPrimitive

当 Object 必须进入 primitive 语义时，会走 ToPrimitive。优先看 `Symbol.toPrimitive`，否则根据 hint 进入 OrdinaryToPrimitive。

```js
const obj = {
  [Symbol.toPrimitive](hint) {
    if (hint === 'string') return 'hello'
    return 10
  }
}
```

### 3. ToBoolean

核心结果：

```text
undefined/null/false/0/-0/0n/NaN/'' → false
其他普通值 → true
```

普通对象不会先 ToPrimitive。

### 4. ToNumber

典型规则：

```text
undefined → NaN
null → +0
false → +0
true → 1
'' → +0
合法数字字符串 → 对应数字
非法数字字符串 → NaN
Symbol → TypeError
BigInt → TypeError
Object → 先 ToPrimitive，再继续转换
```

### 5. ToNumeric

ToNumeric 会先得到 primitive；如果最终是 BigInt，就保留 BigInt，否则走 ToNumber。

这就是为什么现代 ECMAScript 中谈“数值运算”时，不能简单说所有东西都直接 ToNumber。

### 6. ToString

常见：

```js
String(undefined) // 'undefined'
String(null) // 'null'
String(true) // 'true'
String(123) // '123'
```

对象转换成字符串时，会涉及 ToPrimitive。

### 7. ToObject

某些操作需要 Object 时，primitive 可以被包装成对应 wrapper object。`null` 和 `undefined` 不能 ToObject。

这解释了：

```js
'abc'.toUpperCase()
```

为什么可行，而：

```js
null.toString()
```

会出错。

### 8. ToPropertyKey

对象 property key 只有 String 和 Symbol。数字作为属性键时通常会先被转成 String：

```js
const obj = {}
obj[1] = 'a'
obj['1'] === 'a' // true
```

### 9. `+` 的特殊规则

`+` 同时负责数值加法和字符串拼接。可以记成：

```text
两边先 ToPrimitive
→ 任一边是 String
   → 两边 ToString → 拼接
→ 否则
   → ToNumeric → 数值加法
```

因此：

```js
'1' + 2 // '12'
'1' - 2 // -1
```

### 10. `==`

`==` 不是简单“全部转 Number”，而是 IsLooselyEqual 算法。不同类型组合有不同路径。

### 11. `===`

类型不同直接 false；相同类型再比较对应值。不会执行一般性的隐式转换。

### 12. Object.is

对应 SameValue：

```js
Object.is(NaN, NaN) // true
Object.is(+0, -0) // false
```

### 13. SameValueZero

与 SameValue 的区别是 +0/-0 被视为相同；NaN 自己与自己相同。

`includes`、Map、Set 等很多场景会使用这一思路。

### 14. parseInt / parseFloat

`Number` 偏完整转换；`parseInt`/`parseFloat` 偏前缀解析：

```js
Number('12px') // NaN
parseInt('12px', 10) // 12
parseFloat('3.14px') // 3.14
```

## 三、本章面试题与答案

### 题 1：ToPrimitive 是什么？

**答案：**

ToPrimitive 是把对象转换成 primitive value 的规范抽象操作。它优先检查 `Symbol.toPrimitive`，没有时根据 hint 使用 `valueOf`/`toString` 等方式尝试获得非对象值。很多算术、比较和字符串场景都会间接用到它。

### 题 2：ToBoolean 和 ToPrimitive 的区别？

**答案：**

ToBoolean 的目标是得到 true/false，普通对象直接是 true；ToPrimitive 的目标是把对象变成 primitive。因此 `Boolean([])` 为 true，而 `[] == false` 却会触发对象到 primitive 的转换。

### 题 3：为什么 [] == false？

**答案：**

`[]` 是对象，宽松相等比较时先 ToPrimitive，空数组得到 `''`；false 再按规则转为 0，空字符串再转为 0，最终比较 `0 == 0`，结果 true。

### 题 4：为什么 [] == ![]？

**答案：**

先计算 `![]`。数组是对象，ToBoolean 为 true，取反得到 false。于是表达式变成 `[] == false`，再按宽松相等规则转换，结果 true。

### 题 5：为什么 '1' + 2 是 '12'，而 '1' - 2 是 -1？

**答案：**

`+` 具有字符串连接语义，两边 ToPrimitive 后只要任一侧是 String，就进入 ToString 拼接；减法没有字符串连接语义，进入 ToNumeric，因此字符串 `'1'` 被转换为数字 1。

### 题 6：parseInt 和 Number 的区别？

**答案：**

Number 更像完整的数值转换，要求整个输入符合数值转换规则；parseInt 是从字符串前缀解析整数。因此 `Number('12px')` 为 NaN，而 `parseInt('12px', 10)` 为 12。

### 题 7：==、===、Object.is 的区别？

**答案：**

`==` 使用宽松相等算法，允许规范定义的类型转换；`===` 使用严格相等，不做一般隐式转换；`Object.is` 使用 SameValue，主要区别是 NaN 自相等，并区分 +0 与 -0。

### 题 8：NaN 为什么不等于自己？

**答案：**

这是 Number equality 的定义。严格相等中只要一侧是 NaN，就返回 false，因此 NaN !== NaN；需要判断 NaN 时使用 `Number.isNaN()`。

### 题 9：为什么 Number('') 是 0？

**答案：**

ToNumber 的 String 转换规则把空字符串转换成 +0。它与 parseInt 的“从字符开头解析整数”不是同一种语义。
