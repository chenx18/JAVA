# 09 迭代器与生成器

迭代协议把“数据在哪里”和“如何逐项消费”分开。生成器通过保存暂停位置实现这种协议，异步生成器再把等待纳入过程，但都不会自动建立线程。

## 二、知识讲解

<a id="k01"></a>

### 1. iterable 与 iterator

iterable提供[Symbol.iterator]()入口，调用后得到iterator；iterator的next()返回{value,done}。done为true表示结束，value还可能是最终返回值，但一般for...of不会把它作为元素交付。

```js
const iterator = ['A', 'B'].values();
console.log(iterator.next()); // {value:'A',done:false}
console.log([...iterator]); // ['B']
console.log([...iterator]); // []
```

同一个迭代器保存进度，不一定可以重来；数组通常每次调用Symbol.iterator返回新迭代器。普通对象默认不可迭代，类数组也未必可迭代。for...of、数组/调用spread消费迭代协议，对象spread复制属性，是另一套语义。

<a id="k02"></a>

### 2. Generator 的暂停与恢复

```js
function* calculate() {
  const value = yield 'ready';
  return value * 2;
}
const iterator = calculate();
console.log(iterator.next()); // {value:'ready',done:false}
console.log(iterator.next(5)); // {value:10,done:true}
```

调用生成器函数先得到生成器对象；第一次next才开始运行。yield把值交出去并暂停；后一次next(value)把值送回上一次yield表达式，成为局部value。第一次next的参数没有已暂停的yield接收。

return(value)请求结束，throw(error)在暂停点注入异常，函数内部可用try/catch/finally处理。finally自身如果yield，return不一定马上得到done:true，所以清理过程也要看具体控制流。

<a id="k03"></a>

### 3. yield*、惰性与提前退出

yield*把迭代委托给子序列，并可取得子生成器return的最终值。惰性表示消费者需要下一项时才推进，不等于无成本；把无限序列一次展开成数组仍会无法完成。

```js
function* sequence() {
  try { yield 1; yield* [2, 3]; }
  finally { console.log('closed'); }
}
for (const item of sequence()) {
  console.log(item); // 1
  break;
}
// closed
```

for...of在break或循环体异常等提前退出路径会尝试调用iterator.return，生成器finally可以因此清理。手动next后直接丢弃迭代器，不保证语言自动替你调用return。对于next本身失败等路径，要按协议具体分析，不能笼统说任何异常都关闭。

<a id="k04"></a>

### 4. 异步迭代与流消费

async iterable提供Symbol.asyncIterator；next的结果通过Promise交付。async function*可await再yield；for await...of逐项等待，也能适配同步iterable。

```js
async function* numbers() { yield 1; yield await Promise.resolve(2); }
const result = [];
for await (const n of numbers()) result.push(n);
console.log(result); // [1,2]
```

本例需要module或async包装。逐项等待不等于所有底层任务都串行启动：若输入Promise早已创建，它们可能同时运行。reader由谁获取，通常就由谁在finally处理cancel/releaseLock；要决定清理失败是否覆盖原错误。

新环境的同步Iterator.from与map/filter/take/drop/flatMap/reduce/toArray/forEach/some/every/find等辅助方法可组合惰性序列，需核对兼容性；不能把同步Iterator方法直接视作完整异步迭代辅助库。

<a id="summary"></a>

## 三、知识小结

iterable给入口，iterator给进度，generator保存暂停现场；next把值送回来，yield把值交出去，提前退出关注清理。异步迭代负责等待，不负责字节分帧或并发预算。

参考：[MDN 迭代器与生成器](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Iterators_and_generators)。较新 API 按目标运行时核对支持，示例各自独立。

## 四、面试题与答案

<a id="c09-01"></a>

### C09-01 [P1·基础] iterable、iterator、generator是什么关系？

**回答：** iterable能产生iterator，iterator用next逐项返回value/done；generator是方便实现暂停与推进的语言工具，其对象通常同时可迭代和可作为迭代器。三个词分别描述协议入口、消费状态和实现机制。

对应讲解：[iterable 与 iterator](#k01)。

<a id="c09-02"></a>

### C09-02 [P1·原理] next(5)的5传到哪里？

**回答：** 首次next的参数没有yield暂停点接收，通常被忽略。后续next(5)把5作为上一次暂停的yield表达式结果，函数继续运行。它不是替换这一次要yield出去的值。

对应讲解：[Generator 的暂停与恢复](#k02)。

<a id="c09-03"></a>

### C09-03 [P1·原理] 生成器return值会出现在展开数组中吗？

**回答：** 通常不会，for...of和展开消费done为false的迭代值，done为true时的返回值不作为元素。yield*表达式则能取得被委托生成器的最终返回值。

对应讲解：[yield*、惰性与提前退出](#k03)。

<a id="c09-04"></a>

### C09-04 [P1·工程取舍] for await适合流式接口，但解决了哪些问题？

**回答：** 它提供逐项等待消费方式，可配合finally管理资源。UTF-8解码、SSE事件分帧、重连、取消、版本检查和背压仍需独立设计，不能把一个for await循环称作完整流协议实现。

对应讲解：[异步迭代与流消费](#k04)。
