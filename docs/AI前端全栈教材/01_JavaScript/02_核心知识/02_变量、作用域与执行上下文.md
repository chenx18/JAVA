## 二、知识讲解

<a id="k01"></a>

### 1. 声明、初始化与赋值

声明建立名字与绑定，初始化让绑定拥有可读取的初始值，赋值改变已可写绑定保存的值。教学中的“提升”描述执行正文前建立绑定的表现，不是引擎把源码文本真的搬到顶部。

| 声明 | 作用域 | 正文执行前的典型状态 | 再赋值 |
| --- | --- | --- | --- |
| var | 函数或所属顶层环境，普通块不隔离 | 初始化为undefined | 可以 |
| let | 块级 | 已建立但未初始化，处于TDZ | 可以 |
| const | 块级 | 已建立但未初始化，处于TDZ | 不可以 |
| 普通函数声明 | 受所属作用域规则管理 | 通常初始化为函数值 | 视环境与绑定规则 |
| class声明 | 块级 | TDZ | 通常可重新赋值绑定，但不允许初始化前访问 |

var可重复var声明，let/const不允许相冲突的同作用域声明。const普通声明必须有初始值，for...of/in等由迭代初始化是特殊语法。块内函数声明在非严格经典脚本有历史兼容规则，不把它作为普遍可移植的提升写法。

<a id="k02"></a>

### 2. 词法作用域与遮蔽

作用域规定标识符的可访问关系。JavaScript主要使用词法作用域：函数的外层查找路径由定义位置决定，而不是由谁调用它决定。

```js
const label = 'outer';
function read() { return label; }
function caller() {
  const label = 'caller';
  return read();
}
console.log(caller()); // outer
```

read自己的环境找不到label，沿定义位置的外层环境找到outer；caller的局部变量不在该链上。调用栈是caller调用read，查找路径却不因此经过caller的局部环境。

内层同名绑定会遮蔽外层，即使尚未初始化也不会跳过它去找外层。这个规则与TDZ结合，是常见输出题的关键。

<a id="k03"></a>

### 3. TDZ 与函数表达式

```js
const value = 'outside';
{
  try { console.log(value); }
  catch (error) { console.log(error.name); } // ReferenceError
  let value = 'inside';
  console.log(value); // inside
}
```

进入块时内层value已建立，读取命中它但还未初始化，因此报错。“let完全没有提升”遗漏了它从块开始就遮蔽外层的行为。

函数表达式则要先完成赋值才能调用。var fn=function(){}在赋值前fn通常为undefined，调用报TypeError；const fn=()=>{}在初始化前访问会报ReferenceError。区别来自绑定状态，不是箭头天然“不能提升”。

typeof完全未声明名字可返回'undefined'，但读取TDZ中的名字仍抛错。

<a id="k04"></a>

### 4. 环境记录、执行上下文与调用栈

环境记录是规范描述绑定及其外层关联的模型，不是程序中能直接取出的普通对象。执行上下文保存运行代码需要的状态，其中包括用于标识符解析的环境关联。

同步函数调用进入执行上下文栈，返回后退出。调用栈回答“当前谁在运行、返回给谁”；作用域链回答“标识符从哪里找”。它们有关联但不能画成同一条链。

同一个函数定义调用两次，可以创建两份局部环境。外层函数出栈后，内部函数若仍可达，所需环境仍可能保留。闭包不需要让整个调用栈一直不退出。

浏览器经典脚本顶层var通常与全局对象属性相关，let/const在全局词法环境；ESM顶层声明属于模块，Node CJS又有模块包装。全局不是“所有变量都在window”这一条规则。

<a id="k05"></a>

### 5. 循环绑定与异步回调

```js
const shared = [];
for (var i = 0; i < 3; i++) shared.push(() => i);
const separate = [];
for (let j = 0; j < 3; j++) separate.push(() => j);
console.log(shared.map(fn => fn())); // [3,3,3]
console.log(separate.map(fn => fn())); // [0,1,2]
```

这里不用定时器也能看到差异：var版本的函数都读取同一个i，循环结束为3；let的for循环为每次迭代建立独立绑定。定时器只是让读取发生在循环结束后，并不是制造问题的原因。

IIFE用每次调用的参数也能创建独立环境。修复重点是明确共享还是独立状态，不是尝试把延迟改成更小。

<a id="k06"></a>

### 6. 默认参数环境与初始化顺序

默认参数仅在实参为undefined或未提供时求值，每次调用重新计算。前面的参数可被后面的默认表达式引用；反向读取尚未初始化的参数可能触发TDZ。

```js
function valid(a = 1, b = a + 1) { return b; }
function invalid(a = b, b = 1) { return a; }
console.log(valid()); // 2
try { invalid(); } catch (error) { console.log(error.name); } // ReferenceError
```

带默认值的参数环境与函数体的var/函数声明可有独立的作用域关系，不能把默认参数简单改写成函数体开头的一次赋值而忽略查找差异。参数初始化时的副作用也先于后续函数体执行。

<a id="summary"></a>

## 三、知识小结

复述主线：绑定先建立，初始化决定可读性；查名字看定义位置，执行顺序看调用栈；同次环境可能共享，不同调用/循环迭代可能各自独立。

参考：[MDN 作用域](https://developer.mozilla.org/en-US/docs/Glossary/Scope)；[javascript.info 作用域与闭包](https://javascript.info/closure)。较新 API 按目标运行时核对支持，示例各自独立。

## 四、面试题与答案

<a id="c02-01"></a>

### C02-01 [P0·基础] var、let、const最重要的区别是什么？

**回答：** 从作用域、初始化和再赋值三个维度回答。var不受普通块隔离且通常预先初始化为undefined；let/const是块级绑定，初始化前处于TDZ；const限制重新绑定但不限制对象内容。再补充重复声明和全局环境差异。

对应讲解：[声明、初始化与赋值](#k01)。

<a id="c02-02"></a>

### C02-02 [P0·原理] let究竟有没有提升？

**回答：** 若提升指执行正文前建立绑定，let有相应建立过程，但未初始化，读取会报错。它从块开始就遮蔽外层同名绑定，这就是不能仅说“没有提升”的原因。

对应讲解：[TDZ 与函数表达式](#k03)。

<a id="c02-03"></a>

### C02-03 [P0·原理] 函数查变量为什么不看谁调用它？

**回答：** JavaScript使用词法作用域，函数与定义位置的外层环境关联。调用者的局部变量不自动进入这个查找链。调用栈记录执行关系，不能替代词法查找关系。

对应讲解：[词法作用域与遮蔽](#k02)。

<a id="c02-04"></a>

### C02-04 [P0·原理] 循环里的var为何输出三个3？

**回答：** 所有回调访问同一个绑定，执行时循环已经结束。let循环的每次迭代有独立绑定，IIFE参数也能隔离。用同步收集函数再调用的例子同样能证明，因此原因不是setTimeout本身。

对应讲解：[循环绑定与异步回调](#k05)。

<a id="c02-05"></a>

### C02-05 [P1·原理] 函数返回后执行上下文退出，闭包为何还能访问变量？

**回答：** 当前调用不再占据同步执行栈，但可达函数仍关联所需外层环境，环境生命周期与栈帧执行生命周期不是同一件事。是否回收取决于可达性及引擎实现。

对应讲解：[环境记录、执行上下文与调用栈](#k04)。

<a id="c02-06"></a>

### C02-06 [P1·原理] function f(a=b,b=1){}为什么可能抛错？

**回答：** 调用f()时按顺序初始化参数，a的默认表达式读取尚未初始化的b，触发TDZ。默认参数有自己的初始化和作用域规则，不只是函数体首行赋值。

对应讲解：[默认参数环境与初始化顺序](#k06)。
