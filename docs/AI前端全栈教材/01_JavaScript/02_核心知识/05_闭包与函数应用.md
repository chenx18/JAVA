# 05 闭包与函数应用

闭包把函数与定义时的词法环境联系起来。理解重点是以后调用时读哪一份绑定，而不是看到嵌套函数就背“会内存泄漏”。

## 二、知识讲解

<a id="k01"></a>

### 1. 函数与词法环境

```js
function createCounter() {
  let count = 0;
  return () => ++count;
}
const first = createCounter();
const second = createCounter();
console.log(first(), first(), second()); // 1 2 1
```

第一次调用createCounter建立count绑定并创建内部函数；返回后当前同步调用结束，但first仍关联所需环境。以后first读取并修改原来的count。第二次createCounter产生另一份局部环境，所以second从1开始。

闭包在函数创建并关联环境时就形成；return只是让内部函数逃出外层调用的一种方式。监听回调、定时器和模块函数也能保留环境，不要求必须返回函数。

<a id="k02"></a>

### 2. 共享绑定与计算快照

```js
function pair() {
  let count = 0;
  const label = 'count=' + count;
  return {
    increment: () => ++count,
    current: () => count,
    snapshot: () => label
  };
}
const api = pair();
api.increment();
console.log(api.current(), api.snapshot()); // 1 count=0
```

两个读count的函数共享同一绑定，能观察修改；label在创建时已经计算成字符串，count变化不会自动重新计算label。这个旧值来自保存了计算结果，不是闭包复制了所有变量。

框架中一次组件函数调用/渲染可能创建一批新绑定，旧回调仍关联旧调用环境。排查stale state时要区分“共享可变变量后来变了”和“旧函数仍读旧环境”，修复方法不能一概是读全局最新值。

<a id="k03"></a>

### 3. 循环、私有状态与函数工厂

var循环回调可能共享同一绑定，let循环通常每次迭代有独立绑定；IIFE参数也能隔离。先确定想共享状态还是记录当次值。

函数工厂常用来固定配置，私有状态则由闭包控制访问入口：

```js
function createFormatter(prefix) {
  return value => prefix + ': ' + value;
}
const error = createFormatter('ERROR');
console.log(error('network')); // ERROR: network
```

缓存也可封装在闭包中，但Map仍会保持引用；隐藏了变量不等于解决容量问题。柯里化保存先提供的参数，偏应用固定部分参数，它们是闭包的应用而非闭包的同义词。

<a id="k04"></a>

### 4. 防抖、节流与时间线

防抖等待一段没有新调用的静默期再执行；节流限制时间窗口内的执行频率。必须明确leading、trailing、cancel、maxWait/flush及返回值，而不是只写一个timer。

以wait=200ms，在0、80、160ms连续触发：纯尾部防抖最早约360ms执行最后一次；纯首部节流约0ms执行，窗口内其余调用忽略。繁忙主线程可能让实际执行更晚，timer不是精确时钟。

包装函数需要跨调用保存timer、参数、this，因此使用闭包。若每次事件都重新创建debounce包装，就会各自建立计时器，无法合并。cancel只取消尚未执行的计划调用，不取消已经发出的网络请求。

<a id="k05"></a>

### 5. 闭包与资源生命周期

闭包可能使环境中的对象继续可达，但是否泄漏取决于业务是否仍需要及引用链是否清理。

```js
function mount(target) {
  const data = new Array(1000).fill('row');
  const handler = () => data.length;
  target.addEventListener('resize', handler);
  return () => target.removeEventListener('resize', handler);
}
```

这是接收EventTarget的示例，挂载者应在卸载时调用返回函数。全局target仍持有监听器时，移除页面节点不会自动移除这条引用。还需清理定时器、订阅、未完成请求和缓存；不要依赖GC来主动关闭外部资源。

<a id="summary"></a>

## 三、知识小结

闭包的回答主线：函数关联环境→读取绑定→共享或独立→用途→生命周期。需要记住的是访问关系，之后用计数器、循环和快照例子证明。

参考：[MDN Closures](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Closures)。较新 API 按目标运行时核对支持，示例各自独立。

## 四、面试题与答案

<a id="c05-01"></a>

### C05-01 [P0·原理] 什么是闭包，必须return函数吗？

**回答：** 闭包是函数与其关联词法环境的组合，使函数可以访问定义位置外层变量。return不是必要条件，注册回调也能保留环境；返回函数只是演示外层调用结束后仍可访问状态的直观方式。

对应讲解：[函数与词法环境](#k01)。

<a id="c05-02"></a>

### C05-02 [P0·原理] 闭包保存变量还是值？

**回答：** 保留访问绑定的能力。共享同一环境的函数能观察彼此修改，不同次调用可有独立绑定；若提前计算字符串等快照，旧结果不会自动随另一个变量重新计算。

对应讲解：[共享绑定与计算快照](#k02)。

<a id="c05-03"></a>

### C05-03 [P0·编码] 实现尾部防抖并支持取消。

**回答：** 下例保留最后参数和this，每次调用重置计时，安静wait毫秒后执行。先释放内部引用再调用fn，支持重入；不含leading/maxWait/flush，也不返回延迟执行的Promise。异步fn失败需由使用方明确处理。

```js
function debounce(fn, wait = 200) {
  if (typeof fn !== 'function' || !Number.isFinite(wait) || wait < 0) throw new TypeError('invalid arguments');
  let timer = null, args, receiver;
  function cancel() {
    if (timer !== null) clearTimeout(timer);
    timer = null;
    args = receiver = undefined;
  }
  function wrapped(...nextArgs) {
    cancel();
    args = nextArgs;
    receiver = this;
    timer = setTimeout(() => {
      const savedArgs = args, savedReceiver = receiver;
      timer = null;
      args = receiver = undefined;
      fn.apply(savedReceiver, savedArgs);
    }, wait);
  }
  wrapped.cancel = cancel;
  return wrapped;
}
```

**追问与回答：** cancel不取消已经开始的请求，搜索还需要AbortSignal与版本校验。测试连续触发、最后参数/this、取消及重复使用。

对应讲解：[防抖、节流与时间线](#k04)。

<a id="c05-04"></a>

### C05-04 [P0·编码] 实现首部节流，如何说明边界？

**回答：** 下例首次立即执行，窗口内忽略后续调用，并支持cancel重置。它没有尾部补执行，不能保证最终滚动位置一定保存；如需leading+trailing，要保存窗口内最后参数并定义结束策略。

```js
function throttle(fn, wait = 200) {
  if (typeof fn !== 'function' || !Number.isFinite(wait) || wait < 0) throw new TypeError('invalid arguments');
  let timer = null;
  function wrapped(...args) {
    if (timer !== null) return;
    timer = setTimeout(() => { timer = null; }, wait);
    return fn.apply(this, args);
  }
  wrapped.cancel = () => {
    if (timer !== null) clearTimeout(timer);
    timer = null;
  };
  return wrapped;
}
```

**追问与回答：** 视觉刷新可按rAF合并，它与固定毫秒窗口节流并不等价。

对应讲解：[防抖、节流与时间线](#k04)。

<a id="c05-05"></a>

### C05-05 [P1·工程取舍] 闭包一定造成内存泄漏吗？

**回答：** 不会。闭包只可能延长所需对象的可达生命周期，真正的问题是不再需要的数据仍被监听器、timer、缓存等保留。排查应追引用链并明确清理所有者，而不是看到闭包就删除它。

对应讲解：[闭包与资源生命周期](#k05)。
