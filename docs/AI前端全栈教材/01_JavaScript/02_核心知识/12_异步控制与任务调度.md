# 12 异步控制与任务调度

生产异步流程需要管任务启动、并发数量、结果顺序、取消和重试预算。Promise负责表达结果，调度器负责这些结果背后的资源策略。

## 二、知识讲解

<a id="k01"></a>

### 1. 任务函数与工作位

并发池输入应是()=>fetch(...)这样的未启动任务，而非已经发出的fetch Promise。池不能让过去已经启动的请求倒回去。

上限为2时先启动0/1，任一个完成后补2，再补后续。领取索引在await之前完成，同一JS执行线程中可明确分配；完成顺序不必等于输入顺序，因此结果写回输入索引。

限制的是池中task数量，不保证task内部没有再启动多个子请求。还要明确一个任务失败时是立即报告、继续收集还是停止后续启动。

<a id="k02"></a>

### 2. 取消、超时与失败结果

运行中取消要给task传signal并由底层响应；排队取消要停止调用未启动任务。fail-fast只描述汇总结果何时失败，不意味着全部工作已停止。

超时有连接、首数据、空闲和总截止时间等不同预算。race一个超时Promise只是结束等待，不保证关掉网络或撤销服务器写入。当前任务结束后，还应释放timer和abort监听。

文末的pool选择收集全部结局：收到取消后未启动项标cancelled；已启动任务按自身是否响应signal返回成功或拒绝。忽略signal的任务仍可能成功，UI提交有效性由版本层另管。

<a id="k03"></a>

### 3. 重试、退避、抖动与幂等

重试先分类错误：无权限、非法输入等通常不能直接重试；网络、429和某些5xx按接口契约判断，遵守Retry-After。指数退避拉长间隔，抖动避免客户端同步再冲击服务。

客户端没收到结果不代表服务器没执行。例如订单创建成功但响应丢失，重新创建可能产生重复副作用。写操作需要服务端原子幂等键和状态查询；同一幂等键还要绑定用户、参数和有效期。

最大次数、单次超时和总截止时间分别限制不同维度。文末代码演示次数、退避和取消，生产还要接入整体deadline、Retry-After与业务错误分类。

<a id="k04"></a>

### 4. 限速、去重与缓存

| 机制 | 主要作用 |
| --- | --- |
| 防抖/节流 | 控制事件触发频率与执行窗口 |
| 并发池 | 控制同时运行的任务数 |
| 每秒限速 | 控制单位时间启动量 |
| single-flight | 同key共享进行中的请求 |
| 结果缓存 | 按策略复用已完成结果 |

每秒发1个、每个耗时30秒，仍可能累积约30个在途任务，因此限速不等于限制并发。

```js
function createSingleFlight() {
  const active = new Map();
  return (key, task) => {
    if (active.has(key)) return active.get(key);
    const promise = Promise.resolve().then(task).finally(() => active.delete(key));
    active.set(key, promise);
    return promise;
  };
}
let calls = 0;
const run = createSingleFlight();
const first = run('x', () => ++calls);
const second = run('x', () => ++calls);
console.log(first === second, await first, calls); // true 1 1
```

key应包含影响结果的参数和用户上下文。共享请求的一个消费者取消，不应无条件abort所有人的底层请求，需要独立等待取消或引用计数策略；缓存失败是否保留也应明确。

<a id="summary"></a>

## 三、知识小结

调度题按“启动权→资源上限→结果契约→取消→重试预算→幂等”组织答案。每个机制解决一类问题，不用一个race或loading布尔值概括全部过程。

参考：[MDN Promise](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise)；[MDN AbortController](https://developer.mozilla.org/en-US/docs/Web/API/AbortController)。较新 API 按目标运行时核对支持，示例各自独立。

## 四、面试题与答案

<a id="c12-01"></a>

### C12-01 [P0·编码] 实现最多N个任务并发并保留每项结局。

**回答：** 下例在worker中领取索引，await结束后继续补位，结果按输入索引存。处理同步throw与异步拒绝；取消后剩余未启动项标记cancelled。没有强制终止不响应signal的task，也没有无限流输入或每秒限速。

```js
async function pool(tasks, limit, { signal } = {}) {
  if (!Number.isInteger(limit) || limit < 1 || !Array.isArray(tasks) ||
      tasks.some(task => typeof task !== 'function')) throw new TypeError('invalid tasks or limit');
  const results = new Array(tasks.length);
  let cursor = 0;
  async function worker() {
    while (cursor < tasks.length) {
      const index = cursor++;
      if (signal?.aborted) {
        results[index] = { status: 'cancelled', reason: signal.reason };
        continue;
      }
      try {
        results[index] = { status: 'fulfilled', value: await tasks[index](signal) };
      } catch (reason) {
        results[index] = { status: 'rejected', reason };
      }
    }
  }
  await Promise.all(Array.from({ length: Math.min(limit, tasks.length) }, worker));
  return results;
}
console.log((await pool([() => 1, () => Promise.reject('x')], 1)).map(x => x.status));
// ['fulfilled','rejected']
```

**追问与回答：** 测试最大在途数、乱序完成、单项失败、空输入和取消后不再启动。

对应讲解：[任务函数与工作位](#k01)。

### C12-02 [P1·编码] 有限重试如何避免无限等待和取消失效？

**回答：** 下例限制尝试次数、要求显式shouldRetry、使用指数上限和随机抖动，并让退避等待响应signal。生产仍需总deadline、单次超时、Retry-After、日志和幂等协议；task必须协作取消。

```js
function delay(ms, signal) {
  return new Promise((resolve, reject) => {
    if (signal?.aborted) { reject(signal.reason); return; }
    const finish = () => { signal?.removeEventListener('abort', abort); resolve(); };
    const timer = setTimeout(finish, ms);
    function abort() { clearTimeout(timer); signal?.removeEventListener('abort', abort); reject(signal.reason); }
    signal?.addEventListener('abort', abort, { once: true });
  });
}
async function retry(task, {
  attempts = 3, baseDelay = 100, signal, shouldRetry = () => false
} = {}) {
  if (!Number.isInteger(attempts) || attempts < 1 || !Number.isFinite(baseDelay) || baseDelay < 0) {
    throw new TypeError('invalid retry budget');
  }
  for (let attempt = 1; ; attempt++) {
    if (signal?.aborted) throw signal.reason;
    try { return await task({ attempt, signal }); }
    catch (error) {
      if (signal?.aborted) throw signal.reason;
      if (attempt >= attempts || !shouldRetry(error)) throw error;
      const ceiling = Math.min(30000, baseDelay * 2 ** (attempt - 1));
      await delay(Math.random() * ceiling, signal);
    }
  }
}
```

**追问与回答：** 退避只是一部分，写操作结果不明时优先查询状态，不能把所有异常都再次执行。

对应讲解：[重试、退避、抖动与幂等](#k03)。

<a id="c12-03"></a>

### C12-03 [P0·原理] Promise.race超时为什么没停请求？

**回答：** race只选择最先定局的结果，不拥有底层任务的通用停止能力。需要把取消信号传入支持的API，并清理超时资源；服务器已经完成的操作也不能由前端abort自动撤销。

对应讲解：[取消、超时与失败结果](#k02)。

<a id="c12-04"></a>

### C12-04 [P1·工程取舍] 进行中去重与结果缓存有什么不同？

**回答：** 前者让同时的同key请求共享一份Promise，完成后可以立即删除；后者保存已完成数据并需时效与失效规则。key隔离、失败淘汰和多个消费者的取消策略都必须明确。

对应讲解：[限速、去重与缓存](#k04)。
