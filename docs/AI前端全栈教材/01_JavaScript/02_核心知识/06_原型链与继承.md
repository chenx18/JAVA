## 二、知识讲解

<a id="k01"></a>

### 1. prototype、[[Prototype]] 与 constructor

```js
function User(name) { this.name = name; }
User.prototype.say = function () { return this.name; };
const user = new User('A');
console.log(Object.getPrototypeOf(user) === User.prototype); // true
console.log(Object.getPrototypeOf(User) === Function.prototype); // true
```

两条关系不要混淆：

```text
user → User.prototype → Object.prototype → null
User → Function.prototype → Object.prototype → null
```

箭头等对象不必有自有prototype属性；普通对象也可人为定义同名属性。[[Prototype]]是内部关联，Object.getPrototypeOf用于读取；__proto__是历史兼容访问器，可能被遮蔽，无原型对象也不继承它。

constructor是通常从原型继承的普通属性，可以改写，不是new决定调用哪个函数的调度器。

<a id="k02"></a>

### 2. 属性的读、写、删除

```js
const base = { level: 1 };
const child = Object.create(base);
console.log(child.level); // 1
child.level = 2;
console.log(child.level, base.level); // 2 1
delete child.level;
console.log(child.level); // 1
```

读属性先看自身，找不到沿原型链找。对继承的可写数据属性赋值，通常在接收者上创建同名自有属性；删除自有属性后，原型值再次可见。继承的是setter或不可写属性时，写入规则不同，不能只用读规则解释赋值。

in沿原型链检查，Object.hasOwn只检查自身。多个实例共享原型方法可节省函数对象，但把可变数组放到原型上可能让实例共享本不该共享的状态。

<a id="k03"></a>

### 3. Object.create 与继承方案

Object.create(proto)创建一个以proto为原型的新对象，不执行proto所属的构造器。Object.create(null)建立无原型字典，也失去Object.prototype的方法。

| 方案 | 能力 | 问题 |
| --- | --- | --- |
| Child.prototype=new Parent() | 连到父原型 | 执行父构造器，原型可能带共享引用状态 |
| Parent.call(this,...) | 初始化自己的父字段 | 不连接父原型；不能用来调用class |
| 二者组合 | 字段和方法都有 | 父构造器可能执行两次，产生冗余状态 |
| 借构造+Object.create | 独立实例数据与独立子原型 | 还需单独考虑静态链 |
| class extends | 语言支持继承及构造流程 | 仍需理解初始化、super和共享行为 |

不要直接Child.prototype=Parent.prototype：这让父子使用同一个对象，修改子方法会污染父类型。

<a id="k04"></a>

### 4. 寄生组合示例与两条链

```js
function Parent(name) { this.name = name; this.items = []; }
Parent.prototype.say = function () { return this.name; };
function Child(name) { Parent.call(this, name); }
Child.prototype = Object.create(Parent.prototype);
Object.defineProperty(Child.prototype, 'constructor', {
  value: Child, writable: true, configurable: true
});
const a = new Child('A'), b = new Child('B');
a.items.push(1);
console.log(a.say(), b.items.length, a instanceof Parent); // A 0 true
```

构造调用负责每个实例的独立字段，原型关联负责方法共享。上面没有把Child本身的原型连到Parent，所以不是完整静态继承。class extends通常同时建立Child→Parent与Child.prototype→Parent.prototype两条关系。

修改constructor只恢复普通标识属性，不会自动补静态链，也不会改变构造能力。

<a id="k05"></a>

### 5. 原型的边界与安全

instanceof默认判断原型关系，跨realm和原型改写都会影响结果；它不证明对象一定经过某构造器初始化。Object.create(SomeClass.prototype)可能通过instanceof，却没有类的私有字段品牌。

频繁改变运行中对象的原型会增加推理与优化成本。合并外部路径时更要限制__proto__/constructor/prototype等危险写入，避免污染共享原型。代码复用也可通过组合完成，不必为所有对象建立深继承树。

<a id="summary"></a>

## 三、知识小结

原型题先画关系图，再沿具体操作推导。实例字段保证独立，原型方法用于共享；读、写、删是不同规则；实例链和静态链必须分开看。

参考：[MDN 继承与原型链](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Inheritance_and_the_prototype_chain)。较新 API 按目标运行时核对支持，示例各自独立。

## 四、面试题与答案

<a id="c06-01"></a>

### C06-01 [P0·原理] prototype与对象原型有什么区别？

**回答：** prototype是构造函数等对象上的普通属性，一般用于提供新实例原型；对象自己的[[Prototype]]是内部查找关联。User.prototype与Object.getPrototypeOf(User)通常不是同一个对象。

对应讲解：[prototype、[[Prototype]] 与 constructor](#k01)。

<a id="c06-02"></a>

### C06-02 [P0·原理] 给实例赋同名属性会修改原型吗？

**回答：** 对继承的普通可写数据属性，赋值通常在实例上建立自有遮蔽属性，原型不变；删除自有后又可看到原型值。但setter和不可写描述符等有额外规则，需要看具体属性定义。

对应讲解：[属性的读、写、删除](#k02)。

<a id="c06-03"></a>

### C06-03 [P0·原理] Child.prototype=Parent.prototype为什么危险？

**回答：** 它不是创建继承层，而是共享同一个原型对象，给子类型增加或覆盖方法会影响父类型。Object.create生成独立子原型并连接父原型，才能分别保存子行为。

对应讲解：[Object.create 与继承方案](#k03)。

<a id="c06-04"></a>

### C06-04 [P1·编码] 寄生组合继承各部分负责什么？

**回答：** Parent.call在一般function构造器场景初始化独立字段；Object.create连接共享方法且不额外调用父构造器；修复constructor只是普通反向标识。还要单独说明静态继承未必实现，以及class不能用call借构造。

对应讲解：[寄生组合示例与两条链](#k04)。

<a id="c06-05"></a>

### C06-05 [P1·原理] class只是完全等价的语法糖吗？

**回答：** 继承基础仍是原型关联，但class有默认严格模式、必须构造调用、方法不可枚举、super、字段初始化和私有品牌等规则，不等于把任意旧function写法换个外观。

对应讲解：[寄生组合示例与两条链](#k04)。
