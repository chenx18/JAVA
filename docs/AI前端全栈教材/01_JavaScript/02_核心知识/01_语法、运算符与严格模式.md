# 01 语法、运算符与严格模式

## 二、知识讲解

<a id="k01"></a>

### 1. 表达式、语句与求值顺序

表达式产生值，如a+1、函数调用、赋值；语句组织声明和控制流，如if、for、return、throw。优先级决定表达式怎样分组，不等于有副作用的子表达式任意重排。

```js
const order = [];
function read(name, value) { order.push(name); return value; }
const value = read('a', 1) + read('b', 2) * read('c', 3);
console.log(order, value); // ['a','b','c'] 7
```

乘法先结合，但函数调用仍按表达式求值规则从左到右进行。推导复杂题时先补括号，再逐步记录调用与赋值，不能只背运算符优先级表。

++i先更新再产生新值，i++产生旧值并更新；混进多层赋值会降低可读性。逗号运算符依次求值并返回最后一项，也可能丢掉属性引用的接收者语义。

<a id="k02"></a>

### 2. 运算符分类与短路

| 类别 | 常见语法 | 需要关注 |
| --- | --- | --- |
| 算术 | + - * / % ** | +可能拼接，%是余数，BigInt规则另看 |
| 相等/关系 | == === != !== < <= > >= in instanceof | 转换、属性链、NaN、原型关系 |
| 逻辑 | &&、\|\|、??、! | 短路返回操作数；!返回Boolean |
| 赋值 | =、+=、&&=、\|\|=、??= | 逻辑赋值只在需要时写入，左侧引用按规则求值一次 |
| 一元 | typeof、void、delete | 类型查询、求值后返回undefined、删除属性 |
| 位运算 | &、\|、^、~、<<、>>、>>> | Number通常转32位，BigInt支持范围不同 |
| 条件/访问 | condition?a:b、?.、[] | 只执行被选分支；可选链只检查空值 |

```js
let count = 0;
console.log(count || 10, count ?? 10); // 10 0
let value = null;
value ??= 5;
console.log(value); // 5
```

??与&&/||不加括号混合会产生语法错误；?.不能作为普通赋值目标。obj?.a.b只在obj为空时短路，若obj存在但a为空仍可能报错；括号也可能结束连续可选链。未声明变量missing?.x仍会报ReferenceError。

<a id="k03"></a>

### 3. 控制流与遍历协议

if判断真值；switch用严格匹配，case未break会继续执行后续语句。for/while/do...while管理循环，break退出当前目标结构，continue跳到下一次迭代，return结束当前函数。

for...in枚举可枚举字符串属性，可能含继承项；for...of读取迭代协议中的值。Object.entries配for...of适合自有可枚举字符串键值。forEach是方法调用，回调里的return不会退出外层函数，也不能直接用break穿过函数边界。

```js
const obj = Object.create({ inherited: 1 });
obj.own = 2;
const keys = [];
for (const key in obj) keys.push(key);
console.log(keys); // ['own','inherited']
console.log(Object.keys(obj)); // ['own']
```

需要串行await或可中断遍历时，显式for...of往往更合适；需要并发时先定义任务启动与等待策略。label可用于有标签的break/continue，但不应代替清楚的函数划分。

<a id="k04"></a>

### 4. 解构、rest 与 spread

解构按结构提取值；默认值只在取到undefined时启用。对象解构从属性读取，可触发getter；数组解构消费迭代器，而不只是复制数字索引。

rest负责收集剩余内容，spread负责展开内容，外观相同但所在语法位置决定规则。函数rest得到数组；数组/调用spread要求可迭代；对象spread复制自有可枚举字符串/Symbol属性值，属于浅复制。

```js
const { name = 'guest', ...rest } = { name: null, id: 1 };
console.log(name, rest.id); // null 1
const [head, ...tail] = new Set([1, 2, 3]);
console.log(head, tail); // 1 [2,3]
```

对null/undefined直接做对象解构会失败；解构默认值不是结构校验。对象spread能处理一些原始值，但不代表可以对任意值安全解构所有字段。

<a id="k05"></a>

### 5. 严格模式、ASI 与兼容性

经典脚本或简单形参函数可通过'use strict'启用严格模式；ESM和class内部默认严格。它使部分静默失败变为错误，禁止隐式创建全局变量和with等行为，并使普通独立调用保留undefined的this而非替换成全局对象。严格性看函数自身代码，不只看调用方。

ASI按语法条件插入分号，不是每换行都结束语句。return后换行会返回undefined；下一行以(、[等开头时可能继续上一表达式。

```js
function result() {
  return
  { value: 1 };
}
console.log(result()); // undefined
```

现代语法能被构建器解析，不等于目标环境有对应API。语法转译、polyfill、浏览器版本和宿主能力应分别检查。动态eval/new Function还受到作用域、CSP与注入风险约束。

## 三、知识小结

输出题按“语法分组→求值顺序→短路路径→副作用→环境规则”分析。日常代码用括号、清晰控制流和输入校验表达意图，不靠读者猜隐式转换或ASI。

参考：[MDN 表达式与运算符](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Expressions_and_operators)；[MDN 严格模式](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Strict_mode)。较新 API 按目标运行时核对支持，示例各自独立。

## 四、面试题与答案

<a id="c01-01"></a>

### C01-01 [P0·原理] 优先级高是不是先调用对应函数？

**回答：** 优先级决定运算如何结合，但子表达式仍按语言规定求值。a()+b()*c()里a、b、c通常依次调用，随后结合乘法再加法；不能把乘法优先误认为b必须先于a调用。

对应讲解：[表达式、语句与求值顺序](#k01)。

<a id="c01-02"></a>

### C01-02 [P0·基础] &&、||、??都返回Boolean吗？

**回答：** 不是，它们返回短路选中的操作数。&&在左值为假时返回左值，||在左值为真时返回左值，??只在null/undefined时选择右侧。要Boolean可显式转换，但要先确定业务缺失值规则。

对应讲解：[运算符分类与短路](#k02)。

<a id="c01-03"></a>

### C01-03 [P0·基础] for...in和for...of的本质区别是什么？

**回答：** 前者枚举可枚举字符串属性名并可能涉及继承；后者消费迭代协议的值。数组业务遍历通常用for...of，普通对象的自有键值可用Object.entries；不能把in当数组元素遍历的同义词。

对应讲解：[控制流与遍历协议](#k03)。

<a id="c01-04"></a>

### C01-04 [P0·原理] rest和spread有什么区别，是否都是深拷贝？

**回答：** rest收集剩余参数或属性，spread按语法位置展开迭代值或复制属性。复制容器通常只分离外层，嵌套对象引用仍共享，不是深拷贝。

对应讲解：[解构、rest 与 spread](#k04)。

<a id="c01-05"></a>

### C01-05 [P1·原理] 严格模式与ASI会怎样改变结果？

**回答：** 严格模式改变部分非法操作和this行为，ESM默认启用；ASI按语法插入分号，return后换行可能提前结束返回。判断时先明确脚本/模块和函数严格性，再解释具体语句。

对应讲解：[严格模式、ASI 与兼容性](#k05)。
