## 二、知识讲解

<a id="k01"></a>

### 1. ESM：模块作用域与静态依赖

export公开接口，import声明依赖，模块有自己的作用域且默认严格模式。静态import位于顶层，便于在执行正文前建立依赖图；具名导出按名称匹配，default导出由导入方选择本地名称。

下面是两个文件，使用node app.mjs运行，不要拼成一个代码块：

```js
// counter.mjs
export let count = 0;
export function increase() { count++; }
```

```js
// app.mjs
import { count, increase } from './counter.mjs';
const snapshot = count;
console.log(count); // 0
increase();
console.log(count, snapshot); // 1 0
```

模块导入通常共享同一模块实例的执行结果，但“同一实例”有解析URL、缓存、realm和打包副本等边界，不等于整个分布式系统的单例。

<a id="k02"></a>

### 2. Live binding 与 CommonJS 导出

ESM导入是对导出绑定的只读视图，导出方改变export let后导入方可见；导入方不能直接重赋导入绑定。对象属性是否可改是另一问题，绑定只读不等于对象深不可变。

CommonJS用require/module.exports在运行时加载。require取得module.exports当时的值，若是对象，多方可共享其引用；解构出的原始值则是当时的值，不是ESM live binding。

```js
// counter.cjs
exports.count = 0;
exports.increase = () => { exports.count++; };
```

exports最初是module.exports的别名，exports={}只改局部变量，不自动替换module.exports。Node根据文件扩展名和package.json type决定相关模式；互操作支持依版本，不能一句“一个同步一个异步”解释所有情况。

<a id="k03"></a>

### 3. 动态 import、顶层 await 与失败

import(specifier)是表达式，返回模块命名空间的Promise，可放在条件或交互中按需加载。构建器常据此分包，但最终能否分析动态路径、怎样生成chunk取决于工具。

页面、图表和编辑器等非首屏能力可懒加载，同时要处理下载失败与版本失配。发布后旧页面请求被删除chunk可能失败，不能靠无限reload恢复，应有缓存/版本保留和受控提示策略。

顶层await可让模块初始化等待异步结果，同时影响依赖该模块的求值进度。不要把网络不稳定初始化放在所有页面必经模块而忽略启动失败。

<a id="k04"></a>

### 4. 循环依赖的读取时机

ESM会先建立关联再求值，循环本身不必然非法；关键是读取时绑定是否初始化。以下两文件可工作：

```js
// a.mjs
import { readA } from './b.mjs';
export const value = 'ready';
console.log(readA()); // ready
```

```js
// b.mjs
import { value } from './a.mjs';
export function readA() { return value; }
// 若在这里顶层读取value，a的const尚未初始化，会触发TDZ。
```

readA函数体直到a初始化value后才执行。CommonJS循环常暴露未完成exports对象，不可用同一结论概括。解决复杂循环应抽公共模块、改变依赖方向或明确延迟读取，而不是任意加timer掩盖。

<a id="k05"></a>

### 5. Tree Shaking、代码分包与安全边界

Tree Shaking关注“未使用代码能否安全删除”，分包关注“仍需要的代码何时加载”。ESM静态结构便于分析，但删除还依赖副作用信息。

样式导入、全局注册和初始化代码可能没有被引用的导出却有必须保留的行为。错误标记sideEffects:false可能删掉这些行为；应检查实际构建产物、网络加载与功能验证，而非只看源码用了export。

前端构建环境变量若进入产物就是可公开读取的数据。文件名叫secret.js或放在.env并不会保密，长期服务密钥应留在受控服务端。

<a id="summary"></a>

## 三、知识小结

模块回答按“作用域与依赖→导出值如何观察→加载与求值→循环时机→副作用与产物”展开。Live binding、共享对象引用和数值快照是三件不同的事。

参考：[MDN Modules](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules)。较新 API 按目标运行时核对支持，示例各自独立。

## 四、面试题与答案

<a id="c14-01"></a>

### C14-01 [P0·原理] ESM和CommonJS主要区别是什么？

**回答：** ESM用静态import/export关联模块，导入是只读live binding，便于提前分析；CommonJS用运行时require/module.exports取得导出值，对象可以共享引用。还要考虑模块作用域、缓存、加载环境与版本互操作，不能只背引用/值拷贝。

对应讲解：[Live binding 与 CommonJS 导出](#k02)。

<a id="c14-02"></a>

### C14-02 [P0·原理] 为什么snapshot不随导出count变化？

**回答：** 导入count是对导出绑定的视图，但const snapshot=count在执行那一刻保存了数值。以后导出count变化，不会重新执行这次赋值。直接读取导入绑定才观察最新值。

对应讲解：[ESM：模块作用域与静态依赖](#k01)。

<a id="c14-03"></a>

### C14-03 [P1·原理] 循环依赖为何有时不报错？

**回答：** 取决于读取时机。绑定可先建立而尚未初始化，顶层提前读取const触发TDZ；函数体延迟到初始化后读取则可正常。要用两个模块的执行路径证明，不能只看依赖图有环就判错。

对应讲解：[循环依赖的读取时机](#k04)。

<a id="c14-04"></a>

### C14-04 [P1·工程取舍] 使用ESM就一定Tree Shaking成功吗？

**回答：** 不一定。静态结构只提供分析基础，构建器还要判断使用关系和副作用。错误的副作用配置可能删掉必须执行的注册或CSS，应该检查产物与实际运行。

对应讲解：[Tree Shaking、代码分包与安全边界](#k05)。

<a id="c14-05"></a>

### C14-05 [P1·工程取舍] 动态import的风险如何处理？

**回答：** 延迟加载降低首屏负担，但增加交互时等待和加载失败路径。要有loading/降级/重试，处理发布后chunk失效，不把所有失败变成无限刷新。

对应讲解：[动态 import、顶层 await 与失败](#k03)。
