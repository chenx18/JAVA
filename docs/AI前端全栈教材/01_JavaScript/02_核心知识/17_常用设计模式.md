## 二、知识讲解

<a id="k01"></a>

### 1. 观察者与发布订阅

观察者通常由被观察对象维护订阅者并直接通知；发布订阅通常通过事件通道按主题连接双方。不同资料术语可能交叉，描述实际依赖关系比争名字重要。

事件通道降低直接对象依赖，却引入主题、载荷和生命周期的隐式契约。全局bus可能造成难追踪调用链、跨页面串事件和监听泄漏；局部组件交互优先采用显式props/events等结构。

要说明注册顺序、重复listener是否去重、异常是否中断后续监听，以及发射过程中增删监听的语义。

<a id="k02"></a>

### 2. EventEmitter、once 与重入

once必须在调用用户回调前取消自身订阅，否则回调内部再次emit时会重复进入。同步事件系统同样有重入，不需要多线程。

文末实现采用Set对同一listener去重；emit按开始时的快照逐个调用，新增监听不参与本轮，快照内后来被移除的监听仍可能本轮执行；listener抛错会中断本轮并向调用方传播。这个契约需要文档和测试，不应让实现细节变成隐含承诺。

如果希望隔离监听错误或支持async监听，应另定义错误汇总与等待策略，而不是悄悄吞掉所有异常。

<a id="k03"></a>

### 3. 策略、工厂、适配器与装饰

| 模式 | 主要变化点 | 例子 |
| --- | --- | --- |
| 策略 | 同一目标的不同算法 | 运费/校验规则按类型选择 |
| 工厂 | 创建哪个对象及如何初始化 | 根据配置创建存储客户端 |
| 适配器 | 不同接口如何统一 | 把不同请求库错误转为领域错误 |
| 装饰 | 保持接口并附加行为 | 日志、计时、缓存包装 |

```js
const shipping = {
  normal: weight => weight * 2,
  express: weight => weight * 4
};
function quote(type, weight) {
  if (!Object.hasOwn(shipping, type) || !Number.isFinite(weight) || weight < 0) throw new Error('invalid');
  return shipping[type](weight);
}
console.log(quote('express', 3)); // 12
```

只有两个简单稳定分支时，直接if可能更清楚；多实现持续扩展、需要替换与单测时抽象才更有价值。适配器统一接口时不能丢掉取消、鉴权、费用或错误等关键差异。

<a id="k04"></a>

### 4. 单例、组合与状态机

模块实例可提供共享对象，但不自动跨iframe、Worker、不同打包副本或进程唯一。SSR模块可能被多次请求共享，把当前用户token放模块变量可能造成跨用户污染，应创建请求作用域上下文。

组合把行为通过明确接口协作；继承表达稳定is-a关系。状态机则描述允许的状态变化，避免loading、success、error多个布尔值同时矛盾。

```js
const allowed = {
  idle: ['loading'], loading: ['success', 'error', 'cancelled'],
  success: ['loading'], error: ['loading'], cancelled: ['loading']
};
function transition(state, next) {
  if (!allowed[state]?.includes(next)) throw new Error('illegal transition');
  return next;
}
console.log(transition('loading', 'success')); // success
```

真实请求还需requestId与事件顺序，合法状态名不保证消息属于当前请求。模型返回组件名称时用受控注册表和参数schema；不能把动态工厂变成执行任意模型代码的入口。

## 三、知识小结

按变化点记模式：事件解耦、策略替换、工厂创建、适配转换、装饰附加、状态机约束。每次选择都补上契约、资源清理和复杂度代价。

参考：[MDN JavaScript Guide](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide)；[Front End Interview Handbook](https://www.frontendinterviewhandbook.com/javascript-questions)。较新 API 按目标运行时核对支持，示例各自独立。

### C17-01 [P1·原理] 观察者和发布订阅的差异是什么？

**回答：** 主要是依赖关系是否经事件通道解耦，而不是谁一定同步异步。两者都需定义载荷、通知顺序、异常和退订，事件总线还可能让依赖隐式化。

对应讲解：[观察者与发布订阅](#k01)。

<a id="c17-02"></a>

### C17-02 [P1·编码] 实现on、off、once、emit并处理once重入。

**回答：** 下例先退订once再调用用户函数；emit遍历快照；相同listener在同类型内去重。同步监听异常向外传播，不包含异步等待、错误隔离或模式匹配主题。

```js
class Emitter {
  constructor() { this.events = new Map(); }
  on(type, listener) {
    if (typeof listener !== 'function') throw new TypeError('listener required');
    let set = this.events.get(type);
    if (!set) this.events.set(type, set = new Set());
    set.add(listener);
    return () => this.off(type, listener);
  }
  off(type, listener) {
    const set = this.events.get(type);
    if (!set) return;
    set.delete(listener);
    if (set.size === 0) this.events.delete(type);
  }
  once(type, listener) {
    if (typeof listener !== 'function') throw new TypeError('listener required');
    const wrapped = (...args) => {
      this.off(type, wrapped);
      listener(...args);
    };
    return this.on(type, wrapped);
  }
  emit(type, ...args) {
    for (const listener of [...(this.events.get(type) ?? [])]) listener(...args);
  }
}
const bus = new Emitter();
let count = 0;
bus.once('tick', () => { count++; bus.emit('tick'); });
bus.emit('tick');
console.log(count); // 1
```

**追问与回答：** 测试once回调再次emit、unsubscribe重复调用、监听增删和抛错中断行为。

对应讲解：[EventEmitter、once 与重入](#k02)。

<a id="c17-03"></a>

### C17-03 [P1·工程取舍] 什么时候用策略或适配器，什么时候保留if？

**回答：** 当变化重复出现、接口共性明确且需要独立替换测试时，策略/适配器有价值；简单稳定分支不必提前抽层。选择应说明减少了什么变化成本，以及是否丢失底层关键语义。

对应讲解：[策略、工厂、适配器与装饰](#k03)。

<a id="c17-04"></a>

### C17-04 [P1·工程取舍] 模块单例在SSR中为什么危险？

**回答：** 模块可跨请求复用，保存用户级可变状态可能被另一个请求读写。共享服务和配置与请求态应分开，用户上下文按请求创建；单例也不代表跨所有运行环境唯一。

对应讲解：[单例、组合与状态机](#k04)。

<a id="c17-05"></a>

### C17-05 [P1·原理] 状态机比几个Boolean好在哪里？

**回答：** 它把互斥状态和合法转换显式化，减少loading与success等矛盾组合。但还需验证事件所属请求和顺序，只有状态名并不防止旧请求把新状态覆盖。

对应讲解：[单例、组合与状态机](#k04)。
