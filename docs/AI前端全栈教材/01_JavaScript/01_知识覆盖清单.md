# JavaScript 知识覆盖清单

这份清单列出各章知识范围和对应练习。两套正文均已写出；章节覆盖、解释深度和示例行为分别检查，不用篇数或代码检查代替教学质量判断。

章节保持两个专题。每个主题内部按知识关系组织；API 多的类型用分组表和有代表性的例子，机制类主题用执行过程、对比和反例。面试题与答案统一放在各篇文末。

## API 章节的验收要求

String、Array、Object 等章节不能只列方法名称。每个 API 至少明确：所属对象、调用形式、重要参数/默认值、返回值、是否改变原值、关键边界。功能相近的方法一起比较，容易误用的方法给可运行例子。

- String：覆盖 at/charAt/charCodeAt/codePointAt，includes/indexOf/lastIndexOf/startsWith/endsWith，slice/substring，split，replace/replaceAll，search/match/matchAll，concat/repeat/padStart/padEnd，trim 系列，大小写和本地化大小写，localeCompare/normalize，fromCharCode/fromCodePoint/raw，isWellFormed/toWellFormed 和迭代。substr、HTML 包装方法归入历史兼容区。
- Array：覆盖构造、isArray/from/of/fromAsync；增删改与填充、查找、遍历、映射、筛选、归并、排序反转、截取拼接、扁平化、迭代器；明确新复制方法和旧变异方法的区别，单列空位、相等规则及异步边界。groupBy 说明它属于 Object/Map 静态方法。
- Object：覆盖 assign/create/entries/values/keys/fromEntries/hasOwn/is，描述符和属性定义，原型读取设置，扩展/密封/冻结及检查；单列 Symbol 键、自有与继承、可枚举与不可枚举。
- Number/Math/Date/RegExp/集合/Intl：同样按功能族覆盖。低频 API 可以用准确的查阅表呈现，不强行把每个冷门方法包装成一道“必考题”。

较新 API 在正文中说明目标运行时支持及必要降级。提案中的接口与已经标准化的接口分开，不把年份等同于普遍可用。

## 机制章节的验收要求

每个主要机制至少能沿以下路径读通：

1. **定义**：给出准确、可复述的概念，解释必要术语。
2. **原因**：说明语言规则或运行机制，而不是只报结果。
3. **示例**：用小而完整的例子逐步推导，标明输出和环境。
4. **边界**：变更一个条件，说明为什么结果不同。
5. **应用**：用普通前端业务说明用途，不把所有基础题强行套成 AI 场景。
6. **对应题目**：基础问法、机制追问、适当的输出/编码/场景题均提供答案；答案不能以“见上文”代替解释。

不要求每小节机械复制六个小标题，以阅读是否连贯、知识是否实际解释清楚为准。

## 学习范围与深度

- **优先讲透**：值与引用、转换比较、String/Array/Object 常用行为、作用域、函数与 this、闭包、原型、Promise、async/await、事件循环、模块、错误与内存。
- **高级前端继续深入**：协议与边界、并发控制、代理依赖、性能证据、模块副作用、资源所有权、竞态与可靠性，以及代码实现的支持范围。
- **按岗位扩展**：Node 服务端细节、引擎 JIT/GC 专项、完整 Promise 实现、共享内存并发、最新资源管理语法。涉及这些内容会说明延伸边界，不用几句概要冒充完整专项。
- **其他系列负责**：TypeScript、框架源码、CSS、HTTP/浏览器安全、构建工具细节、系统设计和项目经历。JavaScript 教材不能独自代表高级前端面试的全部范围。
- **2026/2027**：以可查证的岗位与标准支持决定补充内容；未来趋势只作有依据的观察，不标虚构的“必考概率”。

## 质量检查

编辑验收检查知识点是否真的展开、例子是否能解释规则、题目是否有回答与追问。技术检查验证例子输出、代码语法、目录与锚点链接。两类检查分别报告，技术检查通过不代替内容审核。
