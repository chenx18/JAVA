## 二、各知识点详细解释

### 1. GC 看的是可达性

最重要的概念不是“变量作用域结束就回收”，而是对象是否仍然从 GC Root 可达。

### 2. Mark and Sweep

抽象过程：

```text
从 GC Roots 出发
→ 标记可达对象
→ 未标记对象成为回收候选
→ 清理/整理
```

现代 JS 引擎实际采用更复杂的分代、并发和增量策略。

### 3. WeakMap

WeakMap 的 key 不会因为被 WeakMap 引用而阻止相关对象被 GC，因此适合把元数据与对象生命周期绑定。

### 4. 内存泄漏

本质是：本应失去作用的数据仍然保持可达。

常见来源：

- 全局缓存无限增长
- 事件监听未清理
- 定时器未清理
- 闭包持有大对象
- DOM 与 JS 相互引用形成长期可达链

## 三、本章面试题与答案

### 题 1：什么是内存泄漏？

**答案：**

不是“内存使用多”就叫泄漏，而是程序继续持有不再需要的数据引用，使 GC 认为对象仍然可达，导致这些对象无法回收并持续累积。

### 题 2：WeakMap 为什么适合对象元数据？

**答案：**

WeakMap 的 key 是弱引用语义，不会仅仅因为存在于 WeakMap 中就阻止对象被回收。当对象生命周期结束时，其对应的弱映射也可以随之消失，因此适合缓存与对象绑定的附加信息。
