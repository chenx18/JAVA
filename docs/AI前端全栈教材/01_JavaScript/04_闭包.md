## 二、各知识点详细解释

### 1. 闭包是什么

闭包可以理解为：函数创建时保留了对其词法环境的访问能力，即使函数在定义它的外层作用域退出后，仍可以访问外层绑定。

```js
function createCounter() {
  let count = 0
  return () => ++count
}

const next = createCounter()
next() // 1
next() // 2
```

`createCounter` 已经执行结束，但 count 仍被返回的函数访问。

### 2. 为什么闭包存在

如果函数只能访问“当前栈上的局部变量”，那么返回内部函数后就无法继续访问外层状态。闭包提供的是词法环境与函数之间的持续关联。

### 3. 闭包不是“把变量复制进函数”

这是错误理解。闭包保留的是访问外层绑定的能力。多个闭包还可以共享同一外层环境：

```js
function create() {
  let x = 0
  return [() => ++x, () => ++x]
}
```

两个函数操作的是同一个 x。

### 4. 闭包与内存

当某个环境仍被可达对象引用时，其中需要的数据就不能被回收。因此闭包可能延长变量生命周期，但“有闭包”不等于“必然内存泄漏”。真正的泄漏是本应释放的数据仍保持不必要的可达性。

## 三、本章面试题与答案

### 题 1：什么是闭包？

**答案：**

闭包是函数与其词法环境之间的持续关联。内部函数即使离开外层函数的调用过程，仍能访问定义时所在作用域中的变量。它可以用于私有状态、函数工厂、缓存和回调等场景。

### 题 2：闭包为什么可能导致内存问题？

**答案：**

闭包可能让原本局部作用域的数据继续保持可达，从而延长生命周期。如果再叠加定时器、事件监听器或长期缓存，可能导致大量对象一直无法回收。真正需要关注的是不必要的引用链，而不是简单把闭包当成泄漏。

### 题 3：循环绑定为什么经常考闭包？

**答案：**

因为回调执行时读取的变量绑定可能不是当初循环迭代的“值副本”。var 的单一函数作用域与 let 的每次迭代绑定模型不同，因此会出现经典循环闭包问题。
