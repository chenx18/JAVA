# 11 Agent Memory 与上下文恢复

当前上下文、任务checkpoint、用户偏好和知识库不是同一种记忆。先按用途、权威来源和保留周期分类，再决定怎样保存与检索。

## 二、知识讲解

<a id="k01"></a>

### 1. 四类信息

| 信息 | 用途 | 权威与周期 |
| --- | --- | --- |
| 当前对话上下文 | 支持本次推理 | 受token窗口限制 |
| 任务状态/checkpoint | 恢复执行流程 | 服务端持久化版本与状态 |
| 用户偏好/事实 | 跨会话个性化 | 来源、有效期与用户控制 |
| 外部知识库 | 提供任务证据 | 文档版本、权限与检索 |

把聊天摘要叫“长期记忆”不会自动让它正确或可靠。任务是否已执行由权威状态决定，不以模型回忆为准。

<a id="k02"></a>

### 2. 写入与更新规则

记忆写入应有来源、时间、适用范围和置信/验证信息，区分用户明确表达与模型推断。互相冲突的事实不能直接追加后全塞回上下文，需要覆盖、过期或待确认策略。

敏感偏好和个人数据按产品权限与保留规则处理，用户能查看、纠正或删除必要信息。不要把偶然一次行为推成永久画像，也不要让工具输出随意改写高信任规则。

<a id="k03"></a>

### 3. 摘要、检索与上下文预算

摘要可压缩历史，但可能丢失细节、否定和例外，应保留原文指针或可恢复记录。向量检索找到语义相近内容不代表其当前有效或有权访问，需结合metadata、时间和权限过滤。

每次调用按任务挑选相关信息，给工具结果与历史设置大小上限。长期存储容量和单次上下文窗口是两件事，不能因为数据库存了全部历史就全部发送。

<a id="k04"></a>

### 4. 恢复、隔离与验证

跨会话恢复任务时读取taskId/checkpoint，而不是让模型从摘要猜工具是否已经执行。并发会话需要租户/用户/任务隔离，避免旧偏好或结果污染另一个用户。

测试过期、冲突、删除、权限撤销、摘要错误和恢复后的重复动作。记忆质量评估关注相关性、准确性和不该召回的数据，而不只看召回数量。

<a id="summary"></a>

## 三、知识小结

记忆按上下文、任务状态、用户信息和知识库分层。存储、检索、写入授权和更新策略共同决定可信度，模型叙述不能取代执行事实。

参考：[JSON Schema](https://json-schema.org/understanding-json-schema/)；[MCP Specification](https://modelcontextprotocol.io/specification/2026-07-28)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="ai11-01"></a>

### AI11-01 [P0·基础] Memory与RAG是一回事吗？

**回答：** 不完全相同，RAG强调检索外部证据，Memory还包括任务状态和跨会话用户信息。可共享技术存储，但权威来源、更新和生命周期不同。

对应讲解：[四类信息](#k01)。

<a id="ai11-02"></a>

### AI11-02 [P1·原理] 摘要能否作为所有历史的可靠替代？

**回答：** 不能，它可能遗漏条件和细节。需按重要性保留原文指针或权威记录，恢复执行尤其应读持久任务状态，而非让模型从摘要猜。

对应讲解：[摘要、检索与上下文预算](#k03)。

<a id="ai11-03"></a>

### AI11-03 [P1·工程取舍] 用户偏好为什么不能无限追加？

**回答：** 可能过期、冲突、含敏感信息或只是推断。应有来源、适用范围、更新删除和用户控制，调用时只取相关内容。

对应讲解：[写入与更新规则](#k02)。

<a id="ai11-04"></a>

### AI11-04 [P1·工程取舍] 如何测试跨会话记忆？

**回答：** 覆盖租户隔离、权限撤销、过期冲突、删除生效、摘要误差和任务恢复，检查不该召回或重复执行的情况，而非只看记住了多少。

对应讲解：[恢复、隔离与验证](#k04)。
