# 14 RAG：摄取、检索与证据回答

RAG通过检索把外部证据提供给生成过程。可靠性取决于文档质量、检索、权限、上下文和回答核验，不能只把向量数据库接上就宣称消除幻觉。

## 二、知识讲解

<a id="k01"></a>

### 1. 离线摄取与在线问答

```text
摄取：文档 → 解析/OCR → 清洗 → 分块 → metadata/权限/版本
      → embedding → 索引

问答：用户与授权范围 → 查询处理 → 混合检索 → 重排
      → 选择证据并构造上下文 → 生成 → 引用/事实核验 → 回答
```

摄取与问答有不同延迟目标，文档解析和向量化可异步任务化。源文档、版本和chunk ID要可追踪，不把所有块只存成没有来源的一串文本。

<a id="k02"></a>

### 2. 分块、更新与删除

分块按标题、段落、表格或语义边界，大小与重叠取决于任务和token预算。太大降低定位精度，太小丢失上下文；重叠增加召回机会也增加成本和重复证据。

文档更新需使旧版本失效，删除和权限撤销需同步索引、缓存及引用可见性。使用内容hash和版本辅助幂等摄取，但不能只凭内容相同忽略租户和授权差异。

PDF/OCR、表格和代码的结构丢失可能比embedding模型选择更影响质量，解析阶段应有质量检查与失败报告。

<a id="k03"></a>

### 3. 检索、重排与权限

词法检索擅长精确术语、编号和名称，向量检索擅长语义改写，混合召回后可重排。topK、相似度阈值和重排模型需用任务集评估，不能通用固定值解决所有领域。

权限必须进入检索/候选与最终上下文检查，不能先把无权文档交给模型再要求它别泄露。缓存键同样需要授权范围。

没有足够证据时明确拒答、澄清或说明限制，不能为了每次回答都完整而补造细节。

<a id="k04"></a>

### 4. 引用、评估与微调区别

引用保留sourceId、段落/页码和版本，生成的引用要能定位且真的支持对应陈述。存在URL不等于证据充分；用户点击来源也需重新检查权限与当前版本。

评估分别看检索召回/相关性、证据覆盖、回答忠实度、引用准确性、拒答和成本。检索失败与生成误读要分开修。

RAG改变推理时提供的上下文，微调改变模型参数与行为。频繁更新且要可追溯权限的知识通常适合检索；微调也可服务领域任务，但不能代替实时数据授权和版本更新。

<a id="summary"></a>

## 三、知识小结

RAG是一条从文档到可核验证据的链路。解析、分块、版本、权限、检索和生成都可能失败；评估拆层，引用必须真实支持结论。

参考：[Microsoft RAG Overview](https://learn.microsoft.com/en-us/azure/search/retrieval-augmented-generation-overview)；[JSON Schema](https://json-schema.org/understanding-json-schema/)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="ai14-01"></a>

### AI14-01 [P0·原理] RAG为什么不能保证没有幻觉？

**回答：** 检索可能找错或缺证据，模型也可能误读或补造。需要检索质量、上下文筛选、引用核验和证据不足时的明确行为，而非只连接向量库。

对应讲解：[检索、重排与权限](#k03)。

<a id="ai14-02"></a>

### AI14-02 [P1·工程取舍] chunk大小怎样选择？

**回答：** 按文档结构、问题类型与token预算评估，太大难定位、太小丢上下文，重叠又有成本。用检索与回答指标验证，不机械固定每篇同一字数。

对应讲解：[分块、更新与删除](#k02)。

<a id="ai14-03"></a>

### AI14-03 [P0·原理] RAG和微调分别改变什么？

**回答：** RAG主要改变推理时可用证据，微调改变模型参数与行为。频繁更新、权限敏感且需追溯的数据不应仅靠训练记忆解决，二者可以配合但职责不同。

对应讲解：[引用、评估与微调区别](#k04)。

<a id="ai14-04"></a>

### AI14-04 [P1·工程取舍] 权限为什么要在检索阶段处理？

**回答：** 无权内容一旦进入模型上下文就已越过数据边界，不能只靠prompt不输出。候选、最终上下文和缓存都需授权范围，引用访问还要再次检查。

对应讲解：[检索、重排与权限](#k03)。

<a id="ai14-05"></a>

### AI14-05 [P1·工程取舍] 为什么RAG摄取与在线查询分开？

**回答：** 解析、分块和向量化耗时且需要重试，在线问答有低延迟要求。用版本和chunk/source ID关联两条链，异步摄取完成后发布可查询版本，并保留引用追溯。

对应讲解：[离线摄取与在线问答](#k01)。
