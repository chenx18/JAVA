# 10 Agent Workflow、并行与恢复

工作流把步骤输入输出、依赖和失败路径显式化。只有真正独立的工作才适合并行，状态与幂等让流程能在重试和断线后继续。

## 二、知识讲解

<a id="k01"></a>

### 1. 顺序、并行与路由

顺序用于后一步依赖前一步数据，并行用于独立且资源允许的步骤，路由根据输入选择流程分支，评审/修正循环用于有明确评价标准的迭代。

```text
输入验证 → 分类
               ├─ 简单查询 → 直接工具 → 结果
               └─ 研究任务 → 多源独立检索 → 去重/合并 → 证据检查 → 结果
```

并行不是把所有任务同时启动。设并发和费用上限，决定部分失败是否仍可输出，以及合并时如何处理冲突证据。存在写依赖或同资源修改的步骤需额外协调。

<a id="k02"></a>

### 2. 节点状态与稳定身份

每个节点有pending/running/succeeded/failed/cancelled等状态及稳定stepId，输入版本与输出可追踪。状态机限制合法转移，不能让旧worker结果覆盖新重试的状态。

工作流定义版本化，持久化实例记录使用了哪一版。部署后正在运行的任务需兼容或迁移，不能悄悄让旧checkpoint按完全不同节点定义继续。

<a id="k03"></a>

### 3. 重试、补偿与人工输入

重试针对可恢复错误并有预算，写动作必须幂等。跨系统无法简单原子回滚时，设计补偿或人工处理，不把“再调用一次反向接口”当总能撤销的事务。

需要人工输入时持久化提案、对象和参数摘要，恢复时检查是否仍有效、权限是否变化。已有授权在范围内使用，时间流逝不等于获得新批准。

子Agent或并行节点的输出仍是待验证材料，最终协调者负责合并与质量，不把多个模型同意当事实证明。

<a id="k04"></a>

### 4. 可观测性与测试

为任务和步骤建立trace/span，记录尝试次数、排队时间、工具/模型耗时与失败类别。敏感输入保留最小必要范围，能通过ID定位即可避免全文日志。

测试节点失败、重复投递、worker崩溃、并行部分成功、取消传播、人工输入过期和版本升级。流程图只是设计起点，恢复测试才能证明可运行。

<a id="summary"></a>

## 三、知识小结

工作流用依赖决定顺序，用预算限制并行，用状态和稳定ID管理恢复，用幂等和补偿处理副作用。人工输入与子Agent结果都需要明确契约。

参考：[JSON Schema](https://json-schema.org/understanding-json-schema/)；[MCP Specification](https://modelcontextprotocol.io/specification/2026-07-28)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="ai10-01"></a>

### AI10-01 [P0·工程取舍] 哪些步骤可以并行？

**回答：** 数据和副作用独立、权限与资源允许且合并规则清楚的步骤。并行需限制数量和成本，处理部分失败；共享资源写入不能无条件并发。

对应讲解：[顺序、并行与路由](#k01)。

<a id="ai10-02"></a>

### AI10-02 [P1·原理] 为什么重试要有stepId和版本？

**回答：** 同一步可能多次执行或收到迟到结果，稳定身份与尝试/状态版本能区分归属并防止覆盖。幂等记录还要保护真实副作用。

对应讲解：[节点状态与稳定身份](#k02)。

<a id="ai10-03"></a>

### AI10-03 [P1·工程取舍] 跨服务失败能否用数据库回滚解决？

**回答：** 普通本地事务不能覆盖所有远程动作，需幂等、outbox、补偿或人工处理。补偿也可能失败或不可完全逆转，应体现在状态与恢复流程。

对应讲解：[重试、补偿与人工输入](#k03)。

<a id="ai10-04"></a>

### AI10-04 [P1·工程取舍] 怎样验收一个Agent工作流？

**回答：** 除正常路径外测试崩溃恢复、重复投递、部分失败、取消、人工输入与版本变化，并查看真实状态和trace，不能只看流程图或一次演示。

对应讲解：[可观测性与测试](#k04)。
