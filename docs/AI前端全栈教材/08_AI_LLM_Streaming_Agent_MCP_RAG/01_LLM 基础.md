# 01 LLM、Token 与应用能力边界

AI应用开发先把模型视为有输入预算、输出协议和失败边界的服务。需要理解生成与上下文，不必把模型训练数学当作第一个交付门槛。

## 二、知识讲解

<a id="k01"></a>

### 1. 生成模型与不确定输出

许多主流语言模型根据上下文逐步生成token，输出体现训练和推理机制，不是查询一张保证正确的事实表。流畅、自信或符合格式都不能证明事实准确。

应用需要定义目标：问答、提取、分类、代码辅助或工具决策，再用真实样本评估。相同prompt不保证每次输出完全一致，即使某些采样参数很低，模型版本、服务实现和其他条件仍可能影响结果。

模型擅长与任务适配是两件事，选型同时看质量、延迟、成本、上下文、模态、工具和结构化输出支持。

<a id="k02"></a>

### 2. Token 与上下文预算

token由对应tokenizer产生，不等于字符、汉字或单词。系统规则、用户输入、历史、工具schema、检索片段和输出预留都可能占用预算，具体计费和上下文规则依模型。

长窗口不等于长期记忆，也不保证模型在巨大输入中稳定利用全部关键信息。上下文要筛选、压缩并保留来源，不能无限把所有聊天历史追加进去。

估算token用于提前控制，最终usage与账单口径由供应商契约决定。图片、音频、推理或缓存等计数可能不同，不用一个字符比例当所有模型精确换算。

<a id="k03"></a>

### 3. 角色、参数与结构化结果

供应商会定义消息角色、指令层级和工具结果格式；应用应区分固定规则、用户请求和外部资料，不把检索文本升级为最高指令。不同协议的role名称不能随意互换。

temperature/top_p等控制某些采样行为，支持范围依模型；max输出预算影响长度和失败路径。不要把temperature=0解释成数学上绝对确定，也不要给不支持的模型机械传同一组参数。

结构化输出可约束格式或schema，但JSON可解析、schema合法、内容真实和操作被授权是不同层。拒绝、截断、未完成与工具调用都要有明确状态。

<a id="k04"></a>

### 4. 模型能力与产品验证

多模态输入增加文件类型、大小、授权和解析边界；上传文件可读不代表可以全量发送给任意供应商。模型给出引用格式也不代表引用确实支持结论。

建立任务样本、正确性标准、失败分类和人工抽检；分别观察事实质量、格式遵守、工具选择、成本和时延。产品可以允许不确定时追问或说明证据不足，而不是强迫每次输出一个确定答案。

模型版本更新时做回归，保留配置与评估记录；不把所有质量变化都归咎于prompt一句话。

<a id="summary"></a>

## 三、知识小结

模型是有预算和不确定性的能力组件。token管理上下文，schema管理结构，评估管理质量，程序和服务端管理权限与确定性业务。

参考：[JSON Schema](https://json-schema.org/understanding-json-schema/)；[MDN Fetch](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="ai01-01"></a>

### AI01-01 [P0·基础] Token为什么不是字符数？

**回答：** 它由模型对应tokenizer切分，语言、符号和编码都会影响，一个词或汉字不固定对应一个token。预算可估算，实际用量和计费按模型协议记录。

对应讲解：[Token 与上下文预算](#k02)。

<a id="ai01-02"></a>

### AI01-02 [P0·原理] 上下文窗口大是否意味着模型记住所有历史？

**回答：** 不意味着，窗口是一次调用可用容量，长期状态需存储再选取。长输入还可能降低相关信息利用，需要筛选、摘要和检索，而不是无限追加。

对应讲解：[Token 与上下文预算](#k02)。

<a id="ai01-03"></a>

### AI01-03 [P0·原理] 结构化输出是否保证答案正确？

**回答：** 它主要约束格式或schema，不能证明事实、引用、资源权限和业务状态。还需数据验证、证据检查及授权，截断和拒绝也要处理。

对应讲解：[角色、参数与结构化结果](#k03)。

<a id="ai01-04"></a>

### AI01-04 [P1·工程取舍] 怎样选择模型而不只看排行榜？

**回答：** 用目标任务样本评估质量、延迟、成本、上下文与工具能力，结合失败容忍度和数据要求。版本变化后回归，不把通用榜单直接等同产品收益。

对应讲解：[模型能力与产品验证](#k04)。

<a id="ai01-05"></a>

### AI01-05 [P0·原理] 模型表达流畅或temperature很低为何仍可能错误？

**回答：** 生成概率和语言流畅不等于事实查证，低采样参数也不保证跨版本/服务实现绝对确定。应按任务评估、提供证据和校验边界，不把自信语气当可靠性。

对应讲解：[生成模型与不确定输出](#k01)。
