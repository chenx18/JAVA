# 16 AI 应用的信任边界与安全

AI安全的关键是避免把语言输出直接升级为真实权限。用户输入、检索资料、工具结果和模型参数各有来源，执行层始终负责验证和授权。

## 二、知识讲解

<a id="k01"></a>

### 1. 直接与间接提示注入

用户输入可诱导模型偏离任务，外部网页、文档和工具结果也可能夹带指令。来源即使使用“系统提示”等字样，也不应提升成高信任规则。

分隔、来源标签和模型规则可帮助降低风险，但不能形成可靠执行沙箱。模型最终产生的工具参数依然是外部输入，程序不能因它看起来合理而跳过检查。

<a id="k02"></a>

### 2. 工具权限与数据范围

执行链应验证身份、工具白名单、schema、资源/租户归属、业务状态及必要授权。授予完成任务所需的最小能力，读取与写入权限分开，模型不能自行扩大scope。

URL抓取需防内部地址和重定向绕过的SSRF，文件操作限制根目录与路径，SQL工具采用受控查询/只读权限和资源限制，不能直接运行任意模型SQL。沙箱还需网络、文件、时间和内存限制，并按威胁模型测试。

<a id="k03"></a>

### 3. 输出、秘密与确认

前端渲染文本、Markdown、HTML、URL和图表各有安全边界；可信组件注册表仍需校验props和规模。供应商Key、数据库凭据和跨租户数据不应进入模型上下文或公开日志。

有外部副作用的动作应按产品授权规则展示具体对象、参数和影响，必要时确认；确认结果绑定提案版本，不能批准后换一套参数。已有授权范围内的正常步骤不必重复询问。

权限检查应在真正执行时再次核对，避免确认与执行之间资源或身份已变化。

<a id="k04"></a>

### 4. 测试、审计与恢复

测试恶意文档、工具参数篡改、重定向URL、越权资源、过大输出、重复调用和权限撤销。安全评估要观察是否实际执行或泄露，不只看模型口头说拒绝。

记录必要审计ID、动作和结果，保留期限与访问控制明确。故障和安全事件可撤销凭据、停用工具、回滚配置或恢复任务，不能只依赖改一句prompt。

模型层过滤、程序验证、后端授权、隔离和人工控制相互补充，不把某一种措施说成绝对安全。

<a id="summary"></a>

## 三、知识小结

来源不自动升级为指令，模型建议不自动成为授权。权限、schema、资源隔离和执行审计在程序边界落实，UI确认绑定具体动作和版本。

参考：[OWASP GenAI Security](https://genai.owasp.org/)；[MCP Security Guidance](https://modelcontextprotocol.io/specification/2026-07-28)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="ai16-01"></a>

### AI16-01 [P0·原理] Prompt Injection为什么不能只用prompt完全解决？

**回答：** 外部文本仍可能影响模型决策，自然语言规则不是强权限隔离。最终工具执行必须验证身份、参数和资源，限制能力并记录结果。

对应讲解：[直接与间接提示注入](#k01)。

<a id="ai16-02"></a>

### AI16-02 [P0·工程取舍] 模型生成SQL怎样安全接入数据？

**回答：** 优先受控查询工具、只读和租户权限、参数化及资源限制，不能给任意模型SQL全库执行权。解析通过也不证明查询有权或成本可控。

对应讲解：[工具权限与数据范围](#k02)。

<a id="ai16-03"></a>

### AI16-03 [P1·原理] 一次确认为什么还要绑定参数版本？

**回答：** 用户批准的是具体动作，之后若对象、参数或权限变化，旧确认不能自动授权新动作。执行前重新核对提案与资源状态，避免时序漏洞。

对应讲解：[输出、秘密与确认](#k03)。

<a id="ai16-04"></a>

### AI16-04 [P1·工程取舍] 安全测试应该看什么结果？

**回答：** 观察真实工具执行、数据访问和输出，而不是只看模型是否说了拒绝。覆盖间接注入、越权、秘密、重复和资源耗尽，并有审计与恢复方案。

对应讲解：[测试、审计与恢复](#k04)。
