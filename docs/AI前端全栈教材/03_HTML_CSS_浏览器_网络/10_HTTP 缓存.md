# 10 HTTP 缓存与版本更新

缓存回答两个问题：能否直接复用已有响应，以及不能直接复用时怎样验证。浏览器、代理和CDN可能各有缓存层，响应变化、用户隔离和更新策略要一起设计。

## 二、知识讲解

<a id="k01"></a>

### 1. 新鲜度与直接复用

Cache-Control:max-age表示响应可保持新鲜的时间，通常与Date/Age及缓存计算共同作用，不是简单从每次页面打开重新计时。s-maxage针对共享缓存，private限制共享缓存使用，public允许按规则共享。

```http
Cache-Control: public, max-age=31536000, immutable
```

这种长缓存适合带内容哈希、内容变化就换URL的静态资源，不适合会在同URL下频繁变化的入口HTML或用户私有接口。immutable减少新鲜资源的不必要验证，但不会替你实现版本发布。

<a id="k02"></a>

### 2. 条件请求与 304

```http
ETag: "resource-v3"
Last-Modified: Tue, 22 Sep 2026 00:00:00 GMT
```

客户端可带If-None-Match或If-Modified-Since验证已有响应。未变化时，GET/HEAD等场景可返回304，客户端结合缓存体与更新后的元数据使用。ETag可表达实体版本，Last-Modified通常受时间粒度等限制；两者并存时按协议条件优先规则处理。

弱ETag适合语义等价验证，但某些范围/写入前提需要更强要求。If-Match还可用于并发修改前提，失败返回412等；不要把所有条件请求都理解成返回304。

<a id="k03"></a>

### 3. no-cache、no-store 与 Vary

no-cache允许存储，但复用前要求成功验证；no-store要求不要存储相应请求/响应，不能简单都翻译成“关闭缓存”。must-revalidate约束过期后的复用，stale-while-revalidate等扩展允许有条件边用陈旧响应边后台更新。

Vary指定哪些请求头参与变体选择，例如Accept-Encoding或Origin。未把语言、租户、用户或权限上下文纳入正确缓存边界，可能把响应串给不该看到的人。

no-store也不是清除所有既有历史、Service Worker缓存和浏览器其他存储的万能命令；不同存储层需要各自更新策略。

<a id="k04"></a>

### 4. 发布、CDN 与故障定位

常用发布策略是入口HTML短缓存或验证，带哈希静态资源长缓存；新版本先确保新资源可用，再切换入口，并保留旧资源一段时间，避免旧页面懒加载旧chunk时404。

CDN purge只作用相应缓存层，客户端HTTP缓存、Service Worker和应用内缓存可能仍保留旧数据。排查时看请求是否发生、来自哪个缓存、响应头、Age/ETag和版本URL，不要先让用户反复强刷掩盖策略问题。

认证响应、个性化SSR和租户数据要特别明确private/no-store或隔离键策略。缓存命中提高速度，但不应绕过服务端权限和数据有效性要求。

<a id="summary"></a>

## 三、知识小结

缓存先判断新鲜度，再看验证条件，最后确定共享范围与版本策略。入口与哈希资源分开缓存，多层缓存分开定位，用户数据按权限边界隔离。

参考：[MDN HTTP](https://developer.mozilla.org/en-US/docs/Web/HTTP)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="web10-01"></a>

### WEB10-01 [P0·基础] no-cache与no-store区别是什么？

**回答：** no-cache通常允许保存但复用前需验证，no-store要求不要存储相应内容。它们解决不同策略，且不能自动清除所有应用缓存或已有其他存储。

对应讲解：[no-cache、no-store 与 Vary](#k03)。

<a id="web10-02"></a>

### WEB10-02 [P0·原理] 304响应没有新body，页面数据来自哪里？

**回答：** 来自已有缓存响应体，客户端按规则结合304更新的元数据复用。前提是有可用缓存，条件请求告诉服务器客户端持有的版本。

对应讲解：[条件请求与 304](#k02)。

<a id="web10-03"></a>

### WEB10-03 [P1·工程取舍] 静态资源为何用hash加长缓存？

**回答：** 内容变化时URL变化，新旧资源可并存，长缓存不会误把同URL的旧内容当新内容。入口HTML采用较短缓存或验证，并在发布时保留旧chunk避免旧页面断裂。

对应讲解：[发布、CDN 与故障定位](#k04)。

<a id="web10-04"></a>

### WEB10-04 [P1·原理] Vary解决什么问题？

**回答：** 它把指定请求头纳入缓存变体选择，避免不同编码、来源等条件复用错误响应。用户/租户隔离仍需完整缓存策略，不能任意加Vary后就认为安全。

对应讲解：[no-cache、no-store 与 Vary](#k03)。

<a id="web10-05"></a>

### WEB10-05 [P0·原理] max-age与s-maxage分别作用于什么？

**回答：** max-age控制相应响应的新鲜期，s-maxage针对共享缓存并有相关优先规则。还要考虑Age、private/public等条件，不能把每次打开页面都当重新开始计时。

对应讲解：[新鲜度与直接复用](#k01)。
