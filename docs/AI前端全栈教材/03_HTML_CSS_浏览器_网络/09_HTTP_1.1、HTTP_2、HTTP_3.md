# 09 HTTP 语义与 HTTP/1.1、HTTP/2、HTTP/3

HTTP版本改变了消息传输组织方式，但方法、状态、头和缓存等应用语义仍需独立理解。更高版本不是对所有请求都无条件更快的承诺。

## 二、知识讲解

<a id="k01"></a>

### 1. 方法、状态与幂等

GET/HEAD主要用于读取，POST常用于创建或触发动作，PUT通常表示替换目标资源，PATCH表示部分修改，DELETE用于删除。安全方法和幂等方法是协议语义，不代表业务实现天然正确。

幂等指重复请求对目标状态的预期效果与一次一致，不要求每次响应码完全相同。POST业务也可通过幂等键实现去重，GET则不应偷偷承担扣款等副作用。

状态族包括2xx成功、3xx重定向/条件结果、4xx请求或权限问题、5xx服务器问题。401与403、404、409、412、422、429各有适用契约；不能所有失败都回200再靠前端猜。HEAD没有响应体，但仍可提供相应元数据。

<a id="k02"></a>

### 2. HTTP/1.1：连接与消息边界

HTTP/1.1通常使用持久连接，一个连接可承载多次请求，但常见浏览器使用方式受到每连接请求响应排序等限制，需要多个连接并行。不能把所有HTTP/1.1实现都简单说成每请求新建连接。

消息体边界可由Content-Length、Transfer-Encoding: chunked等规则表达。chunked是传输编码，不等于SSE事件、JSON对象或模型token；代理也可能重新分块。Content-Encoding:gzip等描述内容压缩，是另一层。

Connection等逐跳头只对当前连接链路有意义，经代理转发时要正确处理，不应把它们当所有HTTP版本都可照搬的端到端头。

<a id="k03"></a>

### 3. HTTP/2：帧、流与多路复用

HTTP/2把消息分为二进制帧，以流标识组织多个请求响应，可在同一连接中交错传输；HPACK压缩头信息，流量控制与优先处理影响资源分配。

它减少HTTP/1.1常见的应用层连接排队压力，但底层仍基于TCP有序字节流。丢失TCP数据时，后续字节即使属于其他HTTP流也可能等待恢复，因此仍存在传输层队头阻塞影响。

多路复用不能消除服务器线程池、数据库、带宽或应用依赖瓶颈。Server Push在浏览器生态中支持已发生变化，不应作为现代默认优化建议。

<a id="k04"></a>

### 4. HTTP/3：QUIC 与流隔离

HTTP/3基于QUIC，QUIC在UDP上提供可靠流、多路复用、拥塞控制和TLS1.3相关安全能力。不同流的数据交付不必像TCP一条字节流那样被同一丢失位置统一阻塞，但共享网络、拥塞和应用依赖仍会影响多个流。

QPACK是HTTP/3头压缩方案，处理多路流条件下的依赖问题；连接迁移可帮助网络切换场景，但实际收益取决于客户端、服务端、中间网络与回退策略。

比较性能要看冷/热连接、丢包、时延、资源数量与部署支持。不能简单根据“UDP不可靠”否定QUIC可靠性，也不能宣称HTTP/3没有任何队头等待。

<a id="summary"></a>

## 三、知识小结

先讲HTTP语义，再讲版本如何传输。1.1看持久连接和消息边界，2看帧/流与TCP限制，3看QUIC流隔离与网络条件；幂等、鉴权和缓存不会因升级协议自动完成。

参考：[MDN HTTP](https://developer.mozilla.org/en-US/docs/Web/HTTP)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="web09-01"></a>

### WEB09-01 [P0·基础] 安全方法与幂等方法有何区别？

**回答：** 安全关注请求预期不改变服务器业务状态，幂等关注重复执行的最终预期效果是否与一次一致。响应可以不同，实现也可能违背协议语义；POST可额外设计业务幂等键。

对应讲解：[方法、状态与幂等](#k01)。

<a id="web09-02"></a>

### WEB09-02 [P0·原理] HTTP/2多路复用为什么仍受丢包影响？

**回答：** HTTP流虽然独立编号并交错传帧，底层TCP仍按一条有序字节流交付。某段丢失时，后续字节可能需要等待恢复，从而影响其他HTTP流。

对应讲解：[HTTP/2：帧、流与多路复用](#k03)。

<a id="web09-03"></a>

### WEB09-03 [P1·原理] HTTP/3使用UDP就不可靠了吗？

**回答：** 不是，QUIC在UDP之上实现可靠流和拥塞控制，并结合安全会话。改变的是可靠性与流隔离的组织位置，不是放弃可靠性。

对应讲解：[HTTP/3：QUIC 与流隔离](#k04)。

<a id="web09-04"></a>

### WEB09-04 [P1·工程取舍] 升级HTTP/3一定能解决页面慢吗？

**回答：** 不一定，CPU、数据库、资源体积、业务串行依赖或缓存策略问题仍在。应按实际时延丢包、连接复用和客户端支持测量，保留兼容回退。

对应讲解：[HTTP/3：QUIC 与流隔离](#k04)。

<a id="web09-05"></a>

### WEB09-05 [P1·原理] Transfer-Encoding和Content-Encoding有什么区别？

**回答：** 前者涉及HTTP消息传输组织，例如1.1的chunked边界；后者描述内容压缩如gzip。它们都不等于SSE事件或JSON对象边界，应用仍要按自己的协议解析。

对应讲解：[HTTP/1.1：连接与消息边界](#k02)。
