# 04 浏览器进程、渲染与主线程预算

浏览器实现因产品和版本而异，但渲染分析可以围绕解析、样式、布局、绘制与合成展开。性能结论应来自测量，不能仅凭某属性被称为GPU加速。

## 二、知识讲解

<a id="k01"></a>

### 1. 进程、线程与职责

现代浏览器通常有浏览器主进程、渲染进程、网络和GPU相关组件，站点隔离还会影响进程分配。JS执行、样式和部分渲染工作在页面主线程，网络与合成等可由其他线程/进程协作。

多进程不代表一段同步JS不会阻塞页面交互；长任务仍会占据主线程。也不能认为每个标签页恰好只有一个进程，iframe、隔离策略和实现都会影响结构。

<a id="k02"></a>

### 2. 从 HTML/CSS 到像素

```text
HTML解析 → DOM
CSS解析 → CSSOM/规则
DOM + 样式匹配 → 计算样式与布局对象
Layout → Paint记录 → 分层/栅格化 → Composite → 画面
```

这是帮助定位工作的抽象，不要求浏览器每次变化都完整走全流程。display:none通常不参与相应布局绘制，visibility:hidden常保留布局位置；改变颜色可能只影响绘制，改变几何尺寸可能引发布局并进一步绘制。

CSS可能阻止首屏渲染，脚本又可能依赖样式和DOM，资源下载与执行形成关键路径，不能把“CSS不阻塞HTML解析”误说成CSS对页面加载没有阻塞影响。

<a id="k03"></a>

### 3. 强制同步布局与批量读写

DOM写入后浏览器可能延后统一布局，但紧接着读取需要准确几何信息的属性，会迫使它提前完成计算。循环交替读写可能反复触发布局，称为布局抖动。

```js
// browser-only：先集中读取，再集中写入。
function alignCards(cards) {
  const widths = cards.map(card => card.getBoundingClientRect().width);
  const max = Math.max(0, ...widths);
  for (const card of cards) card.style.width = max + 'px';
}
```

真实大列表还需避免过多节点和巨大参数展开；这个示例用于表达读写分离。requestAnimationFrame可安排视觉更新时机，但回调内的反复布局仍然有成本。

<a id="k04"></a>

### 4. 合成动画、图层与性能证据

transform/opacity在适合条件下可主要走合成路径，减少布局/绘制，但并不保证每种元素和动画都免费。图层会占纹理内存，will-change长期大量使用可能适得其反。

内容复杂度、阴影/滤镜、大图、字体和跨层合成都可能影响性能。需要在Performance中定位Layout/Paint/Composite与长任务，并观察目标设备的输入延迟和掉帧。

优化前固定数据量、设备和交互步骤，优化后重复测量；只看到帧率短暂提高或开发机变快，不足以证明所有用户改善。

<a id="summary"></a>

## 三、知识小结

浏览器性能分析先定位资源关键路径与主线程工作，再判断是否需要减少布局、绘制、脚本或节点数量。合成是优化机会，不是无成本承诺。

## 四、面试题与答案

<a id="web04-01"></a>

### WEB04-01 [P0·原理] 重排和重绘的区别是什么？

**回答：** 布局重新计算几何位置与尺寸，绘制生成或更新视觉内容。几何变化常进一步需要绘制，而某些视觉变化不需要重新布局；具体受影响范围由浏览器和页面结构决定。

对应讲解：[从 HTML/CSS 到像素](#k02)。

<a id="web04-02"></a>

### WEB04-02 [P0·原理] 为什么读布局属性有时很贵？

**回答：** 在样式或DOM写入后读取精确几何值，可能迫使浏览器立即完成尚未处理的样式/布局。循环交替读写会重复付成本，集中读取再写入通常更易控制。

对应讲解：[强制同步布局与批量读写](#k03)。

<a id="web04-03"></a>

### WEB04-03 [P1·工程取舍] transform一定比left更快吗？

**回答：** 常有合成优化机会，但不是绝对。元素、图层、内容与设备会影响路径和成本；应比较实际布局/绘制/合成与内存，而不是只看属性名。

对应讲解：[合成动画、图层与性能证据](#k04)。

<a id="web04-04"></a>

### WEB04-04 [P1·基础] 浏览器多进程为何页面仍会卡？

**回答：** 多进程让职责隔离，但页面主线程仍需顺序执行许多JS、样式和布局工作。长任务占用主线程时，交互处理和绘制可被延后。

对应讲解：[进程、线程与职责](#k01)。
