# 08 DNS、TCP、TLS 与 HTTPS

网络访问从名字解析到可靠传输和安全会话，各层职责不同。理解请求耗时和安全边界时，要把连接复用、缓存、协议版本及握手阶段一并考虑。

## 二、知识讲解

<a id="k01"></a>

### 1. DNS 与连接路径

URL包含协议、主机、路径等；DNS主要解析主机名，不解析整个URL路径。浏览器、操作系统、递归解析器等层可能命中缓存，解析器进一步查询权威信息，记录的TTL等影响缓存时效。

同一主机可对应多个地址，CDN和负载均衡会影响选路。已有HTTP连接或缓存命中可能避免新一轮DNS与建连，因此不能说每次fetch都完整重新握手。

```text
URL/缓存与已有连接检查
  → 必要时DNS解析
  → TCP+TLS 或 QUIC的安全连接建立
  → HTTP请求响应
  → 响应体处理与页面渲染
```

DoH/DoT关注DNS传输隐私等问题，DNSSEC关注数据真实性验证，不能把其中一个简单当成另一个。

<a id="k02"></a>

### 2. TCP 可靠字节流与握手

TCP提供有序可靠字节流，应用消息边界需要上层协议定义。序列号、确认、重传、流量控制和拥塞控制分别解决排序、丢失、接收能力及网络拥塞问题，不等于永远及时到达。

三次握手围绕双方初始序列号及连接状态确认：客户端SYN，服务端SYN+ACK，客户端ACK。第三步确认服务端序列及前一步已收到，帮助双方建立一致状态，也处理历史重复报文等问题；不是简单“握三次就绝对不会丢”。

关闭通常涉及双方各自停止发送的FIN/ACK，是全双工半关闭过程；报文可以合并，不能说永远恰好四个独立包。TIME_WAIT有避免旧报文干扰和处理最后确认重传等作用。

<a id="k03"></a>

### 3. TLS 身份、密钥与传输保护

TLS提供对端认证、机密性和完整性。客户端验证证书链、域名和有效性等；现代TLS通常通过临时密钥协商派生会话密钥，之后使用对称加密/认证保护应用数据。

不要把现代TLS概括成“服务端公钥直接加密并传递所有对称密钥”。版本与密钥交换算法影响握手，TLS1.3减少了旧算法和握手组合，证书签名验证与会话密钥协商也不是同一动作。

HTTPS保护传输链路，不保证网站业务可信、数据库安全或没有XSS；证书合法也不代表接口已经正确做权限控制。

<a id="k04"></a>

### 4. 握手成本、复用与 QUIC

TLS会话恢复和连接复用可以降低重复建立成本；0-RTT等早期数据方案需考虑重放风险，不能对任何写操作都无条件开启。preconnect只在确有后续使用时才值得占用资源。

HTTP/3基于QUIC，后者在UDP上组织可靠流、拥塞控制和TLS1.3安全能力。它不是“改成UDP就不要可靠性”，而是可靠性的位置与流隔离方式变化。

排查慢请求要分DNS、连接、TLS、TTFB和下载阶段，结合真实连接是否复用。单个请求总耗时无法直接证明“后端SQL慢”。

<a id="summary"></a>

## 三、知识小结

DNS找地址，TCP组织可靠字节流，TLS建立认证与加密会话，HTTP表达应用请求。连接缓存与协议版本决定哪些阶段真正发生，安全与性能都要分层判断。

参考：[MDN Web APIs](https://developer.mozilla.org/en-US/docs/Web/API)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="web08-01"></a>

### WEB08-01 [P0·原理] HTTPS提供哪些保护，不提供哪些？

**回答：** TLS通过证书等认证与密钥协商保护传输机密性和完整性，但不保证页面没有恶意业务、XSS或越权接口。传输安全与应用授权、输入输出安全是不同层次。

对应讲解：[TLS 身份、密钥与传输保护](#k03)。

<a id="web08-02"></a>

### WEB08-02 [P1·原理] TCP为什么需要第三次握手？

**回答：** 它确认客户端已经收到服务端的序列和响应，使双方连接状态与序列同步得到进一步确认，并参与处理旧报文等情况。不能只用检查物理线路双向可用概括协议目的。

对应讲解：[TCP 可靠字节流与握手](#k02)。

<a id="web08-03"></a>

### WEB08-03 [P1·基础] 为什么关闭连接不总能看到四个包？

**回答：** TCP双向发送分别关闭，FIN和ACK在满足条件时可以合并，抓包还受场景影响。四次挥手是理解半关闭的典型过程，不是每次严格独立四包。

对应讲解：[TCP 可靠字节流与握手](#k02)。

<a id="web08-04"></a>

### WEB08-04 [P0·工程取舍] 接口慢怎样区分网络还是服务器处理？

**回答：** 拆开DNS、建连、TLS、等待首字节和下载，检查缓存与连接复用，再结合服务器trace和处理时间。TTFB包含多种等待，不应只凭一个数字断定数据库或网络瓶颈。

对应讲解：[握手成本、复用与 QUIC](#k04)。

<a id="web08-05"></a>

### WEB08-05 [P0·原理] 每次请求都会重新DNS和TLS握手吗？

**回答：** 不一定，浏览器、系统和解析器可能缓存，连接也可复用，缓存响应甚至可能避免网络请求。排查耗时时先看哪些阶段真正发生，不能把固定流程图当每次请求的完整成本。

对应讲解：[DNS 与连接路径](#k01)。
