# 06 浏览器存储与认证状态

浏览器存储机制分别服务HTTP会话、轻量偏好、结构化数据和响应缓存。选型要同时考虑同步成本、共享范围、生命周期与攻击面。

## 二、知识讲解

<a id="k01"></a>

### 1. Cookie 与请求凭据

Cookie按域、路径、安全和站点规则随请求发送，主要是HTTP状态机制。服务端可通过Set-Cookie设置HttpOnly、Secure、SameSite、Path、Max-Age/Expires等属性。

```http
Set-Cookie: __Host-session=opaque-value; Path=/; Secure; HttpOnly; SameSite=Lax
```

__Host-前缀要求Secure、Path=/且不能指定Domain等约束。HttpOnly阻止普通页面脚本直接读取该Cookie，Secure要求安全传输，SameSite影响跨站请求附带。site与origin不同：子域、端口等不一定按同源方式划分站点。

HttpOnly不能阻止XSS脚本在当前页面内发起已认证操作；SameSite也不能代替完整授权。跨站会话还要考虑CSRF、第三方Cookie限制及目标浏览器策略。

<a id="k02"></a>

### 2. LocalStorage、SessionStorage 与跨页状态

Web Storage同步存取字符串，localStorage通常跨页面持久保存，sessionStorage按origin及顶层浏览上下文等范围隔离。关闭/复制标签、隐私模式和浏览器策略影响生命周期，不能当服务器数据库的替代。

```js
// browser-only
function savePreference(value) {
  try {
    localStorage.setItem('preferences:v1', JSON.stringify(value));
    return true;
  } catch {
    return false;
  }
}
```

读写可能因配额或策略失败，JSON解析也可能失败，需版本和降级。storage事件一般通知其他相关文档，不会因为当前文档自己setItem就自动回调同一窗口。大数据同步序列化会阻塞主线程。

<a id="k03"></a>

### 3. IndexedDB 与 Cache Storage

IndexedDB提供异步结构化数据、对象仓库、索引和事务，适合离线记录、草稿或较大数据。需设计版本升级、索引、事务范围和失败处理，不能把一次请求success等同于整个事务已经提交。

Cache Storage保存Request/Response映射，常配合Service Worker；它与HTTP缓存是不同层。缓存更新、版本淘汰、离线降级和私人数据隔离需要应用设计，不能缓存所有带认证请求后长期共享。

浏览器存储可能被清理或受配额控制；需要可靠恢复的任务状态、计费记录和权限仍由服务端持久化。

<a id="k04"></a>

### 4. Token 存储与威胁模型

localStorage中的token可被同源脚本读取，XSS可导致泄露；HttpOnly Cookie降低直接读出风险，但自动附带凭据需考虑CSRF，且XSS仍可借页面发动作。

没有一个存储位置能单独解决认证安全。应结合短期凭据、刷新/撤销、CSP、输出编码、CSRF策略、服务器授权和敏感操作校验。前端保存“已登录”Boolean只是UI状态，不是权威身份。

多标签同步可以通过storage事件或BroadcastChannel等机制协调UI，仍需处理退出、过期与服务端会话失效，不能依靠前端消息保证服务端注销。

<a id="summary"></a>

## 三、知识小结

Cookie随请求，Web Storage轻量同步，IndexedDB管理异步结构化数据，Cache Storage保存响应。认证与持久性需要端到端设计，浏览器缓存和状态都不是权威数据库。

参考：[MDN Web APIs](https://developer.mozilla.org/en-US/docs/Web/API)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="web06-01"></a>

### WEB06-01 [P0·基础] localStorage和sessionStorage主要区别是什么？

**回答：** 二者都同步存字符串，localStorage通常更持久且同源页面可共享；sessionStorage与顶层浏览上下文等范围关联，生命周期更偏会话。还需考虑配额、隐私策略、异常和跨页同步。

对应讲解：[LocalStorage、SessionStorage 与跨页状态](#k02)。

<a id="web06-02"></a>

### WEB06-02 [P0·工程取舍] JWT放Cookie就不会受XSS影响吗？

**回答：** 不是。HttpOnly可降低脚本直接读出token的风险，但XSS仍能在页面中调用已认证操作。自动附带Cookie还需CSRF防护，最终要结合输入输出安全与后端授权。

对应讲解：[Token 存储与威胁模型](#k04)。

<a id="web06-03"></a>

### WEB06-03 [P1·原理] Cache Storage和HTTP缓存是一回事吗？

**回答：** 不是。HTTP缓存按协议头和验证规则运作，Cache Storage是应用可操作的请求响应存储，常由Service Worker策略使用。版本、失效、用户隔离和容量需要分别设计。

对应讲解：[IndexedDB 与 Cache Storage](#k03)。

<a id="web06-04"></a>

### WEB06-04 [P1·工程取舍] 离线草稿可以只放浏览器吗？

**回答：** 可作本地缓冲，但存储可能被清理或写入失败。需要可靠跨设备恢复时应与服务端同步，并设计版本、冲突和错误提示，不把浏览器存储当唯一权威副本。

对应讲解：[IndexedDB 与 Cache Storage](#k03)。

<a id="web06-05"></a>

### WEB06-05 [P0·原理] HttpOnly、Secure、SameSite分别保护什么？

**回答：** HttpOnly限制脚本直接读取Cookie，Secure要求安全传输，SameSite影响跨站请求附带。它们不等于资源授权，也不能让XSS无法在当前页面执行已认证操作。

对应讲解：[Cookie 与请求凭据](#k01)。
