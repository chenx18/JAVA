# 09 VNode、Patch 与列表 Diff

VNode描述待呈现结构，patch比较前后结构并决定复用、更新或卸载。理解列表更新最重要的是稳定身份和操作成本，而不是只背某个算法名称。

## 二、知识讲解

<a id="k01"></a>

### 1. VNode 与渲染结果

模板或render函数产生VNode，其中包含节点类型、props、children和key等信息。组件VNode表示组件边界，元素VNode表示DOM元素；VNode不是实际DOM节点，也不意味着所有UI都会完整重建。

h函数可以手写渲染描述，模板编译器则生成更适合优化的渲染代码。更新时runtime根据新旧节点类型和身份，选择patch、mount或unmount，组件状态和生命周期由此受到影响。

<a id="k02"></a>

### 2. key 表达身份而非位置

key应在同级列表中稳定且唯一，帮助框架区分同一业务项。以index为key在插入、删除、排序时让位置取代身份，可能把输入框、焦点或组件内部状态复用给另一条记录。

```vue
<script setup lang="ts">
const props = defineProps<{ items: Array<{ id: string; name: string }> }>()
</script>
<template>
  <ul>
    <li v-for="item in props.items" :key="item.id">{{ item.name }}</li>
  </ul>
</template>
```

随机key每次变化会让框架失去复用，可能反复销毁创建。固定静态列表使用index风险较小，但应基于不会重排的契约，不是把警告消掉就算正确。

<a id="k03"></a>

### 3. 同层比较与最长递增子序列

典型带key列表更新先同步相同的头尾区域，再处理新增/删除，剩余未知区域建立键与位置映射，找出需复用和移动的节点。最长递增子序列可帮助找出相对顺序已稳定的一组，从而减少实际移动。

例如旧顺序A B C D，新顺序B C A D：B C在新位置关系中可保持一段稳定顺序，A需要移动。LIS不是为了找最长相同文本，也不意味着整个树diff都由一个O(n log n)公式概括。

DOM移动、组件更新、属性patch和浏览器布局都有成本；算法减少某类操作不代表所有页面始终更快。

<a id="k04"></a>

### 4. 复用、卸载与实战判断

同类型同key通常提供复用机会，不代表所有props和子节点都无需检查。改变key也可有意重置组件状态，但需要知道生命周期和资源会重新建立。

列表项状态应尽量与稳定业务ID关联，避免把可编辑数据只存在某个可能被复用的索引组件内部。大量列表还需要分页或虚拟化，key和更快diff不能消除十万DOM节点的成本。

验证列表操作时检查的不只是文本，还包括输入值、焦点、选中项、订阅释放和重排后的正确归属。

<a id="summary"></a>

## 三、知识小结

VNode描述结构，key标识同层身份，patch决定复用与变更，LIS帮助减少特定列表移动。业务身份、组件状态与DOM成本必须一起看。

参考：[Vue Guide](https://vuejs.org/guide/introduction.html)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="vue09-01"></a>

### VUE09-01 [P0·原理] 为什么key不能随意使用index？

**回答：** 重排时index代表位置而不是业务身份，框架可能把旧组件状态和DOM复用给另一条数据，造成输入、焦点和状态错位。稳定唯一ID更符合身份契约。

对应讲解：[key 表达身份而非位置](#k02)。

<a id="vue09-02"></a>

### VUE09-02 [P1·原理] Vue Diff中的LIS解决什么？

**回答：** 在带key未知区域重排时，寻找可以保持相对顺序的一组复用节点，减少移动操作。它只是列表更新的一环，不代表整个渲染或布局成本都由LIS决定。

对应讲解：[同层比较与最长递增子序列](#k03)。

<a id="vue09-03"></a>

### VUE09-03 [P1·工程取舍] 给组件换key有什么效果？

**回答：** 通常会改变身份并触发旧实例卸载、新实例创建，可用于有意重置状态，但会重新执行生命周期和资源建立。随机key会破坏正常复用。

对应讲解：[复用、卸载与实战判断](#k04)。

<a id="vue09-04"></a>

### VUE09-04 [P0·基础] 虚拟DOM一定比直接DOM操作快吗？

**回答：** 不一定，它提供声明式结构和跨更新的协调机制，也有计算成本。针对单一动作的直接DOM可能更少工作；实际性能取决于更新规模、编译优化与浏览器成本。

对应讲解：[VNode 与渲染结果](#k01)。
