# 01 Vue 3 的声明式组件模型

Vue把状态、模板和组件契约组织成可更新的UI。理解它要沿一次真实更新看数据如何被读取、谁订阅变化、何时更新DOM，而不只认识几个API名称。

## 二、知识讲解

<a id="k01"></a>

### 1. 状态到界面的关系

```vue
<script setup lang="ts">
import { ref, computed } from 'vue'
const count = ref(0)
const doubled = computed(() => count.value * 2)
</script>

<template>
  <button type="button" @click="count++">次数 {{ count }}</button>
  <p>两倍 {{ doubled }}</p>
</template>
```

渲染过程读取响应式状态并建立依赖，count变化触发相关更新调度；computed表达派生值，模板描述结果。开发者不必每次手工找p再改文本，但仍需设计数据归属和副作用生命周期。

声明式不代表没有运行成本，组件计算、虚拟节点、DOM和浏览器布局仍会发生；不能把“用了Vue”当作性能保证。

<a id="k02"></a>

### 2. 模板指令与组件边界

插值和v-text表达文本，v-bind或:传属性，v-on或@注册事件，v-if按条件创建销毁，v-show切换显示，v-for渲染列表，v-model表达约定的值与更新事件。

v-if适合条件性存在，切换会影响实例和DOM生命周期；v-show保留元素并改显示，频繁切换但需要保留状态时可能合适。列表key表达稳定身份，不是装饰性警告修复项。不要在同一元素上依赖模糊的v-if/v-for组合来隐藏迭代作用域问题。

props向下传，事件向上表达意图，slot让父级提供内容；子组件不应偷偷修改父数据来绕过契约。v-html用于解析HTML，不能直接接不可信内容。

<a id="k03"></a>

### 3. Options API 与 Composition API

Options API按data、methods、computed、watch和生命周期选项组织；Composition API通过setup内的ref/reactive/computed/watch等函数按业务能力组合。两者共享Vue组件和响应式体系，不是两套互不相干的运行时。

组合式函数适合复用带状态与生命周期的逻辑，例如搜索请求与取消；普通纯函数适合无组件上下文的计算。不要把所有函数都命名useX却没有清楚输入输出与清理责任。

组件创建多个实例时，实例状态应独立。把可变状态放模块顶层会共享，在SSR中还可能跨请求污染，需要区分配置、服务与用户态。

<a id="k04"></a>

### 4. 生命周期与服务器渲染

setup中同步注册onMounted/onUpdated/onUnmounted等钩子，挂载后可访问真实DOM；清理监听、timer和请求放在合适的卸载/作用域结束路径。onBeforeMount/onBeforeUpdate/onBeforeUnmount用于对应阶段前的处理。

onActivated/onDeactivated对应KeepAlive，onErrorCaptured处理子树错误边界，onServerPrefetch用于SSR等待数据等场景。mounted/unmounted等客户端DOM钩子不会作为SSR DOM生命周期照常执行，不能在模块求值时无条件读取window。

异步之后才创建的watcher或注册逻辑未必自动绑定组件作用域，应明确stop或资源所有者。

<a id="summary"></a>

## 三、知识小结

Vue的主线是状态→依赖→调度→组件更新；模板和组件契约表达结果，生命周期管理副作用。Options和Composition主要改变逻辑组织方式，不能省略数据与资源设计。

参考：[Vue Guide](https://vuejs.org/guide/introduction.html)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="vue01-01"></a>

### VUE01-01 [P0·原理] Vue的声明式UI具体是什么意思？

**回答：** 用状态与模板描述界面关系，渲染读取状态形成依赖，变化后框架调度更新DOM。开发者仍负责状态归属、事件契约和副作用，而非自动解决所有业务与性能问题。

对应讲解：[状态到界面的关系](#k01)。

<a id="vue01-02"></a>

### VUE01-02 [P0·基础] v-if和v-show如何选择？

**回答：** v-if影响节点和组件是否存在，切换涉及创建销毁；v-show主要改显示并保留实例。根据切换频率、初始成本和状态保留需求选择，还要考虑隐藏元素的可访问行为。

对应讲解：[模板指令与组件边界](#k02)。

<a id="vue01-03"></a>

### VUE01-03 [P1·工程取舍] Composition API比Options API本质上更快吗？

**回答：** 不能这样概括，它主要改善按能力组织和复用复杂逻辑，两者使用同一组件响应式体系。性能取决于实际依赖、计算、更新和浏览器工作。

对应讲解：[Options API 与 Composition API](#k03)。

<a id="vue01-04"></a>

### VUE01-04 [P0·原理] 为什么不能在所有setup代码中直接操作DOM？

**回答：** 组件尚未挂载时DOM可能不存在，SSR也没有页面DOM。DOM逻辑应放合适生命周期并处理条件渲染引用，资源需在卸载或作用域结束时清理。

对应讲解：[生命周期与服务器渲染](#k04)。
