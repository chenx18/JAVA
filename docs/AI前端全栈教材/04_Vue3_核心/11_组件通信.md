## 二、知识讲解

<a id="k01"></a>

### 1. props向下、事件向上

props描述输入，emits描述事件载荷，父组件决定如何更新自己的状态。props根级通常是只读视图，但对象/数组内部仍可能经共享引用被修改；这不代表推荐子组件直接改父对象。

```vue
<script setup lang="ts">
const props = defineProps<{ count: number }>()
const emit = defineEmits<{ increment: [] }>()
</script>
<template>
  <button type="button" @click="emit('increment')">{{ props.count }}</button>
</template>
```

事件名表达意图而不是把所有内部实现泄露出去。组件自定义事件不会像原生DOM事件那样自动沿任意组件祖先冒泡；需要明确转发或采用合适上下文机制。

<a id="k02"></a>

### 2. v-model 与输入组件

组件v-model通常对应某个值prop和update事件，默认是modelValue/update:modelValue；命名模型可表达多个独立值。defineModel简化该契约，不表示父子获得任意共享可写状态。

```vue
<script setup lang="ts">
const name = defineModel<string>({ required: true })
</script>
<template><input v-model="name" aria-label="名称"></template>
```

修饰符、格式化和校验应明确在哪层执行。父侧undefined与子侧默认值可能造成不同步，提交式表单也可能需要独立draft而非每键都改服务器数据。

<a id="k03"></a>

### 3. slots、attrs 与 expose

slot让父级提供内容，作用域插槽通过slot props把子组件计算结果交给父模板使用；内容默认仍按声明位置的作用域解释，不是任意访问子内部变量。

未声明为props/emits的attrs可以透传到根节点，多根组件和inheritAttrs:false等场景需要显式指定落点。透传class/style/事件时要避免把内部包装层变化变成公共破坏。

defineExpose暴露有限命令式能力，如focus/reset；不要为了方便把所有内部ref暴露成公共API。大多数数据同步仍应通过props与事件表达。

<a id="k04"></a>

### 4. provide/inject 与共享状态

provide/inject适合跨层上下文，如主题、表单注册、依赖服务。使用Symbol键或类型化InjectionKey减少冲突，明确默认值和提供者缺失处理。

提供ref或响应式对象可让消费者观察变化，提供一个当前原始值快照不会自动变成订阅。修改权最好由提供者管理，通过只读视图和动作函数暴露，避免任意后代随意写共享对象。

跨路由共享客户端状态可使用Pinia，服务器数据还涉及缓存与失效，URL状态则应与导航和分享需求一致；每类状态各有所有者。

<a id="summary"></a>

## 三、知识小结

通信按数据关系选：props输入，emit意图，v-model约定同步，slot定制内容，provide/inject上下文，expose有限命令。公共契约越明确，内部组件越容易重构。

参考：[Vue Guide](https://vuejs.org/guide/introduction.html)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="vue11-01"></a>

### VUE11-01 [P0·原理] 子组件为何不应直接修改父传来的对象？

**回答：** 嵌套共享引用可能允许实际修改，但会绕过清晰的数据所有权，使父组件难以追踪来源。应通过事件或提供者动作表达修改意图，必要时维护局部draft。

对应讲解：[props向下、事件向上](#k01)。

<a id="vue11-02"></a>

### VUE11-02 [P0·基础] 组件v-model的本质是什么？

**回答：** 它是一组值prop和更新事件的约定，defineModel提供编译简写。它不自动处理提交、验证、服务器同步或所有父子默认值冲突。

对应讲解：[v-model 与输入组件](#k02)。

<a id="vue11-03"></a>

### VUE11-03 [P1·原理] slot内容能直接访问子组件全部状态吗？

**回答：** 不能，插槽内容通常按声明方作用域解释，子组件需通过slot props明确提供数据。作用域插槽是契约，不是打破组件封装的后门。

对应讲解：[slots、attrs 与 expose](#k03)。

<a id="vue11-04"></a>

### VUE11-04 [P1·工程取舍] provide/inject与Pinia怎么选？

**回答：** 组件子树上下文和依赖服务适合provide/inject，跨业务共享且需要集中动作/调试的客户端状态可用Store。还要区分服务器数据和URL状态，不一律全局化。

对应讲解：[provide/inject 与共享状态](#k04)。
