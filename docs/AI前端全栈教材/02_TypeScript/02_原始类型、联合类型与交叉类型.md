# 02 基础类型、联合、交叉与元组

类型可以看作允许的值的集合。联合允许候选集合中的值，交叉要求同时满足多个约束；先用集合思维理解，再将它们用于函数和对象建模。

## 二、知识讲解

<a id="k01"></a>

### 1. 基础类型与空值

使用string、number、boolean、bigint、symbol等原始类型名，通常不用String/Number/Boolean包装对象类型。strictNullChecks下null和undefined需要显式纳入允许类型，不会自动兼容所有其他类型。

object表示非原始对象；{}通常表示非null/undefined的值，连数字字符串也可能满足，不等于“空普通对象”。Object也不宜当业务结构类型。需要字段时直接写具体对象类型，需要未知输入用unknown。

```ts
type User = { id: string; nickname: string | null };
const user: User = { id: 'u1', nickname: null };
function label(value: string | null) {
  return value === null ? '未设置' : value.toUpperCase();
}
console.log(label(user.nickname));
```

void通常表达调用方不使用返回值，never表达不可能的值或不正常返回；两者不是“都没有值”的同义词。

<a id="k02"></a>

### 2. 数组、元组与只读

T[]和`Array<T>`表示同类元素数组。元组按位置与长度描述不同元素，可含可选项和rest元素；元组长度是类型层信息，运行时仍是数组。

```ts
type Point = readonly [x: number, y: number];
const point: Point = [10, 20];
function sum(values: readonly number[]) {
  return values.reduce((total, n) => total + n, 0);
}
console.log(sum(point)); // 30
// @ts-expect-error 只读视图不允许push。
if (false) point.push(3);
```

readonly限制通过这个类型视图修改，不是深冻结。同一对象可能仍被另一条可写引用修改；把readonly用于API输入可防止函数无意改动调用者数据，但不能当并发或安全隔离。

<a id="k03"></a>

### 3. 联合与交叉

联合A|B表示值可以属于其中一种；在未收窄前，只能安全使用各候选共同支持的操作。交叉A&B要求同时满足，适合组合对象约束，不是运行时Object.assign。

```ts
type Named = { name: string };
type Identified = { id: string };
type User = Named & Identified;
type Id = string | number;
function normalize(id: Id): string {
  return typeof id === 'number' ? id.toString() : id;
}
const user: User = { id: normalize(1), name: 'A' };
```

冲突交叉可能使字段成为never，例如{value:string}&{value:number}的value无法同时满足两种原始类型。它不会自动选择后写类型覆盖前写类型；对象合并运行时的后覆盖规则不能直接套给交叉类型。

<a id="k04"></a>

### 4. 字面量、可选属性与索引签名

字面量联合如'idle'|'loading'可限制状态名称。可选属性name?:string表示属性可能缺失，读取需考虑undefined；exactOptionalPropertyTypes开启时，缺失与显式赋undefined的写入规则更明确。

索引签名{[key:string]:number}声明字符串键对应值的契约，不保证每个运行时键真的存在。noUncheckedIndexedAccess可让未证明存在的索引读取包含undefined。

```ts
type Scores = Record<string, number>;
const scores: Scores = {};
const score = scores['missing'];
console.log(score); // undefined；类型配置不能替运行时创造成员。
```

建模时不要为省事把所有字段都可选；必需数据应在合法状态下成为必填，联合类型可以把状态和数据绑定。

<a id="summary"></a>

## 三、知识小结

联合是候选，交叉是同时满足；元组表达位置，数组表达同类序列；只读是类型视图，可选不等于允许所有空值；索引类型不保证运行时存在。

参考：[TypeScript Handbook](https://www.typescriptlang.org/docs/handbook/intro.html)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="ts02-01"></a>

### TS02-01 [P0·基础] union和intersection的本质区别是什么？

**回答：** 联合只需满足候选之一，未收窄前要使用共同安全操作；交叉需同时满足各约束，冲突字段可能成为never。交叉不执行对象合并，也不是后写类型覆盖前写类型。

对应讲解：[联合与交叉](#k03)。

<a id="ts02-02"></a>

### TS02-02 [P0·原理] object、{}、unknown该怎么选？

**回答：** 业务结构用明确字段类型，未知边界用unknown。object排除原始值，{}通常排除null/undefined但可接受其他原始值，均不等于一个经过结构验证的普通对象。

对应讲解：[基础类型与空值](#k01)。

<a id="ts02-03"></a>

### TS02-03 [P1·基础] readonly能防止对象被任何代码修改吗？

**回答：** 不能，它约束当前静态视图，通常是浅层的，其他可写引用或运行时代码仍可能修改。需要运行时不可变性还需相应数据设计或冻结策略。

对应讲解：[数组、元组与只读](#k02)。

<a id="ts02-04"></a>

### TS02-04 [P1·原理] `Record<string,number>`为何仍能读到undefined？

**回答：** 类型描述索引访问契约，不会在运行时填满所有键。启用noUncheckedIndexedAccess可提醒未验证读取，但仍需hasOwn或业务存在性检查。

对应讲解：[字面量、可选属性与索引签名](#k04)。
