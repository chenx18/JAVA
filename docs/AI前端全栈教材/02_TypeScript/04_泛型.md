# 04 泛型与类型关系

泛型把某些类型作为参数，保留输入、输出与成员之间的关系。它的价值不是“任何类型都能传”，而是传入具体类型后信息仍能传到结果。

## 二、知识讲解

<a id="k01"></a>

### 1. 从any到关系保留

```ts
function identity<T>(value: T): T { return value; }
const id = identity('u1');
const length = id.length;
console.log(length); // 2

function first<T>(values: readonly T[]): T | undefined {
  return values[0];
}
console.log(first([1, 2])); // 1
```

any会让检查信息继续流失，泛型让调用方得到相关类型。first显式包含undefined，反映空数组可能没有结果；泛型再准确也不能忽略运行时为空的路径。

类型参数若只出现一次且不建立有用关联，通常普通参数类型更直接。不要把所有函数都加`<T>`当作质量提升。

<a id="k02"></a>

### 2. 约束与索引关系

```ts
function get<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key];
}
const user = { id: '1', age: 20 };
const age = get(user, 'age');
// @ts-expect-error key必须属于目标类型。
if (false) get(user, 'missing');
console.log(age); // 20
```

T extends {length:number}只保证可读取length，不保证T就是数组，也不能任意返回另一个仅满足约束的对象作为T。调用方可能传入带额外字段的更具体类型，约束是下限，不是泛型实际类型本身。

<a id="k03"></a>

### 3. 推断、显式类型实参与默认值

```ts
interface Page<T = unknown> {
  items: T[];
  total: number;
}
function wrap<T>(value: T): { data: T } { return { data: value }; }
const inferred = wrap({ id: '1' });
const explicit = wrap<string | null>(null);
const page: Page<string> = { items: ['a'], total: 1 };
```

优先让合理推断工作，必要时显式给类型实参表达预期。泛型默认值在没有合适指定值时提供默认类型，不能修复错误的运行时输入。const类型参数可帮助保留某些字面量推断，但同样不产生运行时冻结。

回调参数与返回值、多个参数的共同推断都会影响T。类型推断结果不好时先检查函数签名是否准确表达关系，而不是立即写as any。

<a id="k04"></a>

### 4. 泛型接口、类与变化方向

泛型接口可描述容器、结果或函数；泛型类的类型参数服务实例侧，静态成员不能直接使用某个尚未确定的实例T。

```ts
class Box<T> {
  constructor(public value: T) {}
  map<U>(fn: (value: T) => U): Box<U> {
    return new Box(fn(this.value));
  }
}
console.log(new Box(1).map(n => String(n)).value); // '1'
```

函数参数和返回值的可替换关系涉及协变/逆变；strictFunctionTypes对函数类型参数施加更严格检查，但方法签名有历史兼容例外。先用“某实现能否安全接收调用方可能给出的全部值”解释，再讨论术语。

泛型容器里读与写同时出现时，不能只看返回类型兼容就推断整体可随意替换；可变性会影响安全性。

<a id="summary"></a>

## 三、知识小结

解释泛型时给出一条类型关系：输入T传到结果T、key约束来自keyof T、map将T映射到U。约束保证最低能力，不能代表调用方所有具体信息。

参考：[TypeScript Handbook](https://www.typescriptlang.org/docs/handbook/intro.html)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="ts04-01"></a>

### TS04-01 [P0·原理] 为什么不用any代替泛型？

**回答：** any丢失关联并关闭许多检查；泛型把调用时的具体类型传递到返回值或其他参数。例如`identity<T>`(x:T):T保留输入结果关系，返回any则无法提供同样约束。

对应讲解：[从any到关系保留](#k01)。

<a id="ts04-02"></a>

### TS04-02 [P1·原理] T extends {length:number}能直接返回{length:0}作为T吗？

**回答：** 通常不能，调用方的T可能还要求其他字段或更具体约束。extends只保证操作时可依赖的最低能力，不代表T恰好等于那个约束类型。

对应讲解：[约束与索引关系](#k02)。

<a id="ts04-03"></a>

### TS04-03 [P0·编码] 怎样写安全的get属性函数？

**回答：** 将键参数写为K extends keyof T，返回T[K]，把对象、键和结果建立关系。它约束已知类型的合法键，不替代对未知外部对象的运行时验证。

对应讲解：[约束与索引关系](#k02)。

<a id="ts04-04"></a>

### TS04-04 [P1·工程取舍] 什么时候不该引入泛型？

**回答：** 没有需要保留的类型关系时，明确的联合或接口往往更清楚。泛型不是任意输入通行证，也不能为了消除错误而返回as T；应检查运行时契约和推断目标。

对应讲解：[推断、显式类型实参与默认值](#k03)。

<a id="ts04-05"></a>

### TS04-05 [P1·原理] 泛型类的静态成员能直接使用实例类型参数吗？

**回答：** 通常不能，类的静态侧不对应某一个实例T。需要静态方法自己的类型参数或独立契约；实例方法则可用T并通过新的U表达转换。判断函数可替换性时还要分别看参数接受范围和返回保证。

对应讲解：[泛型接口、类与变化方向](#k04)。
