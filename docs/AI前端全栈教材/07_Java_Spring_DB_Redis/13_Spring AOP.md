# 13 Spring AOP 与代理边界

AOP把事务、监控等横切逻辑织入调用流程。Spring常通过代理实现，因此调用路径和可代理性比注解是否写在源码上更能决定行为。

## 二、知识讲解

<a id="k01"></a>

### 1. 切面、通知与切点

join point在Spring AOP中主要是方法执行连接点，pointcut选择哪些连接点，advice定义前后或环绕行为，aspect组织规则。注解本身是元数据，框架读取后建立实际代理逻辑。

```text
调用者 → 容器提供的代理 → 通知链 → 目标方法
                                   → 返回/异常沿链传回
```

Before、AfterReturning、AfterThrowing、After和Around关注不同路径。Around控制proceed及结果/异常，漏掉proceed可能不执行业务，吞异常也可能改变事务结局。

<a id="k02"></a>

### 2. 接口代理与子类代理

JDK动态代理通常面向接口调用，子类代理通过继承目标类覆盖可拦截方法。final类/方法、private方法、可见性和框架配置影响能力，不能断言所有方法都能代理。

代理对象与目标对象可能有不同运行时类型身份，注入和接口设计需考虑这点。多个增强的顺序影响事务、异常转换、日志和权限的观察位置，应明确order而不是靠扫描顺序。

<a id="k03"></a>

### 3. 自调用与生命周期

外部通过proxy调用增强方法会经过通知链，目标内部this.other()通常直接调用自身，绕过代理，因此other自己的切面配置可能不生效。

如果外层已经开启事务，内部SQL仍可能处在该已有事务中；“内层注解被绕过”不等于任何事务都不存在。问题是内层自己的传播、权限或监控策略没有单独执行。

初始化阶段、手动new和跨线程调用也要检查容器/代理边界。优先通过清晰服务边界让调用自然经过代理，不为绕过设计问题到处自注入。

<a id="k04"></a>

### 4. 日志、权限与测试

日志切面要控制敏感参数，不无差别打印密码、token和大请求体。监控保留异常与耗时，权限增强需要可信身份上下文及资源检查。

单元测试直接new业务对象可验证纯逻辑，但不能证明AOP生效；集成测试应从容器取得代理，验证成功、失败、自调用和不同传播。

切面适合统一技术关注点，核心业务流程不宜全部藏在隐式注解和复杂切点中，否则难以追踪实际调用。

<a id="summary"></a>

## 三、知识小结

AOP看切点选谁、通知做什么、调用是否经过代理。自调用影响内层增强，已有外层上下文仍可能存在；测试区分目标逻辑和容器代理。

参考：[Spring Framework Reference](https://docs.spring.io/spring-framework/reference/)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="java13-01"></a>

### JAVA13-01 [P0·原理] 为什么同类this调用可能让@Transactional失效？

**回答：** 目标内部调用通常绕过代理，内层事务通知未被单独执行。但若外层已有事务，内部操作仍可能使用该上下文，不能笼统说所有事务消失。

对应讲解：[自调用与生命周期](#k03)。

<a id="java13-02"></a>

### JAVA13-02 [P1·基础] JDK代理和子类代理有什么约束？

**回答：** 接口代理围绕接口调用，子类代理依赖可继承、可覆盖的方法；final/private等及版本配置会影响能力。以实际代理方式判断，不只看注解。

对应讲解：[接口代理与子类代理](#k02)。

<a id="java13-03"></a>

### JAVA13-03 [P1·工程取舍] AOP测试为什么不能只new Service？

**回答：** 直接构造通常没有容器代理，只测试了目标逻辑。需容器集成测试验证通知链、异常、权限和传播。

对应讲解：[日志、权限与测试](#k04)。

<a id="java13-04"></a>

### JAVA13-04 [P1·原理] Around吞掉异常会有什么影响？

**回答：** 调用者可能误以为成功，事务回滚判定和监控也可能改变。环绕逻辑要明确恢复、转换或继续抛出的契约。

对应讲解：[切面、通知与切点](#k01)。
