## 二、知识讲解

<a id="k01"></a>

### 1. 运行时区域与内存占用

堆主要承载对象数据；每线程Java栈保存调用帧等执行状态；程序计数器和本地方法相关状态支持执行。方法区是规范概念，HotSpot常以元空间等实现类元数据，不能直接说“方法区永远就是某个旧永久代”。

进程总内存还包含线程栈、直接缓冲、代码缓存、JVM原生结构等，不等于-Xmx。容器内OOM可能来自进程总量超过限制，即使堆曲线没满。

对象分配和优化也不能完全靠“new都必在堆某固定位置”判断，逃逸分析等可改变实现，语言语义保持一致。

<a id="k02"></a>

### 2. 类加载、链接与初始化

类加载器定位字节码，链接涉及验证、准备和解析等步骤，初始化执行相应静态初始化逻辑。双亲委派是常见机制，类身份还包含定义它的加载器，不是只看全限定名字符串。

静态编译期常量的使用可能不触发你想象的类初始化，反射、初始化异常和加载器隔离也有边界。应用服务器、插件和热部署场景要避免类加载器被长期引用造成元数据积累。

.class字节码不是源码压缩包，编译目标和运行时版本不兼容会导致类版本错误。

<a id="k03"></a>

### 3. 解释、JIT 与预热

JVM可先解释执行并收集热点信息，再JIT编译优化；内联、逃逸分析和去优化使冷启动与稳定阶段表现不同。一次运行的简单计时容易混入类加载、JIT和GC噪声。

微基准使用适合工具如JMH，包含预热、重复、避免死代码消除并说明数据与硬件。生产延迟还受IO、锁和下游影响，不用一个循环跑分代表整个服务。

<a id="k04"></a>

### 4. 常见故障与诊断顺序

StackOverflowError常见于过深或无终止递归；OutOfMemoryError有堆、元空间、直接内存、线程等不同可能，不能都靠增加-Xmx解决。线程过多也会消耗栈与系统资源。

先收集版本、参数、容器限制、错误堆栈、GC/线程与资源指标，再用jcmd、JFR、堆转储等按需诊断。诊断工具可能有暂停、磁盘与敏感数据成本，生产按流程使用。

修复需回到保留链、资源上限、分配热点或类加载器生命周期，不能只把进程重启当根因解决。

<a id="summary"></a>

## 三、知识小结

JVM看区域职责、加载生命周期和执行优化；进程内存不等于堆，性能不等于一次计时。故障先分类取证，再选择工具和修复。

参考：[Java 17 API](https://docs.oracle.com/en/java/javase/17/docs/api/)；[Java Learning](https://dev.java/learn/)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="java10-01"></a>

### JAVA10-01 [P0·基础] 堆、栈、元空间大致存什么？

**回答：** 堆主要放对象数据，线程栈保存调用执行状态，HotSpot元空间承载类元数据等实现。还要区分规范方法区与具体实现，进程占用包括堆外和线程资源。

对应讲解：[运行时区域与内存占用](#k01)。

<a id="java10-02"></a>

### JAVA10-02 [P1·原理] 同名类为什么可能互相不能转换？

**回答：** 类身份还包含定义类加载器，不只全限定名。不同加载器定义的同名类可视为不同类型，插件和容器隔离中尤其需要理解。

对应讲解：[类加载、链接与初始化](#k02)。

<a id="java10-03"></a>

### JAVA10-03 [P1·工程取舍] 为什么Java微基准不能只跑一次System.nanoTime？

**回答：** 类加载、JIT预热、优化消除和GC都影响结果。应使用合理基准方法与工具，说明运行条件，并区分微操作和真实服务瓶颈。

对应讲解：[解释、JIT 与预热](#k03)。

<a id="java10-04"></a>

### JAVA10-04 [P1·工程取舍] OOM是不是把-Xmx调大就行？

**回答：** 不是，可能是泄漏、堆外、线程或容器总量问题。先确认错误种类与资源证据，增堆还可能减少其他可用内存或延长某些回收成本。

对应讲解：[常见故障与诊断顺序](#k04)。
