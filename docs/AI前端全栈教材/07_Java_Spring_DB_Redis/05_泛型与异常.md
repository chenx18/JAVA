# 05 Java 泛型、异常与资源关闭

## 二、知识讲解

<a id="k01"></a>

### 1. 泛型、约束与不变性

`List<Integer>`不是`List<Number>`的子类型，否则向后者写Double会破坏原Integer列表。Java泛型通常不支持原始类型参数，需要包装类；类型擦除后也不能直接new T或new T[]。

```java
import java.util.*;
public class Example {
    static <T> void copy(List<? super T> target, List<? extends T> source) {
        for (T value : source) target.add(value);
    }
    public static void main(String[] args) {
        List<Number> target = new ArrayList<>();
        copy(target, List.of(1, 2));
        System.out.println(target); // [1, 2]
    }
}
```

PECS可帮助记忆：主要产出T的来源用extends，主要消费T的目标用super。通配符不是任意读写通行证，? extends Number通常不能随意加入Integer，? super Integer读取时只能保证较宽类型。

<a id="k02"></a>

### 2. 类型擦除与保留信息

编译器使用泛型进行检查，必要时插入转换和桥接方法，运行时普通泛型实例不各自生成一份具体参数类。不能直接instanceof `List<String>`，也不能指望new `ArrayList<String>`().getClass提供所有实例泛型事实。

擦除不等于字节码没有任何泛型信息：声明签名等元数据可被反射读取，某些类型令牌模式利用这些声明，但不代表任意运行对象都可自动恢复T。

<a id="k03"></a>

### 3. checked、unchecked 与异常传播

Throwable下有Error和Exception；RuntimeException及Error属于unchecked相关类别，checked异常要求捕获或声明。分类表达语言检查规则，不保证某类异常一定可恢复。

catch应有恢复、转换或传播的明确策略，保留cause。不要catch(Exception)后返回默认成功，finally的return/throw也可能覆盖原结果。

业务异常应有稳定语义，HTTP层统一映射安全错误码与状态；内部日志保留诊断，不把堆栈和SQL直接交给用户。

<a id="k04"></a>

### 4. try-with-resources 与 suppressed

AutoCloseable资源可通过try-with-resources自动关闭，多资源按反向顺序关闭。主体与close同时抛错时，关闭异常可作为suppressed附在主异常上，比手写finally更能保留原故障。

```java
import java.io.*;
import java.nio.charset.StandardCharsets;
public class Example {
    public static void main(String[] args) throws IOException {
        byte[] bytes = "hello".getBytes(StandardCharsets.UTF_8);
        try (InputStream input = new ByteArrayInputStream(bytes)) {
            System.out.println(new String(input.readAllBytes(), StandardCharsets.UTF_8)); // hello
        }
    }
}
```

GC回收对象内存不保证及时关闭文件、连接或线程池。资源所有者要覆盖成功、失败和取消路径；事务回滚也不等于所有外部资源自动关闭。

<a id="summary"></a>

## 三、知识小结

泛型保留关系但受擦除和不变性约束，PECS帮助表达读写方向；异常要保留控制流，AutoCloseable帮助可靠关闭，不能用GC代替业务生命周期。

## 四、面试题与答案

<a id="java05-01"></a>

### JAVA05-01 [P0·原理] 为什么`List<Integer>`不能直接赋给`List<Number>`？

**回答：** 否则可通过Number列表加入Double，破坏原Integer列表契约。泛型通常不变，按读取或写入需求使用extends/super通配符表达安全边界。

对应讲解：[泛型、约束与不变性](#k01)。

<a id="java05-02"></a>

### JAVA05-02 [P1·原理] 类型擦除意味着反射看不到任何泛型吗？

**回答：** 不是。普通实例运行时不能普遍携带具体T，但类/方法声明签名可能保留泛型元数据供反射使用。类型令牌依赖特定声明，不是任意对象的完整类型恢复。

对应讲解：[类型擦除与保留信息](#k02)。

<a id="java05-03"></a>

### JAVA05-03 [P0·基础] checked和unchecked区别是什么？

**回答：** 主要是编译器是否强制捕获或声明；RuntimeException/Error相关unchecked不强制。业务是否可恢复还需按原因决定，不能机械包装所有异常或全部吞掉。

对应讲解：[checked、unchecked 与异常传播](#k03)。

<a id="java05-04"></a>

### JAVA05-04 [P1·原理] try-with-resources比手写finally有哪些优势？

**回答：** 按契约自动关闭并保留主体异常与关闭异常的suppressed关系，减少遗漏和覆盖原错误。仍要明确哪些资源由当前代码拥有以及close语义。

对应讲解：[try-with-resources 与 suppressed](#k04)。
