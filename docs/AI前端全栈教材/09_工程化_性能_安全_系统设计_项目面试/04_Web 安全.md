# 04 Web 安全边界与工程防护

安全按输入、执行、数据与权限边界分析。浏览器机制、后端校验和部署策略相互补充，不存在一个CORS或过滤函数解决所有威胁。

## 二、知识讲解

<a id="k01"></a>

### 1. XSS、CSRF 与 CORS 分层

XSS关注不可信内容进入页面执行环境，防护需按HTML、属性、URL等上下文编码或清洗；CSP和Trusted Types可限制部分执行/注入入口，但不取代正确输出。

CSRF关注自动凭据被诱导用于非预期请求，组合SameSite、CSRF token、Origin验证与合理方法语义。CORS主要控制浏览器跨源访问，不能代替服务器鉴权或阻止所有请求副作用。

Clickjacking可通过合适frame-ancestors等策略控制被嵌入范围，仍需结合实际嵌入业务。

<a id="k02"></a>

### 2. API 授权与注入

身份认证回答是谁，授权回答能否对这个资源做这件事。每次请求按用户、租户、资源归属和动作检查，不能信任客户端传role或隐藏按钮。

SQL参数化保护值的解析边界，动态表列和排序用白名单；命令、模板与路径注入也需按目标语法处理。类型正确、JSON合法或输入很短都不等于可以执行。

业务重复提交、越权枚举和限流也属于接口设计，不能只做登录token校验。

<a id="k03"></a>

### 3. SSRF 与文件上传

服务器代抓URL必须限制协议、目标和网络范围，处理DNS解析、重定向及连接时实际地址，防止只检查初始域名却访问内部网络。出网隔离是另一道边界，不把字符串前缀匹配当完整防护。

文件上传检查大小、内容类型/签名与允许格式，使用生成的存储名并隔离不可执行存储，下载按权限提供。客户端扩展名和MIME可伪造，压缩包还需限制解压路径、层级和展开体积。

解析器、图片处理和文档转换依赖需保持更新，异步扫描状态应在允许发布前明确。

<a id="k04"></a>

### 4. 秘密、依赖与验证

前端包和source map属于用户可接触范围，长期秘密留服务端并按权限注入。日志、错误堆栈和监控平台也可能泄露数据，需脱敏和访问控制。

依赖安全更新、CSP策略、权限测试和业务审计组成持续流程。验证关注实际越权或执行效果，扫描无告警不等于系统无风险；改动应有可追踪修复与回归。

<a id="summary"></a>

## 三、知识小结

按威胁进入的边界选择防护，浏览器限制、参数化、资源授权、网络隔离和秘密管理分别发挥作用。安全需要真实验证，不靠标签或一次扫描背书。

参考：[OWASP Cheat Sheets](https://cheatsheetseries.owasp.org/)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="eng04-01"></a>

### ENG04-01 [P0·原理] CORS为什么不能代替后端权限？

**回答：** 非浏览器客户端不受同样读取限制，浏览器某些请求也可产生副作用。服务器必须自行确认身份、资源和动作授权。

对应讲解：[XSS、CSRF 与 CORS 分层](#k01)。

<a id="eng04-02"></a>

### ENG04-02 [P1·工程取舍] SQL已经参数化是否完全安全？

**回答：** 参数化主要处理值注入，动态标识符、越权查询、资源消耗和业务逻辑仍需白名单、授权和限制。不能把语法安全等同整体安全。

对应讲解：[API 授权与注入](#k02)。

<a id="eng04-03"></a>

### ENG04-03 [P1·原理] SSRF为什么不能只检查URL域名前缀？

**回答：** 解析、端口、重定向、DNS变化和实际连接地址可能突破简单字符串检查。需正规解析、允许范围、逐跳验证和出网控制。

对应讲解：[SSRF 与文件上传](#k03)。

<a id="eng04-04"></a>

### ENG04-04 [P1·工程取舍] 上传文件只看扩展名够吗？

**回答：** 不够，名称和MIME可伪造，还需内容验证、大小/解压限制、隔离存储、访问权限和依赖安全。扫描结果与可发布状态也要有流程。

对应讲解：[SSRF 与文件上传](#k03)。

<a id="eng04-05"></a>

### ENG04-05 [P1·工程取舍] 为什么日志和source map也属于秘密管理？

**回答：** 它们可能包含源码、内部路径、参数或凭据，访问范围与保留策略需明确。前端可见产物不适合长期秘密，扫描无告警也不证明没有业务泄露路径。

对应讲解：[秘密、依赖与验证](#k04)。
