# 第六章 AI 前端性能

## 一、本章具体知识点

- first token latency
- token throughput
- stream parsing
- reactive update frequency
- batching
- markdown rendering
- code block rendering
- auto-scroll
- virtualized conversation

## 二、各知识点详细解释

AI Chat 多了一个传统页面没有的指标：

```text
Request
→ TTFB
→ First Token
→ Token Stream
→ Final Answer
```

如果模型生成很快，但前端每个 token 都触发复杂 Markdown AST 解析和整条消息列表更新，用户仍会看到卡顿。

可以：

```text
Stream chunk
→ buffer
→ batch update
→ update current message only
→ throttle expensive markdown parse
```

历史消息很多时可以采用虚拟列表或分段渲染。

## 三、本章面试题与答案

### 题：AI 回复很快，为什么页面还是卡？

**答案：**

模型速度只是整个链路的一部分。前端可能在每个 chunk 到达时更新大量 reactive state、重新解析整篇 Markdown、更新复杂代码高亮或滚动布局，因此 Main Thread 被大量小任务占满。需要通过 Performance 定位，再做 buffer/batch、局部更新和昂贵渲染节流。
