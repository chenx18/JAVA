# 03 CI/CD、Docker 与回滚

发布不是把代码拷上服务器，而是将经过验证的版本以可观察、可回退的方式投入流量。容器只封装运行环境，不自动提供业务就绪和数据恢复。

## 二、知识讲解

<a id="k01"></a>

### 1. 流水线与不可变产物

常见流程：冻结依赖安装→lint/typecheck→测试→构建→镜像或静态产物→必要扫描→部署→就绪验证→灰度/回滚。测试的提交和部署产物需对应，避免部署时又重新解析另一组依赖。

镜像标签与提交/版本关联，生产可固定批准的版本或digest。秘密通过部署环境或秘密管理注入，不写入镜像层、前端包或日志。构建参数与运行配置的生命周期不同。

<a id="k02"></a>

### 2. 多阶段静态前端镜像

```dockerfile
# 示例：已有npm锁文件和build脚本的Vite SPA。
FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
```

生产需按团队批准的补丁/digest和安全更新策略固定基础镜像，配置.dockerignore排除node_modules、秘密和无关产物。上例分离构建与运行层，不包含SPA history回退、TLS或API代理配置，部署时按实际路由补齐。

SSR/Nuxt Node服务不是把dist放Nginx即可，需使用相应服务端输出与启动方式。

<a id="k03"></a>

### 3. 健康、就绪与优雅关闭

进程存活与可接流量不同。liveness帮助发现需重启的进程故障，readiness表示实例是否应进入流量；不要让一个短暂下游故障导致全服务无限重启。

滚动发布要先等待新实例就绪，再移除旧实例流量，并给在途请求/长连接合理处理时间。长任务需独立持久化，不随一个实例被替换而丢失。

监控错误、延迟和业务成功率，health接口200不能代表所有关键流程可用。

<a id="k04"></a>

### 4. 数据库变更与回滚

应用回滚不自动回滚数据库。滚动期间新旧实例可能共存，schema变更采用兼容扩展→迁移→收缩等策略，删除字段或改变语义前确认旧版本已退出。

不可逆迁移需要备份、校验与恢复方案，不能只保留旧镜像就宣称可回滚。静态资源也要保留旧chunk，避免旧页面请求失效版本。

发布验收包含登录、关键读写、权限、缓存与异步任务，故障演练验证回滚动作和数据完整性。

<a id="summary"></a>

## 三、知识小结

可重复构建、不可变产物、就绪门禁、灰度观察和数据兼容共同构成交付。Docker封装环境，不替代应用健康与数据库恢复。

参考：[Docker Multi-stage Builds](https://docs.docker.com/build/building/multi-stage/)；[GitHub Actions Docs](https://docs.github.com/en/actions)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="eng03-01"></a>

### ENG03-01 [P0·原理] 容器启动为什么不代表服务就绪？

**回答：** 进程可能已运行但依赖、迁移或初始化未完成。应区分存活和接流量条件，再验证关键业务，不仅看端口或health200。

对应讲解：[健康、就绪与优雅关闭](#k03)。

<a id="eng03-02"></a>

### ENG03-02 [P1·工程取舍] 多阶段构建有什么价值？

**回答：** 将编译工具和开发依赖与运行产物分开，减少最终镜像内容并明确构建过程。但仍需版本、秘密、运行配置和路由策略。

对应讲解：[多阶段静态前端镜像](#k02)。

<a id="eng03-03"></a>

### ENG03-03 [P0·原理] 回滚镜像能否恢复所有数据？

**回答：** 不能，数据库schema和已写数据不会自动回退。需要兼容迁移、备份和恢复策略，尤其新旧版本并存时。

对应讲解：[数据库变更与回滚](#k04)。

<a id="eng03-04"></a>

### ENG03-04 [P1·工程取舍] 为什么发布要验证真实流程？

**回答：** 单点健康只反映有限条件，认证、权限、缓存、数据库和长任务可能另有故障。灰度观察与关键路径测试能发现产物成功但业务失败的情况。

对应讲解：[流水线与不可变产物](#k01)。
