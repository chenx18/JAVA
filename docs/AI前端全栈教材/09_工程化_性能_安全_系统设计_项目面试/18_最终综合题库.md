综合复习把知识链连接到真实任务。题目按前端主力、Java与AI横向能力组织，答案说明关键判断和边界，不要求所有岗位同等深度。

## 二、知识讲解

<a id="k01"></a>

### 1. 语言、类型与框架链

从值/引用、作用域和异步机制连接到TS契约、Vue依赖或React快照，再到组件与状态管理。能解释一次更新为什么发生、旧状态为何出现、数据是否被验证，比分别背工具名更重要。

<a id="k02"></a>

### 2. 浏览器、网络与交付链

从URL和缓存到资源关键路径、JS执行、布局绘制和交互，再到构建、测试、部署和回滚。把问题分层，避免把所有慢都归后端或所有失败都归跨域。

<a id="k03"></a>

### 3. 后端与AI应用链

Java服务明确身份、资源权限和事务，数据库保护约束，缓存和任务管理可靠性，AI适配器/工具/RAG提供受控能力，前端按状态与事件展示。每层都有自己的成功与失败定义。

<a id="k04"></a>

### 4. 自评与复述深度

基础层能给定义和例子，原理层能推导变形，编码层能实现与测试，工程层能说明取舍、证据和限制。题目优先级不是必考概率，年度新能力按目标岗位和已核对版本选择。

回答职业定位时，以真实前端经验为主轴，Java和AI说明能独立完成哪些链路、哪些仍在学习。不要因技术名单长就宣称已具备所有高级岗位要求。

<a id="summary"></a>

## 三、知识小结

综合面试考查知识能否连成判断与行动。用准确机制、具体代码、失败路径和真实项目证据回应，未知范围明确说明。

参考：[OpenTelemetry Concepts](https://opentelemetry.io/docs/concepts/)；[MCP Specification](https://modelcontextprotocol.io/specification/2026-07-28)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="eng18-01"></a>

### ENG18-01 [P0·原理] 闭包、状态快照和迟到请求怎样联系？

**回答：** 函数关联创建时环境，某些回调读旧绑定或计算快照；请求完成顺序又可改变状态。框架依赖机制、函数式更新和版本检查分别解决不同问题，取消也不替代提交归属。

对应讲解：[语言、类型与框架链](#k01)。

<a id="eng18-02"></a>

### ENG18-02 [P0·原理] TypeScript通过为何接口仍会崩？

**回答：** 普通类型被擦除，网络可能返回错误结构。应从unknown经schema验证再进入领域模型，处理HTTP、语法、结构和业务错误；泛型或as不构成运行校验。

对应讲解：[语言、类型与框架链](#k01)。

<a id="eng18-03"></a>

### ENG18-03 [P0·工程取舍] Vue与React性能怎样比较？

**回答：** 先理解依赖追踪与render快照，再在相同业务、数据和设备上测更新、DOM与交互。编译器、状态结构和节点量都影响，不能凭框架名给绝对排名。

对应讲解：[语言、类型与框架链](#k01)。

<a id="eng18-04"></a>

### ENG18-04 [P0·原理] 跨域错误是否说明服务器没执行请求？

**回答：** 不一定，某些请求已经发送，只是响应不能被脚本读取；预检又有另一流程。服务器副作用、CSRF和授权仍需独立处理。

对应讲解：[浏览器、网络与交付链](#k02)。

<a id="eng18-05"></a>

### ENG18-05 [P1·工程取舍] 页面加载快但交互慢该查什么？

**回答：** 看主线程长任务、事件等待、状态更新、布局和呈现延迟，INP不只看回调时长。加载缓存优化与交互CPU问题属于不同路径。

对应讲解：[浏览器、网络与交付链](#k02)。

<a id="eng18-06"></a>

### ENG18-06 [P0·原理] @Transactional与数据库唯一约束怎样配合？

**回答：** 事务定义操作提交边界，唯一约束保护并发写入的事实，Service预查改善提示。还需正确代理、异常规则和资源范围，任何一层都不能单独替代其他层。

对应讲解：[后端与AI应用链](#k03)。

<a id="eng18-07"></a>

### ENG18-07 [P1·原理] SSE的chunk、event、token为什么不能混用？

**回答：** 它们分别属于传输、协议和模型分词层，边界不一致。要增量解码、分帧、校验后更新状态，业务done与字节EOF也分开。

对应讲解：[后端与AI应用链](#k03)。

<a id="eng18-08"></a>

### ENG18-08 [P1·工程取舍] 模型工具调用如何连接真实业务？

**回答：** 模型提出结构化建议，后端验证工具、参数、用户和资源权限，按幂等与必要确认执行，结果与callId/taskId关联。模型文字不是授权或执行证据。

对应讲解：[后端与AI应用链](#k03)。

<a id="eng18-09"></a>

### ENG18-09 [P1·原理] RAG引用正确与可访问为什么都要检查？

**回答：** 引用可能存在却不支持陈述，文档也可能过期或权限已撤销。检索上下文与引用打开都应核对来源、版本和授权。

对应讲解：[后端与AI应用链](#k03)。

<a id="eng18-10"></a>

### ENG18-10 [P1·工程取舍] MCP长任务接入应确认哪些条件？

**回答：** 确认协议/扩展版本、双方能力、句柄持久化与所有权、查询/输入/取消流程及TTL。当前扩展与旧实验字段不能混用，取消确认不等于立即终止。

对应讲解：[后端与AI应用链](#k03)。

<a id="eng18-11"></a>

### ENG18-11 [P0·工程取舍] 你最大的技术优势怎么回答？

**回答：** 围绕真实主力前端项目说明能解决什么问题，再用已完成的Java接口、事务或AI应用链路补充。明确实践深度与学习范围，用证据而不是堆技术名称。

对应讲解：[自评与复述深度](#k04)。

<a id="eng18-12"></a>

### ENG18-12 [P0·工程取舍] 为什么学习Java和AI，是否偏离前端？

**回答：** 可把目标解释为提升从UI到API、数据和AI工作流的交付能力，同时保持前端基础与工程深度。具体竞争力仍由目标岗位和真实项目证明，不能只凭学习计划承诺。

对应讲解：[自评与复述深度](#k04)。
