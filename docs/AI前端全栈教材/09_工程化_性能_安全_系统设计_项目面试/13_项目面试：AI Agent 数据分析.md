# 13 项目面试：Agent 数据分析与受控查询

数据分析Agent的价值在于把用户问题变成可授权、可复核的数据操作与图表。以下是教学设计，实际项目回答应说明本人实现与证据。

## 二、知识讲解

<a id="k01"></a>

### 1. 问题到查询计划

先确认指标定义、时间范围、维度和用户权限，再让模型提出受控查询意图。收入、订单数和活跃用户等业务口径不能由模型临时发明。

```json
{
  "metric": "paid_order_count",
  "groupBy": "day",
  "from": "2026-01-01",
  "to": "2026-02-01"
}
```

这是领域查询契约示意，服务端把允许指标映射成安全查询，定义时区、边界和数据版本。比直接暴露任意SQL执行器更容易验证权限与成本。

<a id="k02"></a>

### 2. 执行权限与资源预算

按用户/租户过滤表、行和字段，数据库连接采用最小权限，参数化值、白名单结构，限制时长和结果量。只读账号降低写风险，但昂贵查询和敏感读取仍需控制。

即使用SQL AST校验，也要处理语义、函数、子查询和资源边界；结果LIMIT不保证底层扫描便宜。查询日志与trace保存必要审计，不暴露敏感原始数据给无权模型或用户。

<a id="k03"></a>

### 3. 图表、解释与证据

图表使用已验证结果和有限组件schema，坐标、单位、缺失值和聚合口径明确。模型解释应引用实际数据范围，不把相关性说成因果，也不制造不存在的趋势。

长查询或报告任务用taskId和状态恢复，取消需传播且部分结果标记明确。错误可以是无权限、数据不足、查询超时或模型解释失败，不要只弹一个“分析失败”。

<a id="k04"></a>

### 4. 面试表达与测试

可讲一个真实难点：自然语言时间范围歧义、租户过滤或查询成本。按失败输入→约束模型→服务端验证→执行证据→图表核对组织。

测试口径、跨时区、空数据、越权、超时、重复请求、错误图表和解释忠实度。没有真实上线规模时说明是练习或设计，不编造性能收益。

<a id="summary"></a>

## 三、知识小结

分析Agent先有业务口径，再有受控查询和预算，最后展示可核对图表与解释。会生成SQL不是完整交付证据。

参考：[OpenTelemetry Concepts](https://opentelemetry.io/docs/concepts/)；[MCP Specification](https://modelcontextprotocol.io/specification/2026-07-28)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="eng13-01"></a>

### ENG13-01 [P0·工程取舍] 允许模型直接执行SQL安全吗？

**回答：** 不能无条件允许，需数据库最小权限、表列/行范围、参数化与结构规则、时长和结果限制。更可控的方式是领域查询工具，模型只选择允许指标。

对应讲解：[执行权限与资源预算](#k02)。

<a id="eng13-02"></a>

### ENG13-02 [P1·原理] 只读账号和LIMIT是否足够？

**回答：** 只读不阻止敏感读取和昂贵扫描，LIMIT也不保证执行计划便宜。还要资源权限、查询预算、计划与审计。

对应讲解：[执行权限与资源预算](#k02)。

<a id="eng13-03"></a>

### ENG13-03 [P1·工程取舍] 如何验证生成图表正确？

**回答：** 核对数据来源、聚合口径、时间范围、单位、缺失值和图表schema，再看解释是否忠实于数据。模型给出漂亮图不等于正确分析。

对应讲解：[图表、解释与证据](#k03)。

<a id="eng13-04"></a>

### ENG13-04 [P0·工程取舍] 项目面试怎样体现个人价值？

**回答：** 讲自己解决的具体约束或失败案例，展示查询契约、权限测试、状态恢复或图表核验，明确实际负责范围和未验证规模。

对应讲解：[面试表达与测试](#k04)。

<a id="eng13-05"></a>

### ENG13-05 [P1·工程取舍] 数据分析Agent为什么先定义指标口径？

**回答：** 自然语言里的收入、订单或时间范围可能有歧义，模型不能临时创造业务定义。通过受控指标与维度契约映射查询，明确时区、权限和版本，图表才可核对。

对应讲解：[问题到查询计划](#k01)。
