## 二、各知识点详细解释

工程化解决的是“多人长期协作与稳定交付”，不是“工具越多越专业”。

Git：

- merge 保留分叉历史并产生 merge commit
- rebase 改写提交基线，使线性历史更清晰
- revert 通过新提交反向抵消历史改动
- reset 改变当前分支指针，公共历史慎用
- reflog 用于找回本地曾经移动过的 HEAD

Monorepo 将多个 package 放在一个仓库，通过 workspace 管理共享依赖与版本；关键是清晰定义 package boundary，避免所有模块互相引用。

## 三、本章面试题与答案

### 题：rebase 和 merge 怎么选？

**答案：**

merge 更保守，不改写已有分支提交历史；rebase 会把当前提交重新应用到新的基线，得到更线性的历史。团队通常可以约定个人分支允许 rebase，而共享主干不随意改写。

### 题：reset、revert 区别？

**答案：**

reset 会移动分支指针，可能改写本地历史；revert 通过创建新的反向提交来抵消已有 commit，对共享分支更安全。
