# 01 前端工程化与可重复交付

工程化让多人在持续变化中交付可验证产物。重点是依赖、模块边界、检查流程和版本控制，而不是工具数量。

## 二、知识讲解

<a id="k01"></a>

### 1. 依赖与构建可重复性

锁文件记录依赖解析结果，CI采用匹配包管理器的冻结安装方式，避免每次发布意外升级。Node、包管理器与构建工具版本都应明确，不能只锁顶层package.json范围。

dependencies、devDependencies、peerDependencies表达不同分发意图，组件库中的React/Vue等常需正确peer关系以避免重复实例。锁文件也不能替代对供应链、许可证和安全更新的管理。

源码到产物的流程应固定为安装、静态检查、类型检查、测试和构建，产物携带版本/提交信息方便追踪。

<a id="k02"></a>

### 2. 模块边界与 Monorepo

Monorepo把多个包放同仓库，workspace帮助本地依赖和任务组织。它不自动消除循环依赖，也不意味着所有包都可引用内部实现。

通过package exports、公开类型和依赖方向定义边界，避免依赖提升造成未声明的幽灵依赖。共享包应有明确所有者、版本和变更影响测试；独立仓库与Monorepo按协作和发布需求选择。

工具链缓存需包含影响产物的输入，如锁文件、配置和环境；错误缓存键可能复用过时产物。

<a id="k03"></a>

### 3. Git 操作与协作语义

| 操作 | 作用与边界 |
| --- | --- |
| merge | 合并历史，可快进或产生合并提交；不必然每次新merge commit |
| rebase | 重新应用提交，通常改提交身份；共享历史需团队约定 |
| cherry-pick | 将选定改动应用到当前分支，注意重复与依赖 |
| revert | 用新提交抵消旧改动，适合保留公共历史 |
| reset | 移动引用，模式影响索引/工作区；不能当安全撤销的同义词 |
| reflog | 本地引用移动记录，可辅助恢复但有范围和保留限制 |

提交应表达可审查的一件事，PR说明问题、行为和验证。冲突解决不仅让文件无标记，还要理解双方业务并运行相关检查。

<a id="k04"></a>

### 4. 质量门禁与渐进改造

lint/format统一部分规则，TypeScript检查契约，测试检查行为，构建验证产物；它们不能互相替代。规则需要与团队习惯和旧代码基线适配，逐步收紧比一次制造海量无意义变更更可控。

记录失败可定位日志，关键检查在合并前执行，发布产物与测试产物保持对应。代码生成和AI辅助同样经过审查与验证，不把生成成功当质量门禁。

评价工程化看故障率、交付时间、回滚能力和开发反馈，不以配置文件多或命令长作为成果。

<a id="summary"></a>

## 三、知识小结

工程化围绕可重复安装、清晰依赖、可审查历史和分层验证。工具各负其责，团队约定与实际交付证据决定价值。

参考：[Git Documentation](https://git-scm.com/doc)；[MDN Web Development](https://developer.mozilla.org/en-US/docs/Learn_web_development)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="eng01-01"></a>

### ENG01-01 [P0·基础] merge与rebase怎么选？

**回答：** merge可保留分叉关系且可能快进，rebase重放提交使历史更线性但改变身份。个人分支与共享历史按团队约定使用，不以线性外观凌驾协作安全。

对应讲解：[Git 操作与协作语义](#k03)。

<a id="eng01-02"></a>

### ENG01-02 [P0·原理] reset和revert有何区别？

**回答：** reset移动引用并按模式影响索引/工作区，revert创建抵消改动的新提交。公共历史一般更容易用显式新提交追踪，不能把二者都叫无损撤销。

对应讲解：[Git 操作与协作语义](#k03)。

<a id="eng01-03"></a>

### ENG01-03 [P1·工程取舍] Monorepo解决什么又增加什么？

**回答：** 可统一协作和共享工具，但增加包边界、任务缓存和发布影响管理。它不自动消除耦合，需公开接口和依赖方向，防止幽灵依赖。

对应讲解：[模块边界与 Monorepo](#k02)。

<a id="eng01-04"></a>

### ENG01-04 [P0·工程取舍] 为什么构建通过仍需类型检查和测试？

**回答：** 构建可能只转译，类型检查也不能证明运行行为。安装、静态检查、测试和产物验证覆盖不同风险，应形成一致流水线。

对应讲解：[质量门禁与渐进改造](#k04)。

<a id="eng01-05"></a>

### ENG01-05 [P0·工程取舍] 锁文件之外还要固定什么才能重复构建？

**回答：** 还要明确Node、包管理器、构建工具、配置与环境输入，CI冻结安装并让部署对应已测产物。锁文件不替代安全更新和缓存键设计。

对应讲解：[依赖与构建可重复性](#k01)。
