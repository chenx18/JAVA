## 二、知识讲解

<a id="k01"></a>

### 1. 开发与生产的不同目标

开发服务器通常利用原生ESM按需处理源模块，维护依赖图并提供快速反馈；生产构建则分析完整图，生成分包、压缩和资源引用等部署产物。开发快不等于生产包小，二者需分别测量。

当前官方文档描述生产构建使用Rolldown；旧版Vite资料常围绕Rollup/esbuild，不能把某一历史实现写成所有版本固定原理。依赖预构建的后端、兼容配置和插件行为也应按目标版本核对。

Vite可转译TS/Vue等输入，但完整类型检查通常仍交给tsc/vue-tsc。现代语法转译也不自动补齐所有运行时API。

<a id="k02"></a>

### 2. 模块解析、依赖优化与插件

浏览器源模块、第三方依赖、CSS和静态资源有不同处理。依赖优化可减少大量小模块请求并协调格式，锁文件、依赖变化和缓存失效影响启动；遇到问题先看模块来源和优化日志，不只删整个node_modules。

插件常介入resolveId、load、transform及构建钩子；Vue插件处理SFC。插件次序、转换次数和不必要全量扫描会成为开发性能瓶颈。

```ts
// vite-only: vite.config.ts
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
export default defineConfig({
  plugins: [vue()],
  server: { proxy: { '/api': 'http://localhost:8080' } }
});
```

代理配置属于开发服务器行为，不代表生产部署自动具备同样转发和认证边界。

<a id="k03"></a>

### 3. HMR 的更新边界与清理

文件变化后，服务器根据模块图失效相关模块，寻找可接受更新的边界，通知浏览器应用更新；没有合适边界时可能整页刷新。框架插件可保留部分组件状态，但不保证任意编辑都无损热替换。

```ts
// vite-only: 演示模块资源的热更新清理。
const timer = setInterval(() => console.log('tick'), 1000);
if (import.meta.hot) {
  import.meta.hot.dispose(() => clearInterval(timer));
}
```

HMR不是仅重新加载一份脚本；旧监听、timer和模块缓存若不清理，开发时也会累积副作用。模块接受更新与业务状态迁移需符合插件契约。

<a id="k04"></a>

### 4. 环境变量、资源路径与发布

默认VITE_前缀变量可暴露给客户端构建，不能存长期秘密。mode、NODE_ENV、.env加载顺序和运行时配置是不同概念；静态前端产物中的值可能在构建时已固定。

base影响部署子路径资源引用，动态import生成chunk还需CDN、缓存和旧版本保留策略。source map帮助排错，但发布方式需考虑内部源码暴露和错误平台接入。

排查生产问题时确认安装锁文件、构建版本、目标浏览器、产物URL和网络响应，而不是只看开发服务器正常。

<a id="summary"></a>

## 三、知识小结

Vite按开发模块图、HMR和生产产物分别理解。底层打包器随版本变化，类型检查、API兼容、代理部署和秘密管理仍需独立配置。

参考：[Vite Guide](https://vite.dev/guide/)；[Vite Plugin API](https://vite.dev/guide/api-plugin)。示例按标注环境运行，版本相关能力以目标版本为准。

## 四、面试题与答案

<a id="build01-01"></a>

### BUILD01-01 [P0·原理] Vite为什么开发启动通常较快？

**回答：** 它通常按需转换源模块、利用浏览器ESM并优化依赖，减少启动前完整打包的需求。最终速度仍受模块数量、插件和缓存影响，不能只归因于某一个固定底层工具。

对应讲解：[开发与生产的不同目标](#k01)。

<a id="build01-02"></a>

### BUILD01-02 [P1·原理] HMR为什么可能退回整页刷新？

**回答：** 更新需要可接受变更的模块边界，若影响传播找不到合适边界或插件无法保留结构，就可能刷新。旧资源清理和状态迁移也不是自动万能。

对应讲解：[HMR 的更新边界与清理](#k03)。

<a id="build01-03"></a>

### BUILD01-03 [P0·工程取舍] 开发proxy能否直接解决生产跨域？

**回答：** 不能，它只作用开发服务器。生产需配置真实网关或BFF、origin和凭据策略，后端授权也独立存在。

对应讲解：[模块解析、依赖优化与插件](#k02)。

<a id="build01-04"></a>

### BUILD01-04 [P0·原理] VITE_变量为什么不能放API密钥？

**回答：** 这类变量可进入公开客户端产物，用户可以读取。构建环境变量不是保密容器，长期服务秘密应留在受控服务器。

对应讲解：[环境变量、资源路径与发布](#k04)。
