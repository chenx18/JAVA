> 接口返回 code，前端通过字典把 code 翻译成 label。

## 3. 完整示例

当前部门接口可能返回：

```json
{
  "id": 1,
  "name": "研发部",
  "status": 1
}
```

业务接口只返回数字：

```text
status = 1
```

前端页面不应该直接显示 `1`，而是显示：

```text
Enabled
```

所以后端可以提供一个字典接口：

```http
GET /dict/department-status
```

返回：

```json
{
  "code": 200,
  "message": "success",
  "data": [
    { "label": "Disabled", "value": 0 },
    { "label": "Enabled", "value": 1 }
  ]
}
```

前端拿到部门数据：

```json
{
  "id": 1,
  "name": "研发部",
  "status": 1
}
```

再拿到字典：

```json
[
  { "label": "Disabled", "value": 0 },
  { "label": "Enabled", "value": 1 }
]
```

前端就可以翻译：

```text
1 -> Enabled
0 -> Disabled
```

这就是数据字典最基础的作用。

## 4. 完整代码示例

### 4.1 DictOptionResponse

字典选项返回对象：

```java
package com.example.week4.common.response;

import lombok.Data;

@Data
public class DictOptionResponse {

  private String label;

  private Integer value;
}
```

它最终对应前端看到的一项：

```json
{ "label": "Enabled", "value": 1 }
```

---

### 4.2 DictService

字典数据来自 `DepartmentStatusEnum`：

```java
package com.example.week4.project.system.service;

import java.util.Arrays;
import java.util.List;

import org.springframework.stereotype.Service;

import com.example.week4.common.enums.DepartmentStatusEnum;
import com.example.week4.common.response.DictOptionResponse;

@Service
public class DictService {

  public List<DictOptionResponse> getDepartmentStatusOptions() {
    return Arrays.stream(DepartmentStatusEnum.values())
        .map(status -> {
          DictOptionResponse option = new DictOptionResponse();
          option.setLabel(status.getLabel());
          option.setValue(status.getCode());
          return option;
        })
        .toList();
  }
}
```

这里的核心是：

```java
DepartmentStatusEnum.values()
```

意思是：

```text
拿到 DepartmentStatusEnum 里的所有枚举项
```

当前枚举有：

```text
DISABLED
ENABLED
```

所以最终生成两个字典选项。

---

### 4.3 DictController

字典接口：

```java
package com.example.week4.project.system.controller;

import java.util.List;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import com.example.week4.common.response.ApiResponse;
import com.example.week4.common.response.DictOptionResponse;
import com.example.week4.project.system.service.DictService;

import lombok.RequiredArgsConstructor;

@RequiredArgsConstructor
@RestController
@RequestMapping("/dict")
public class DictController {

  private final DictService service;

  @GetMapping("/department-status")
  public ApiResponse<List<DictOptionResponse>> getDepartmentStatusDict() {
    return ApiResponse.success(service.getDepartmentStatusOptions());
  }
}
```

访问：

```http
GET /dict/department-status
```

返回：

```json
{
  "code": 200,
  "message": "success",
  "data": [
    { "label": "Disabled", "value": 0 },
    { "label": "Enabled", "value": 1 }
  ]
}
```

## 5. 这个示例的完整流程

```text
前端请求 /dict/department-status
  ↓
DictController 接请求
  ↓
DictService 读取 DepartmentStatusEnum.values()
  ↓
把 enum 转成 label/value
  ↓
ApiResponse 返回给前端
  ↓
前端用 value 匹配业务数据里的 status
  ↓
前端显示 label
```

一句话：

> 字典接口负责告诉前端：每个 code 应该显示成什么文字。

## 6. 为什么不直接在部门接口返回 statusLabel

部门接口可以这样返回：

```json
{
  "id": 1,
  "name": "研发部",
  "status": 1,
  "statusLabel": "Enabled"
}
```

这属于可用写法。

但很多后台管理系统更常见的是：

```json
{
  "id": 1,
  "name": "研发部",
  "status": 1
}
```

然后前端通过字典翻译。

原因：

```text
1. 业务接口更干净，只返回业务字段
2. 多个页面可以复用同一套字典
3. 表格、搜索、下拉框都能用同一个字典
4. 多语言时 label 可能由前端统一处理
5. code 比 label 更稳定
```

所以实际常见模式是：

```text
业务接口返回 code
字典接口返回 code -> label
前端负责展示翻译
```

## 7. 什么是数据字典

数据字典就是一组固定或半固定的选项。

例如部门状态：

```json
[
  { "label": "禁用", "value": 0 },
  { "label": "启用", "value": 1 }
]
```

用户性别：

```json
[
  { "label": "男", "value": 1 },
  { "label": "女", "value": 2 },
  { "label": "未知", "value": 0 }
]
```

订单状态：

```json
[
  { "label": "待支付", "value": 0 },
  { "label": "已支付", "value": 1 },
  { "label": "已取消", "value": 2 }
]
```

一句话：

> 字典就是 code 和 label 的对应表。

---

## 8. enum 和数据字典的区别

`enum` 是后端代码里的固定选项。

```java
public enum DepartmentStatusEnum {
  DISABLED(0, "Disabled"),
  ENABLED(1, "Enabled");
}
```

数据字典是给接口或前端使用的一组选项。

```json
[
  { "label": "Disabled", "value": 0 },
  { "label": "Enabled", "value": 1 }
]
```

区别：

```text
enum：后端代码内部使用
字典：通常给前端展示、下拉框、表格翻译使用
```

它们可以互相配合：

```text
后端 enum 管理状态规则
  ↓
后端提供字典接口
  ↓
前端请求字典
  ↓
前端用字典把 status 数字显示成文字
```

---

## 9. DictOptionResponse 为什么放 common/response

`DictOptionResponse` 是一种通用返回对象。

不仅部门状态能用：

```text
department-status
```

以后这些也能用：

```text
user-status
role-type
gender
order-status
```

所以它可以放在：

```text
common/response/DictOptionResponse.java
```

因为它不是某个具体业务表的 Entity，而是接口返回结构。

---

## 10. DictService 为什么不需要 Mapper

当前字典来自 enum：

```text
DepartmentStatusEnum
```

不是来自数据库。

所以不需要：

```text
Mapper
XML
数据库表
```

当前链路是：

```text
DictService -> DepartmentStatusEnum
```

不是：

```text
DictService -> DictMapper -> dict_data
```

后面如果字典要后台配置，再上数据库字典表。

## 11. 前端怎么用字典

前端先请求字典：

```http
GET /dict/department-status
```

拿到：

```js
const dict = [
  { label: 'Disabled', value: 0 },
  { label: 'Enabled', value: 1 }
]
```

再请求部门列表：

```http
GET /departments/list
```

拿到：

```js
const row = { id: 1, name: '研发部', status: 1 }
```

展示时：

```js
const statusLabel = dict.find(item => item.value === row.status)?.label
```

结果：

```text
Enabled
```

## 12. 核心知识沉淀：字典不一定都来自 enum

不是所有字典都应该写 enum。

### 12.1 适合 enum 的字典

```text
启用/禁用
男/女/未知
是否删除
是否默认
```

特点：

```text
选项少
变化少
和代码逻辑强相关
```

### 12.2 适合数据库字典表的字典

```text
民族
学历
地区
业务类型
设备类型
告警类型
```

特点：

```text
选项多
可能后台配置
可能经常变化
可能需要排序、备注、颜色、权限
```

所以：

```text
稳定且和代码逻辑强相关：enum
经常变化且需要后台配置：数据库字典表
```

---

## 13. 核心知识沉淀：字典和业务表不是一回事

业务表：

```text
department
user
role
order
```

字典表：

```text
dict_type
dict_data
```

业务表保存业务数据。

字典表保存选项数据。

例如：

```text
department.status = 1
```

这里的 `1` 是业务表里的状态值。

字典负责解释：

```text
1 = 启用
```

---

## 14. 实际开发注意点：字典接口通常会缓存

字典数据变化不频繁。

所以真实项目里经常会：

```text
前端缓存字典
后端缓存字典
Redis 缓存字典
```

原因：

```text
每个页面都可能用字典
没有必要每次都重新查数据库
```

此处不需要展开 Redis，只需要知道：

> 字典是非常适合缓存的数据。

## 15. 实际开发中更完整的字典表

后面如果用数据库字典表，常见结构是：

```text
dict_type
  id
  dict_type
  dict_name
  status

dict_data
  id
  dict_type
  dict_label
  dict_value
  sort
  status
```

例如：

```text
dict_type = department_status
dict_label = 启用
dict_value = 1
```

这套更接近 RuoYi 这类后台管理系统。

但实际实现时不建议一开始就上完整字典表。

先走：

```text
enum -> 字典接口 -> 前端展示
```

更适合建立理解。

## 17. 常见误区

### 17.1 把字典写进业务列表接口

不推荐每个列表接口都额外返回完整字典。

例如每次 `/departments/list` 都返回：

```json
{
  "rows": [],
  "dict": []
}
```

这样会让业务接口变乱。

更推荐：

```text
/departments/list 返回业务数据
/dict/department-status 返回字典数据
```

---

### 17.2 Controller 里写太多转换逻辑

可以在 Controller 里直接转换 enum，但实际开发更推荐：

```text
Controller 接请求
Service 组装数据
```

所以使用：

```text
DictController -> DictService -> Enum
```

---

### 17.3 所有字典都写 enum

不是所有字典都适合 enum。

如果字典项经常变化，应该考虑数据库字典表。

## 18. 面试小题

如果面试问：

> 后台管理系统里的状态字段怎么给前端展示？

可以这样回答：

```text
数据库里一般保存状态 code，比如 0 表示禁用，1 表示启用。
业务接口通常返回 code，前端通过字典把 code 翻译成 label。
如果状态比较固定，可以在后端用 enum 管理，并提供一个字典接口把 enum 转成 label/value 列表。
如果字典项很多或者需要后台配置，就会设计 dict_type、dict_data 这类字典表。
字典数据变化不频繁，实际项目里前端或后端通常会做缓存。
```

## 19. 本节小结

现在重点掌握：

```text
1. 状态字段通常返回 code
2. 前端通过字典把 code 翻译成 label
3. enum 是后端内部管理状态含义
4. 字典接口是给前端拿选项
5. 稳定选项可以来自 enum
6. 经常变化的选项更适合数据库字典表
7. 字典数据通常适合缓存
```
