# Auth 登录认证与权限专题

`19-auth` 用于沉淀登录、认证、授权、登录态和权限体系。

它属于 Spring Boot 主线中的第 19 章展开专题：前面已经掌握 Controller、Service、Mapper、MyBatis、事务、字典等基础能力后，再进入登录权限体系。

## 3. 实际开发中的登录后初始化流程

后台管理系统登录成功后，前端通常不会只保存 token 就结束，而是会继续调用一组基础接口完成初始化。

常见流程：

```text
POST /user/login
  ↓
返回 JWT
  ↓
GET /user/info
  ↓
获取当前用户信息、角色、权限标识
  ↓
GET /user/menus 或 /getRouters
  ↓
获取当前用户可访问菜单 / 路由树
  ↓
进入系统首页
```

对应接口：

| 接口 | 作用 | 对应文档 |
| --- | --- | --- |
| `POST /user/login` | 登录并返回 JWT | `01-登录流程-JWT生成.md` |
| `GET /user/info` | 获取当前登录用户信息 | `04-获取当前登录用户.md` |
| `GET /user/menus` / `GET /getRouters` | 获取当前用户菜单树 / 路由树 | `06-菜单权限基础.md` |
| `GET /user/perms` | 获取按钮权限标识列表 | `06-菜单权限基础.md` |
| `POST /user/logout` | 退出登录，让 token 失效 | `07-Redis登录态.md` |

前端通常会把这些数据保存到状态管理中：

```text
token：请求接口时放到 Authorization
userInfo：页面展示用户昵称、头像等
menus / routers：动态生成侧边栏和路由
permissions：控制按钮是否显示
```

`19-auth` 的文档会按真实后台开发流程组织，不为了概念而过度拆分。

## 4. 登录基础与登录信息的区别

登录基础解决：

```text
怎么登录
怎么生成 token
怎么校验 token
密码怎么安全存
```

登录信息与权限解决：

```text
当前是谁在操作
这个人有什么角色
这个人能访问什么菜单
这个 token 是否仍然有效
```

可以这样理解：

```text
登录基础 = 进门
登录信息与权限 = 进门后能去哪些房间
```

## 5. 与 Spring Boot 主线的关系

`19-auth` 不是孤立专题，它依赖前面的基础：

```text
Controller 接口
  ↓
Request DTO
  ↓
Service 业务判断
  ↓
Mapper 查询数据库
  ↓
ApiResponse 统一返回
  ↓
GlobalExceptionHandler 统一异常
  ↓
Interceptor 拦截请求
```

所以登录认证不是重新学一套结构，而是在已有 CRUD 分层能力上增加认证和权限逻辑。

## 7. 小结

登录权限体系可以分成两层：

```text
登录认证：证明用户是谁
权限授权：判断用户能做什么
```

`19-auth` 的目标是把这两层逐步拆开，每篇只解决一个核心问题，避免把登录、JWT、密码、角色、菜单、Redis 全部混在一篇文档里。
