# 角色权限基础

角色权限用于解决“用户登录后，不同用户能访问不同功能”的问题。

登录只能证明用户是谁，角色权限用于判断用户能做什么。

---

## 1. 本节目录 / 学习目标

本节按以下路线学习：

```text
用户 User
  ↓
角色 Role
  ↓
用户角色关系 UserRole
  ↓
根据 userId 查询角色列表
  ↓
Service 判断是否拥有某个角色
  ↓
接口根据角色决定是否允许访问
```

学完本节应能掌握：

- 用户和角色为什么是多对多关系
- `sys_role` 和 `sys_user_role` 如何设计
- 如何根据用户 id 查询角色
- 如何判断当前用户是否拥有某个角色
- 角色权限和菜单权限有什么区别

---

## 2. 为什么需要角色

登录只能说明：

```text
用户身份有效
```

但系统还需要知道：

```text
这个用户是不是管理员
这个用户能不能新增用户
这个用户能不能删除部门
这个用户能不能查看系统设置
```

角色就是对用户身份的一种业务分组。

常见角色：

```text
admin：管理员
manager：主管
user：普通用户
auditor：审计员
```

---

## 3. 表设计

用户和角色通常是多对多关系：

```text
一个用户可以有多个角色
一个角色可以分配给多个用户
```

所以需要三张表：

```text
sys_user
sys_role
sys_user_role
```

角色表：

```sql
create table sys_role (
  id int primary key auto_increment,
  role_key varchar(50) not null unique,
  role_name varchar(50) not null,
  status int not null default 1
);
```

用户角色关系表：

```sql
create table sys_user_role (
  user_id int not null,
  role_id int not null,
  primary key (user_id, role_id)
);
```

测试数据：

```sql
insert into sys_role (role_key, role_name, status)
values ('admin', '管理员', 1), ('user', '普通用户', 1);

insert into sys_user_role (user_id, role_id)
values (1, 1);
```

表示用户 `1` 拥有 `admin` 角色。

## 5. RoleMapper

```java
import java.util.List;

import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Param;

import com.example.week4.project.system.domain.Role;

@Mapper
public interface RoleMapper {

  List<Role> findRolesByUserId(@Param("userId") Integer userId);

  List<String> findRoleKeysByUserId(@Param("userId") Integer userId);
}
```

## 6. RoleMapper.xml

```xml
<mapper namespace="com.example.week4.project.system.mapper.RoleMapper">

  <resultMap id="RoleResultMap" type="com.example.week4.project.system.domain.Role">
    <id property="id" column="id" />
    <result property="roleKey" column="role_key" />
    <result property="roleName" column="role_name" />
    <result property="status" column="status" />
  </resultMap>

  <select id="findRolesByUserId" resultMap="RoleResultMap">
    select r.id, r.role_key, r.role_name, r.status
    from sys_role r
    inner join sys_user_role ur on r.id = ur.role_id
    where ur.user_id = #{userId}
      and r.status = 1
  </select>

  <select id="findRoleKeysByUserId" resultType="string">
    select r.role_key
    from sys_role r
    inner join sys_user_role ur on r.id = ur.role_id
    where ur.user_id = #{userId}
      and r.status = 1
  </select>

</mapper>
```

核心 SQL：

```text
sys_user_role 连接 sys_role
```

## 7. RoleService

```java
@RequiredArgsConstructor
@Service
public class RoleService {

  private final RoleMapper roleMapper;

  public List<String> getRoleKeysByUserId(Integer userId) {
    if (userId == null) {
      throw new IllegalArgumentException("userId is null");
    }
    return roleMapper.findRoleKeysByUserId(userId);
  }

  public boolean hasRole(Integer userId, String roleKey) {
    if (userId == null || roleKey == null || roleKey.isBlank()) {
      return false;
    }

    List<String> roleKeys = roleMapper.findRoleKeysByUserId(userId);
    return roleKeys.contains(roleKey);
  }
}
```

## 8. 在业务中判断角色

示例：只有管理员可以删除用户。

```java
public void deleteByIds(List<Integer> ids) {
  Integer currentUserId = LoginUserContext.getUserId();

  if (!roleService.hasRole(currentUserId, "admin")) {
    throw new IllegalArgumentException("no permission");
  }

  userMapper.deleteByIds(ids);
}
```

流程：

```text
从 LoginUserContext 获取当前用户 id
  ↓
根据 userId 查询角色
  ↓
判断是否包含 admin
  ↓
有权限继续执行
  ↓
无权限抛出异常
```

## 9. 是否要把角色放进 JWT

可以放，但不建议作为最终权限判断依据。

优点：

```text
少查一次数据库
```

缺点：

```text
用户角色变更后，旧 JWT 里的角色不会立刻变化
```

学习阶段推荐：

```text
JWT 中只放 userId / userName
角色从数据库查询
```

后续接入 Redis 后，可以把角色权限缓存起来。

## 10. 角色权限和菜单权限的区别

角色权限回答：

```text
这个用户是什么角色
```

菜单权限回答：

```text
这个角色能看到哪些菜单
这个角色能点击哪些按钮
```

关系：

```text
用户 -> 角色 -> 菜单 / 按钮权限
```

## 11. 实际开发注意点

- 用户和角色通常是多对多关系。
- `role_key` 用于代码判断，`role_name` 用于页面展示。
- 禁用角色不应该参与权限判断。
- 简单项目可以在 Service 中判断角色。
- 复杂项目通常会使用权限注解或 Spring Security。

## 12. 面试小题

### 12.1 用户和角色是什么关系？

答：通常是多对多关系。一个用户可以有多个角色，一个角色可以分配给多个用户，因此需要用户角色关系表。

### 12.2 `role_key` 和 `role_name` 有什么区别？

答：`role_key` 是稳定的角色标识，用于代码判断；`role_name` 是展示名称，用于页面显示。

### 12.3 为什么不建议写 `userId == 1` 判断管理员？

答：这样强耦合具体数据，不可维护。应该通过用户角色关系判断用户是否拥有某个角色。
