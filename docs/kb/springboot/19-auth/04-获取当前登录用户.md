# 获取当前登录用户

获取当前登录用户用于解决“请求已经通过 JWT 校验后，Controller 或 Service 如何知道当前是谁在操作”的问题。

登录拦截器只判断 token 是否有效还不够，实际业务经常需要知道当前用户 id、用户名、角色等信息。

---

## 1. 本节目录 / 学习目标

本节按以下路线学习：

```text
请求携带 JWT
  ↓
LoginInterceptor 解析 JWT
  ↓
从 Claims 中取出 userId / userName
  ↓
保存到当前请求上下文
  ↓
Controller / Service 获取当前登录用户
  ↓
请求结束后清理上下文
```

学完本节应能掌握：

- 为什么需要当前登录用户
- JWT 解析后如何取出用户信息
- `ThreadLocal` 是什么
- 为什么请求结束后要清理 `ThreadLocal`
- Controller / Service 如何获取当前用户 id

---

## 2. 为什么需要当前登录用户

常见场景：

```text
新增数据时记录 create_by
修改数据时记录 update_by
查询个人数据
判断当前用户是否有权限操作某条数据
写操作日志
```

不推荐让前端传当前用户 id：

```http
POST /order/create?userId=2
```

因为前端参数可以伪造。

推荐：

```text
前端只传 JWT
后端从 JWT 中解析当前用户
```

## 3. 当前登录用户对象

建议新建：

```text
framework/security/LoginUser.java
```

代码：

```java
package com.example.week4.framework.security;

import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;

@Data
@NoArgsConstructor
@AllArgsConstructor
public class LoginUser {

  private Integer userId;

  private String userName;
}
```

---

## 4. 当前用户上下文

建议新建：

```text
framework/security/LoginUserContext.java
```

代码：

```java
package com.example.week4.framework.security;

public class LoginUserContext {

  private static final ThreadLocal<LoginUser> LOCAL = new ThreadLocal<>();

  public static void set(LoginUser loginUser) {
    LOCAL.set(loginUser);
  }

  public static LoginUser get() {
    return LOCAL.get();
  }

  public static Integer getUserId() {
    LoginUser loginUser = get();
    return loginUser == null ? null : loginUser.getUserId();
  }

  public static String getUserName() {
    LoginUser loginUser = get();
    return loginUser == null ? null : loginUser.getUserName();
  }

  public static void remove() {
    LOCAL.remove();
  }
}
```

理解：

```text
ThreadLocal 可以给当前线程保存一份数据
一次 HTTP 请求通常由一个线程处理
所以可以把当前登录用户临时放到 ThreadLocal 中
```

## 5. 在拦截器中写入当前用户

在 `LoginInterceptor` 中解析 JWT 后写入上下文：

```java
try {
  Claims claims = jwtUtil.parseToken(token);
  Integer userId = Integer.valueOf(claims.getSubject());
  String userName = claims.get("userName", String.class);

  LoginUserContext.set(new LoginUser(userId, userName));
  return true;
} catch (Exception e) {
  writeUnauthorized(response, "invalid token");
  return false;
}
```

需要补充的 import：

```java
import com.example.week4.framework.security.LoginUser;
import com.example.week4.framework.security.LoginUserContext;
import io.jsonwebtoken.Claims;
```

这里和只校验 JWT 的区别是：

```text
原来：jwtUtil.parseToken(token) 只判断 token 是否有效
现在：jwtUtil.parseToken(token) 解析出 Claims，并把当前用户放进 LoginUserContext
```

同时要在请求结束后清理：

```java
@Override
public void afterCompletion(HttpServletRequest request, HttpServletResponse response, Object handler, Exception ex) {
  LoginUserContext.remove();
}
```

完整流程：

```text
parseToken 解析 JWT
  ↓
claims.getSubject() 取 userId
  ↓
claims.get("userName") 取用户名
  ↓
LoginUserContext.set 保存当前用户
  ↓
afterCompletion 中 remove 清理
```

## 6. Controller 中获取当前用户

示例：

```java
@GetMapping("/current")
public ApiResponse<LoginUser> currentUser() {
  return ApiResponse.success(LoginUserContext.get());
}
```

### 6.1 实际开发中的用户信息接口

后台管理系统登录成功后，前端通常会马上调用用户信息接口：

```http
GET /user/info
Authorization: Bearer JWT
```

这个接口用于返回当前登录用户的基础信息。实际开发中常见返回内容：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "userId": 1,
    "userName": "admin",
    "nickName": "管理员",
    "roles": ["admin"],
    "permissions": ["system:user:list", "system:user:add"]
  }
}
```

学习阶段可以先返回简化版：

```java
@GetMapping("/info")
public ApiResponse<LoginUser> getUserInfo() {
  return ApiResponse.success(LoginUserContext.get());
}
```

实际项目通常会继续查询数据库，补齐昵称、头像、角色、权限等信息：

```text
LoginUserContext.getUserId()
  ↓
查询 sys_user
  ↓
查询用户角色
  ↓
查询权限标识
  ↓
组装 UserInfoResponse
```

可以新建响应对象：

```java
@Data
public class UserInfoResponse {

  private Integer userId;

  private String userName;

  private String nickName;

  private List<String> roles;

  private List<String> permissions;
}
```

这样前端登录后的初始化流程会更接近真实后台系统：

```text
login 返回 token
  ↓
/user/info 返回用户信息
  ↓
/user/menus 返回菜单路由
  ↓
进入首页
```

请求：

```http
GET /user/current
Authorization: Bearer JWT
```

返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "userId": 1,
    "userName": "admin"
  }
}
```

## 7. Service 中获取当前用户

示例：

```java
public void createDepartment(DepartmentCreateRequest request) {
  Integer currentUserId = LoginUserContext.getUserId();

  if (currentUserId == null) {
    throw new IllegalArgumentException("please login");
  }

  Department department = new Department();
  department.setName(request.getName());
  department.setCreateBy(currentUserId);

  departmentMapper.insert(department);
}
```

实际开发常见字段：

```text
create_by：创建人
create_time：创建时间
update_by：修改人
update_time：修改时间
```

---

## 8. 为什么必须 remove

Web 服务通常使用线程池，线程会复用。

如果不清理 `ThreadLocal`：

```text
上一个请求的数据可能残留
  ↓
下一个请求可能读到错误用户
```

所以必须：

```java
LoginUserContext.remove();
```

---

## 9. ThreadLocal 和 request attribute

也可以使用 request attribute：

```java
request.setAttribute("loginUser", loginUser);
```

两种方式对比：

| 方式 | 优点 | 缺点 |
| --- | --- | --- |
| request attribute | 和请求绑定清晰，不容易泄漏 | Service 层不方便直接拿 |
| ThreadLocal | Controller / Service 都能直接拿 | 必须手动 remove |

学习阶段可以先使用 `ThreadLocal`，更容易理解“当前登录用户上下文”。

---

## 10. 实际开发注意点

- 不要让前端传 `userId` 表示当前登录人。
- 当前用户应由后端从 JWT 或登录态中解析。
- `ThreadLocal` 使用后必须清理。
- JWT 中不建议放太多用户信息。
- 获取当前用户只是身份上下文，不等于权限校验。

## 11. 面试小题

### 11.1 如何在后端获取当前登录用户？

答：通常在拦截器或过滤器中解析 token，取出用户 id，再放入请求上下文、ThreadLocal 或 Spring Security Context。

### 11.2 ThreadLocal 最大注意点是什么？

答：使用后必须清理，尤其在 Web 线程池场景下，否则可能造成数据污染或内存泄漏。

### 11.3 为什么不让前端直接传 userId？

答：前端参数可以被伪造，不能作为当前登录人的可信来源。

## 12. 小结

```text
JWT 中保存 userId
  ↓
拦截器解析 JWT
  ↓
生成 LoginUser
  ↓
放入 LoginUserContext
  ↓
Controller / Service 读取当前用户
  ↓
请求结束 remove
```

完成本节后，后端就不只是“知道用户已登录”，还可以知道“当前是谁在操作”。
