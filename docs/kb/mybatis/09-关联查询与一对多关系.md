# 关联查询与一对多关系

## 1. 本节完整流程

以“部门”和“部门操作日志”为例：

```text
department
  ↓
department_log
```

它们之间的关系是：

```text
一个部门可以有多条操作日志
```

对应到数据库字段：

```text
department.id
  ↓
department_log.department_id
```

查询接口流程：

```text
Controller 接收部门 ID
  ↓
Service 校验部门 ID 是否合法
  ↓
Service 判断部门是否存在
  ↓
Mapper 根据 department_id 查询日志
  ↓
返回日志列表
```

接口示例：

```http
GET /departments/{id}/logs
```

---

## 2. 什么是一对多关系

一对多就是：

```text
一条主表数据
  ↓
对应多条子表数据
```

例如：

```text
一个部门 -> 多条操作日志
一个用户 -> 多个订单
一个角色 -> 多个用户
一个订单 -> 多个订单明细
```

在示例项目中：

```text
department 是主表
department_log 是子表
```

子表通过 `department_id` 记录自己属于哪个部门。

---

## 3. 表结构示例

部门表：

```sql
create table department (
  id int primary key auto_increment,
  name varchar(50) not null unique,
  description varchar(255),
  status int default 1
);
```

部门日志表：

```sql
create table department_log (
  id int primary key auto_increment,
  department_id int not null,
  operation varchar(50) not null,
  content varchar(255),
  create_time datetime not null
);
```

重点字段：

```text
department_log.department_id
```

它用来关联：

```text
department.id
```

---

## 4. Java 实体类

`DepartmentLog` 用来接收 `department_log` 表的数据。

```java
@Data
public class DepartmentLog {

  private Integer id;

  private Integer departmentId;

  private String operation;

  private String content;

  private LocalDateTime createTime;
}
```

注意字段命名：

```text
数据库字段：department_id
Java 属性：departmentId

数据库字段：create_time
Java 属性：createTime
```

数据库常用下划线命名，Java 常用小驼峰命名。

---

## 5. Mapper 接口写法

```java
@Mapper
public interface DepartmentLogMapper {

  int insert(DepartmentLog log);

  List<DepartmentLog> findByDepartmentId(@Param("departmentId") Integer departmentId);
}
```

这里有两个重点。

第一，查询多条数据要返回 List：

```java
List<DepartmentLog>
```

因为一个部门可以有多条日志。

第二，`@Param("departmentId")` 的名字要和 XML 里的参数一致：

```xml
#{departmentId}
```

---

## 6. Mapper XML 写法

```xml
<select id="findByDepartmentId" resultType="com.example.week4.project.system.domain.DepartmentLog">
  select
    id,
    department_id as departmentId,
    operation,
    content,
    create_time as createTime
  from department_log
  where department_id = #{departmentId}
  order by id desc
</select>
```

### 6.1 id 必须和接口方法名一致

Mapper 接口：

```java
List<DepartmentLog> findByDepartmentId(...);
```

XML：

```xml
<select id="findByDepartmentId">
```

这两个必须一致。

如果接口写：

```java
findByDepartmentIds
```

XML 写：

```xml
findByDepartmentId
```

运行时 MyBatis 会找不到对应 SQL。

---

## 7. 为什么要写 as 别名

SQL 中：

```sql
department_id as departmentId
create_time as createTime
```

原因是数据库字段名和 Java 属性名不一样。

如果不写别名，MyBatis 可能无法准确把值放进 Java 对象。

数据库返回：

```text
department_id
```

Java 对象需要：

```text
departmentId
```

所以写：

```sql
department_id as departmentId
```

意思是：

```text
把数据库的 department_id 映射到 Java 的 departmentId
```

## 8. Service 写法

```java
public List<DepartmentLog> getDepartmentLogs(int departmentId) {
  if (departmentId <= 0) {
    throw new IllegalArgumentException("department id must be > 0");
  }

  if (!mapper.existsById(departmentId)) {
    throw new DepartmentNotFoundException(departmentId);
  }

  return logMapper.findByDepartmentId(departmentId);
}
```

这里不需要 `@Transactional`。

原因：

```text
这个方法只查询数据，没有修改数据库
```

查询日志的职责：

```text
1. 校验参数
2. 判断部门是否存在
3. 调 Mapper 查询日志列表
```

---

## 9. Controller 写法

```java
@GetMapping("/{id}/logs")
public ApiResponse<List<DepartmentLog>> getDepartmentLogs(
    @Parameter(description = "Department ID") @PathVariable int id) {
  return ApiResponse.success(service.getDepartmentLogs(id));
}
```

注意返回类型：

```java
ApiResponse<List<DepartmentLog>>
```

因为项目使用统一返回格式：

```json
{
  "code": 200,
  "message": "success",
  "data": []
}
```

如果方法声明成：

```java
public List<DepartmentLog> getDepartmentLogs(...)
```

但是实际返回：

```java
ApiResponse.success(...)
```

就会类型不匹配。

## 11. 删除后还能不能查日志

示例代码中，查询日志前会判断部门是否存在：

```java
if (!mapper.existsById(departmentId)) {
  throw new DepartmentNotFoundException(departmentId);
}
```

所以如果部门被删除了，再查：

```http
GET /departments/{id}/logs
```

可能会返回部门不存在。

但实际审计系统中，日志通常希望长期保留，即使部门被删除，也仍然可以查日志。

后续可以优化成：

```text
查部门详情时要求部门存在
查操作日志时不一定要求部门仍然存在
```

这是业务设计问题，不是 MyBatis 写法问题。

## 12. 常见误区

### 12.1 接口方法名和 XML id 不一致

不推荐写法：

```java
findByDepartmentIds()
```

```xml
<select id="findByDepartmentId">
```

正确：

```java
findByDepartmentId()
```

```xml
<select id="findByDepartmentId">
```

### 12.2 Service 方法写成 private

不推荐写法：

```java
private List<DepartmentLog> getDepartmentLogs(int departmentId)
```

Controller 需要调用它，所以应该写：

```java
public List<DepartmentLog> getDepartmentLogs(int departmentId)
```

### 12.3 Controller 返回类型不一致

不推荐写法：

```java
public List<DepartmentLog> getDepartmentLogs(...) {
  return ApiResponse.success(...);
}
```

正确：

```java
public ApiResponse<List<DepartmentLog>> getDepartmentLogs(...) {
  return ApiResponse.success(...);
}
```

### 12.4 URL 用单数 log

能用：

```http
/departments/{id}/log
```

但更推荐：

```http
/departments/{id}/logs
```

因为返回的是日志列表。

## 13. 本节小结

本节重点不是复杂 JOIN，而是先掌握：

```text
1. 一对多关系是什么意思
2. 子表通过外键字段关联主表 ID
3. Mapper 接口方法名要和 XML id 一致
4. 数据库下划线字段要映射到 Java 小驼峰属性
5. 查询多条记录返回 List<T>
6. Controller 返回统一 ApiResponse<List<T>>
```
