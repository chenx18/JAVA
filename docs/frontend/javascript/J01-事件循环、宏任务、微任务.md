# 事件循环、宏任务、微任务

> 专题：JavaScript 核心  
> 编号：J01

### 一句话答案

事件循环负责调度同步代码和异步回调；同步代码先执行，当前宏任务结束后会先清空微任务，再进入下一轮宏任务。

### 核心原理

```text
调用栈执行同步代码
异步任务完成后进入任务队列
Promise 回调进入微任务队列
setTimeout 回调进入宏任务队列
当前宏任务结束后清空微任务队列
```

### 项目里怎么用

- 判断异步日志输出顺序。
- 理解 Vue `nextTick`、React 状态更新后的读取时机。
- 排查长任务阻塞渲染。

### 常见坑

- 认为定时器时间到了就一定马上执行。
- 在微任务里做大量循环导致页面无法及时渲染。

### 面试表达

事件循环是 JS 单线程还能处理异步任务的基础。Promise 属于微任务，定时器属于宏任务，所以同一轮事件循环里 Promise 回调通常会先于定时器执行。

## 继续讲解

### 先建立心智模型

可以把浏览器里的 JavaScript 执行理解成三块：

```text
调用栈 Call Stack
任务队列 Task Queue
事件循环 Event Loop
```

调用栈负责执行当前代码。JS 一次只能执行栈顶的一个任务，所以同步代码会一行一行往下走。

异步代码不是“另开一个 JS 线程执行回调”，而是先交给浏览器或运行环境处理。等时机到了，回调再被放回任务队列，等待事件循环把它拿出来执行。

所以事件循环解决的问题是：

```text
JS 是单线程的
但浏览器里有定时器、点击事件、网络请求、Promise 回调
这些异步结果什么时候回到 JS 主线程执行
```

---

### 宏任务和微任务的执行规则

面试里可以记住这个顺序：

```text
1. 执行一个宏任务
2. 执行这个宏任务里的所有同步代码
3. 清空当前产生的所有微任务
4. 浏览器有机会进行页面渲染
5. 执行下一个宏任务
```

注意重点是“清空微任务”，不是“执行一个微任务”。

如果微任务执行过程中又产生新的微任务，新产生的微任务也会继续执行，直到微任务队列为空。

---

### 常见宏任务

```text
script 整体代码
setTimeout
setInterval
setImmediate，Node.js 中
I/O
UI 事件，例如 click、input
postMessage
```

页面第一次加载时，整段 `<script>` 本身就是一个宏任务。

---

### 常见微任务

```text
Promise.then / catch / finally
queueMicrotask
MutationObserver
process.nextTick，Node.js 中
```

前端面试里最常见的是：

```text
Promise.then
setTimeout
async / await
```

## 经典执行顺序题

### 示例代码

```js
console.log('1');

setTimeout(() => {
  console.log('2');
}, 0);

Promise.resolve().then(() => {
  console.log('3');
});

console.log('4');
```

### 输出结果

```text
1
4
3
2
```

### 执行过程

```text
1. 整段 script 是一个宏任务，开始执行
2. console.log('1') 同步执行，输出 1
3. setTimeout 回调进入宏任务队列
4. Promise.then 回调进入微任务队列
5. console.log('4') 同步执行，输出 4
6. 当前宏任务的同步代码执行完
7. 清空微任务队列，输出 3
8. 进入下一个宏任务，执行 setTimeout 回调，输出 2
```

面试时不要只背答案，要能把这 8 步讲出来。

## async / await 怎么看

`async / await` 本质还是 Promise。

可以先记住一句话：

```text
await 后面的代码，可以理解成被放进 Promise.then 里的微任务。
```

### 示例代码

```js
async function test() {
  console.log('1');
  await Promise.resolve();
  console.log('2');
}

console.log('3');
test();
console.log('4');
```

### 输出结果

```text
3
1
4
2
```

### 执行过程

```text
1. 先执行 console.log('3')，输出 3
2. 调用 test()
3. test 内部先同步输出 1
4. 遇到 await，test 后续代码暂停
5. await 后面的 console.log('2') 进入微任务
6. 回到外层继续执行 console.log('4')，输出 4
7. 当前宏任务同步代码结束
8. 执行微任务，输出 2
```

## 为什么微任务优先级更高

微任务通常用于处理“当前任务结束后马上要做的收尾工作”。

比如：

```text
Promise 状态变更后的 then 回调
框架内部批量更新后的回调
DOM 变化观察
```

这些事情通常希望在进入下一个宏任务之前完成，这样状态更连贯。

所以可以这样理解：

```text
宏任务负责开启一轮大的工作
微任务负责在这一轮工作结束后立刻收尾
```

## 和页面渲染的关系

浏览器一般会在一轮宏任务结束、微任务清空之后，找机会进行页面渲染。

所以如果微任务一直执行不完，页面可能迟迟没有机会渲染。

### 示例

```js
function loop() {
  Promise.resolve().then(loop);
}

loop();
```

这段代码会不断创建微任务，导致微任务队列一直清不空。结果是浏览器很难进入渲染阶段，页面可能卡死。

这也是为什么不能在微任务里做大量循环或无限递归。

---

## 和 Vue nextTick 的关系

Vue 更新数据后，不会每改一次数据就立刻更新 DOM，而是把多次数据变化合并起来，等当前同步代码执行完后再统一刷新。

所以：

```js
count.value++;
console.log(el.textContent); // 可能还是旧 DOM

await nextTick();
console.log(el.textContent); // DOM 已更新
```

可以这样表达：

```text
Vue 的 nextTick 用来等待本轮数据更新对应的 DOM 刷新完成。
它和事件循环有关，因为 DOM 更新不是每次状态变化都同步立即完成。
```

不要把 `nextTick` 简单理解成 `setTimeout`。它更接近“等当前批量更新和微任务时机完成后再执行”。

---

## 和 React 状态更新的关系

React 里调用 `setState` 或 `setXxx` 后，也不要立刻假设下一行代码能拿到最新渲染结果。

原因是 React 会对状态更新做调度和批处理。

可以这样表达：

```text
事件循环解释的是 JS 异步任务的调度顺序。
React 的状态更新还有框架自己的调度机制。
两者不是同一个东西，但都说明了一点：状态变化不等于 DOM 立刻完成更新。
```

## 项目里真正会遇到的问题

### 1. loading 为什么没有显示出来

常见代码：

```js
loading.value = true;
heavyWork();
loading.value = false;
```

如果 `heavyWork` 是很重的同步任务，主线程一直被占用，浏览器没有机会渲染 `loading = true` 的状态。

表现就是：

```text
代码设置了 loading
但页面上看不到 loading
```

解决思路：

```text
把重任务拆分
用 setTimeout 让出一轮渲染机会
使用 requestIdleCallback
使用 Web Worker
后端异步处理
```

### 2. 搜索接口返回顺序错乱

用户连续输入：

```text
a
ab
abc
```

可能 `abc` 的请求先返回，`ab` 的请求后返回。若不处理，旧结果会覆盖新结果。

解决思路：

```text
防抖
请求取消 AbortController
请求序号校验
只接受最后一次请求结果
```

这不是单纯事件循环问题，但和异步回调顺序有关。

### 3. Promise 里大量计算导致页面卡顿

很多人以为放进 Promise 就不会卡页面，这是误区。

```js
Promise.resolve().then(() => {
  // 大量同步计算
});
```

这段代码仍然跑在 JS 主线程里。Promise 只是改变执行时机，不会自动开新线程。

如果计算很重，仍然会阻塞页面。

## 面试追问

### 问：setTimeout(fn, 0) 是不是立即执行？

不是。

`setTimeout(fn, 0)` 的意思是尽快把回调放进宏任务队列，但它要等当前调用栈清空、当前宏任务结束、微任务队列清空之后，才有机会执行。

### 问：Promise 是同步还是异步？

Promise 构造函数里的代码是同步执行的，`then/catch/finally` 回调是异步的，进入微任务队列。

示例：

```js
new Promise((resolve) => {
  console.log('1');
  resolve();
}).then(() => {
  console.log('2');
});

console.log('3');
```

输出：

```text
1
3
2
```

### 问：微任务一定比宏任务先执行吗？

更准确地说：

```text
在同一轮事件循环中，当前宏任务执行结束后，会先清空微任务队列，再执行下一个宏任务。
```

不能脱离“当前这一轮”去说微任务永远比宏任务先执行。

### 问：事件循环只存在浏览器里吗？

不是。Node.js 也有事件循环，但 Node.js 的阶段划分和浏览器不完全一样。

前端面试里优先讲浏览器事件循环；如果面试官追问 Node.js，再补充两者有差异。

---

## 背诵版

可以按这段背：

```text
JavaScript 是单线程执行的，同步代码会先进入调用栈执行。遇到异步任务时，浏览器或运行环境会先接管，等条件满足后把回调放进任务队列。事件循环会在当前宏任务执行完后，先清空微任务队列，再进入下一个宏任务。Promise.then 属于微任务，setTimeout 属于宏任务，所以同一轮中 Promise 回调通常会先于 setTimeout 执行。实际项目里，这个机制可以帮助我们理解异步执行顺序、Vue nextTick、React 状态更新后的读取时机，以及页面卡顿和渲染阻塞问题。
```
