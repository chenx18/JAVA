# 内存泄漏排查

> 专题：工程化与性能优化  
> 编号：E18

### 一句话答案

内存泄漏是对象不再需要但仍然可达，常见原因是定时器、事件监听、订阅、闭包、缓存和长连接未清理。

### 常见来源

```text
setInterval 未清理
事件监听未解绑
WebSocket / SSE 未关闭
闭包引用大对象
全局缓存无限增长
DOM 引用未释放
```

### 项目里怎么用

- 组件卸载清理副作用。
- 路由切换关闭流式连接。
- 限制缓存大小。
- 使用 Memory 面板快照对比。

### 常见坑

- 只在正常关闭路径清理，异常路径没清。
- keep-alive 页面缓存过多。
- AI 流式请求停止后连接没断。

### 面试表达

内存泄漏排查要看对象为什么还可达。前端项目里最常见的是组件卸载后定时器、监听器、订阅或长连接还在。AI 流式场景尤其要清理 SSE/fetch 连接。
