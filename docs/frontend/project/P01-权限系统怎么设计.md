# 权限系统怎么设计

> 专题：项目表达与综合实战  
> 编号：P01

### 一句话答案

权限系统通常由后端控制真实权限，前端负责路由、菜单、按钮和交互展示，不能只靠前端判断。

### 核心原理

常见模型：

```text
用户 User
角色 Role
权限 Permission
菜单 Menu
按钮 Action
```

前端常做：

```text
登录后获取用户信息和权限
生成动态路由
渲染菜单
控制按钮显示
请求拦截处理 401 / 403
```

### 项目里怎么用

- 后台管理系统按角色展示菜单。
- 按按钮权限控制新增、编辑、删除。
- 接口返回 403 时统一提示无权限。

### 常见坑

- 只隐藏按钮，接口不鉴权。
- 前端写死路由权限，后端配置变更后不同步。
- 刷新页面后权限状态丢失。

### 面试表达

我会强调前端权限只负责体验，安全必须由后端保证。前端拿到权限后生成路由和菜单，同时做按钮级展示控制。接口层如果返回 401 或 403，会在拦截器里统一处理。
